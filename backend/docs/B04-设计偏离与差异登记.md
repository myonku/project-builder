# 设计偏离与差异登记

## 1. 文档定位

本文档登记**本实现的设计约定、有意偏离与相对设计基线的加强项**。

区分三类内容：

1. **设计约定**：结构或行为上的固定选择，改动前必须先改本文档。
2. **有意偏离**：刻意与常见做法（或与最朴素的实现）不同，且给出理由。偏离必须在此登记，不得默默发生。
3. **加强项**：比设计基线更严格的要求（例如"未知字段一律拒绝"），客户端需要遵守。

本仓库是**文档与代码的唯一主线**：不再有需要回查的外部基准仓库，
本文档也不承担"文件级映射"的职责。历史教训的来源统一记为"早期实现"
（见《B01-Go服务端架构设计.md》第 5 节）。

## 2. 结构与命名约定

| 约定 | 内容 | 理由 |
| --- | --- | --- |
| 应用装配 | `cmd/api/main.go` 显式装配，`internal/httpapi/router.go` 独立构造路由 | 消除模块级副作用；测试可以直接构造路由，不必启动进程 |
| 配置 | `internal/config/config.go`：默认值 → TOML → 环境变量 → 显式覆盖，启动时快速失败 | 配置错误必须在启动时暴露，而不是在第一次请求时 |
| 迁移 | `internal/database/migrations/*.sql`，`go:embed` + golang-migrate，单一 head | 迁移随二进制走，不需要额外部署迁移工具；head 必须唯一 |
| 测试 | 与被测包同目录的 `*_test.go`；集成测试装配集中在 `internal/testsupport/` | Go 惯例；集成装配集中一处，避免每个用例各写一套 |
| 文档 | `docs/S01`–`backend/docs/B05` 共七份：需求 / 架构 / 数据 / 配置 / 契约 / 本文件 / 进度与验证 | 编号稳定，交叉引用不出仓库 |

## 6. 有意偏离汇总（必须保留）

| # | 偏离 | 理由 | 防回归措施 |
| --- | --- | --- | --- |
| 1 | 删除 `struct/`、`factory/`、Repository Protocol、ORM 模型 | 这些间接层从未被真正替换，只增加穿透成本 | 《B01-Go服务端架构设计.md》4.4 与本文档 §6 登记 |
| 2 | 用显式 SQL + `RETURNING` 替代 ORM | 消除"更新后访问过期属性触发隐式 IO"这一 早期实现最严重缺陷 | `TestUpdatedAtMustBeAdvancedExplicitly` + Auth 集成测试 |
| 3 | 错误映射改为单张显式表 | 早期实现只注册 500，其余错误全部退化 | `TestErrorCodesAllHaveStatusAndMessage`、`TestEveryDomainErrorConstantIsMapped` |
| 4 | 请求体未知字段返回 422 | 早期实现静默忽略，导致版本协议静默降级 | `TestUnknownFieldIsRejected` |
| 5 | 生产环境拒绝通配 CORS 与开发占位密钥 | 修复 早期实现的凭据型 CORS 缺陷 | `TestLoadRejectsProductionUnsafeDefaults` |
| 6 | 会话网关只挂在版本化路由组上 | 挂全局会把 404/405 误报为 401 | `TestNoRouteReturnsErrorEnvelope`、`TestNoMethodReturnsErrorEnvelope` |
| 7 | panic 恢复直接写信封 | `ErrorHandler` 的 defer 在 panic 展开时已执行完，必须由 Recovery 补信封 | `TestRecoveryMiddlewareConvertsPanicToEnvelope` |
| 8 | 用户名/邮箱不区分大小写唯一 | 并发注册同一账号需要数据库兜底 | `TestUserIdentityIsCaseInsensitiveInDatabase`、并发注册集成测试 |
| 9 | Redis 可禁用且不影响启动 | 早期实现关闭 Redis 时全站 500 | `TestLoginFailsWhenSessionBackendUnavailable` |
| 10 | 集成测试为常规测试一部分 | 早期实现 45 个 fake 测试未发现真实缺陷 | 见《B05-进度与验证记录.md》验证矩阵 |
| 11 | 集成测试串行化（咨询锁 + 禁 `t.Parallel()`） | 共享物理数据库，并发会互相清空数据 | `internal/testsupport` 的 `sharedState` 与 `TestMain` |
| 12 | 迁移日志打印脱敏目标库 | 避免"迁移到了错误的库"这类难以察觉的事故 | `RedactedDSN()` + `TestRedactedDSNNeverContainsPassword` |
| 13 | 资料更新除 `expected_updated_at` 外还必须**至少提供一个可改字段**，否则 422 | 一次没有任何变更的请求同样会推进 `updated_at`，让其他客户端手里的版本无谓失效，使"版本变了"不再等于"数据变了" | `TestUserProfileUpdateHasChanges`（单测）、`TestUserProfileUpdateRejectsEmptyAndInvalidPayload` |
| 14 | 系统必须**至少保留一个启用中的管理员**：降级或停用最后一个管理员返回 409 | 管理员是唯一能停用用户、改系统角色与处理全局异常的入口。允许清零会让系统永久失去管理能力，且没有任何接口可恢复，只能直接改数据库 | `TestWouldRemoveLastAdmin`、`TestLastActiveAdminCannotBeDemotedOrDisabled`、`TestAdminGuardTakesRowLocksOnAllActiveAdmins`、`TestAdminGuardSerializesConcurrentDemotions` |
| 15 | `POST /users/{id}/disable` 对已停用用户返回 409，而不是成功的空操作 | 同 13：不让无变更请求推进版本，也不让"停用成功"掩盖"本来就已经停用" | `TestDisableUserKeepsRowAndInvalidatesExistingSession` |
| 16 | "今天"按请求者 `timezone` 计算，而不是服务器 UTC 日历日或固定 UTC+8 | 需求文档 5.7 要求底层统一 UTC、上层按用户时区计算业务日期。固定时区会让不在该时区的成员看到错误的逾期标记与逾期计数 | `TestTodayFollowsRequesterTimezone`、`TestUserTimezoneChangeTakesEffectImmediately`、`TestInvalidTimezoneDoesNotBreakReadPaths`、`TestToday`（`domain.Today`） |
| 17 | 创建用户的端点不接受 `system_role`，新账号固定为 `member` | 允许在创建时直接指定管理员就绕过了"系统至少保留一个启用中管理员"的判定，也不会留下一次显式的角色变更记录 | `TestAdminCreateUserEqualsSelfRegistration` |
| 18 | 管理员代建账号复用注册用例（`users.Accounts` 由装配点注入 `*auth.Service`），不复制注册流程 | 两份实现迟早会在密码强度、归一化与唯一性检查上分叉，而这三项都属于安全边界 | `TestAdminCreateUserEqualsSelfRegistration`、`TestPasswordRuleIsSharedBetweenRegistrationAndReset` |
| 19 | 用户列表的 `total` 与列表条目必须来自同一套筛选（`ListFilter.where()` 单点生成） | 第二阶段实测"计数漏掉列表筛选"会让 `pagination.total` 与实际条目数不符，接口看着正常但翻页结果错 | `TestUserListRequiresAdminAndHonoursIncludeDisabled` |
| 20 | 首个管理员改为**配置驱动、启动时初始化**，不提供"自我提升为管理员"的端点 | 本系统面向内部小组，普通用户不需要管理员角色，因此没有分发需求；开放一个自我提升的端点等于把权限提升暴露在 HTTP 面上。初始化保持幂等且**绝不覆盖既有账号的密码**，否则每次重启都会把管理员改过的密码打回配置里的初始值 | `TestEnsureAdministratorPromotesExistingAccountWithoutTouchingPassword`、`TestEnsureAdministratorIsIdempotent`、`TestBootstrapAdministratorUnlocksAdminEndpoints` |
| 21 | 引导管理员配置要求**整组配置或整组留空**，部分配置导致启动失败 | 只配用户名会让一次本该创建管理员的初始化静默地什么都不做，而操作者以为已经录入完毕 | `TestLoadRejectsInvalidValues`（引导管理员三条） |
| 22 | 计划视图的逐对象权限收敛放在**领域层**而不是 SQL；SQL 只做视图范围与机械筛选 | 权限规则出现两份 SQL 实现时必然分叉，而"多看到一条不该看的数据"不会有任何报错 | `TestGroupPlanViewOnlyExposesSharedContent`、`TestGanttViewHidesUnsharedTasksFromGroupVisitors` |
| 23 | 计划视图**未知查询参数一律拒绝**，并用 `project_*` / `task_*` 前缀消歧 | 拼错参数名会被静默忽略，客户端以为筛选生效却拿到全量数据 | `TestPlanViewFiltersAndValidation` |
| 24 | 组内视图的 `progress` 基于**该视图可见任务**，与项目详情的口径不同 | 组内访客看不到未共享任务，按全部任务计算会用进度数值泄漏它们的存在与进展 | `TestGroupPlanViewOnlyExposesSharedContent`、§4.7 实测行为要点 |
| 25 | 计划视图不分页，数组完整返回 | 甘特图必须一次拿到全部条目；分页会让"计划"变成"计划的第一页"，而静默截断更糟。规模增长时应改契约而不是悄悄截断 | §4.7 共同约定 |
| 26 | 持有者转移：`role: owner` = 同事务内先降现任、再升目标；拒绝降级唯一持有者 | 修复"持有者永远无法变更"这一不可用状态。单条 SQL 无法同时满足"至多一个"（部分唯一索引）与"至少一个"（不允许出现无人可管理的中间态），因此必须显式事务 + 固定顺序 | `TestProjectMemberInvariants`（含"转移给非成员必须整体回滚"）、`TestTaskMemberMustBeProjectMember`、`TestOwnershipTransferConcurrencyKeepsExactlyOneOwner` |
| 27 | **系统管理员对所有工作组/项目/任务放行**（需求文档 4.1）；放行只豁免权限判定，不豁免状态规则与领域不变式 | 管理员是异常情况下的兜底：持有者离职或被停用后，转移所有权是唯一的补救路径。放行若无边界，管理员就成了可以绕过归档只读与唯一持有者的后门 | `TestAdminCanReachDataWithoutMembership`、`TestAdminBypassDoesNotBreakInvariants`、`TestCanManageGroupMembers`、`TestCanUpdateGroupAllowsSystemAdmin` |
| 28 | 工作组的 `owner_id` 用组更新接口转移，并同事务改写 `group_members` 的 manager 行 | `owner_id` 是组自身的治理属性而非成员角色（backend/docs/B02 §3.2.1）；两处表示分开写会静默不一致，而"所有者但没有 manager 行"会让所有者看不到自己也管不了组 | `TestGroupOwnershipTransfer`、`TestAdminCanTransferOwnership` |
| 29 | 附件**没有独立权限**，完全继承项目/任务；逻辑删除后只对上传者、容器持有者与系统管理员可见 | 另立一套附件权限会立刻与项目/任务权限分叉；"删除即对所有人隐藏"会让上传者自己都收拾不了传错的文件 | `TestAttachmentSoftDeleteVisibility`、`TestCanViewDeletedAttachment` |
| 30 | 彻底删除必须**先逻辑删除**，且**先删对象再删行** | 前者避免误操作不可逆地销毁文件；后者因为"对象没了行还在"可修复，"行没了对象还在"不可见且永远占着磁盘 | `TestAttachmentSoftDeleteVisibility`（含"彻底删除后行与字节都消失"） |
| 31 | 配额按上传者统计并**计入已逻辑删除的附件** | 已删除附件仍占磁盘；不计入则可用"上传 + 逻辑删除"绕过配额 | `TestAttachmentQuota` |
| 32 | 存储层被压到"按 key 做 CRUD"四个方法，不含业务语义；`stored_key` 由服务端生成，绝不由用户文件名派生 | 初版只用本地文件系统，但文件是真实数据里最难迁移的部分；key 派生自用户输入则恶意文件名会影响磁盘布局（含目录穿越） | `TestLocalRejectsEscapingKeys`、`TestNormalizeAttachmentName` |
| 33 | 提醒的幂等靠 `dedupe_key` 唯一约束（键含时间窗口），生成侧 `ON CONFLICT DO NOTHING`；不用内存去重或"先查后插" | 周期扫描必然重复运行；键不含窗口则改了到期日后再也收不到提醒，而系统看起来一切正常。"先查后插"在并发下会双写 | `TestReminderOverdueLifecycle`、`TestReminderDedupeKeyIncludesWindow` |
| 34 | `skipped` 与 `failed` 严格分开；邮件未启用记 `skipped` | `failed` 的语义是"需要人排查"；把配置状态混进去会让失败列表永远噪声不断 | `TestReminderMailDisabledIsSkippedNotFailed`、冒烟实测 |
| 35 | 提醒发送前**重新判定**收件人与任务适用性 | 生成与发送之间可能隔很久：收件人可能已停用/关闭提醒，任务可能已完成 | `TestReminderSkipsIneligibleRecipients` |
| 36 | 时间只有一个来源：一切"现在"的判断走注入时钟 | 混用注入时钟与 `time.Now()` 会让"刚创建的会话立刻过期"，并让测试结果取决于运行时刻（实测 87 个用例在某墙钟时刻后必然失败） | `TestSessionTTLMatchesConfiguration`、`TestReminderDueSoonFollowsBusinessDays` |
| 37 | 限流是**全局中间件**、按**连接的来源地址**分桶、**不信任 `X-Forwarded-For`**、单实例内存态 | 按会话限流在登录前失效（口令尝试正是要挡的场景）；`X-Forwarded-For` 可被客户端伪造，用它分桶等于换一个头就绕过；单进程部署不需要分布式限流，多一个会失败的依赖不划算。默认额度刻意宽松，避免把正常使用打成 429 | `TestRateLimiterAllowsBurstThenRejects`、`TestRateLimiterRefillsWithInjectedClock`、`TestRateLimiterIsolatesBucketsPerClient`、`TestRateLimiterSweepsStaleBuckets`、`TestRateLimitMiddlewareReturnsUnifiedEnvelope`、`TestRateLimitDoesNotTrustForwardedFor`；另由端到端冒烟证明"限流开启时 182 项断言仍全绿" |
| 38 | 审计**与业务同事务写入**；成员变更记在**容器对象**上；只记录新值、只保留白名单键 | 放在提交后写，失败就只能记日志，留下"业务成功但记录缺失"且无法回滚的空洞；成员行 id 是内部细节，记在容器上才能一次查询答完"这个对象被谁改过"；记录完整前后值会把密码/令牌/邮件正文一类内容带进日志表 | `TestAuditSharesTransactionWithBusiness`（业务回滚 ⇒ 无审计行）、`TestAuditCoversProjectWrites`（六类关键写操作 + 失败的写入不留记录）、`TestSanitizeAuditChangesRedactsSensitiveKeys`（领域单测）、`TestAuditRedactsSensitiveChangesInDatabase`（入库前已脱敏）、`TestAuditEnumWhitelistMatchesDatabaseCheck` |
| 39（W3 已落地） | 引入 MongoDB 9 GridFS 作为附件/头像字节存储，PostgreSQL 仍是唯一业务事实源 | 本地文件系统在扩容/备份/迁移上受限；GridFS 保持 `storage.Store` 四方法不变，`stored_key` 原样沿用。**代价**：多一个外部依赖与备份对象；Mongo 只存字节，不存权限/元数据/审计 | P01 §3；`TestGridFSStoreRoundTrip`、API gridfs 上传/下载、迁移 copy/verify/rollback |
| 40（W3 已落地） | `attachments.storage_backend` 只作为迁移账本，不做读路由 | 若用该列路由读写，会引入混合读并掩盖“对象缺失”；服务只使用当前配置的 Store，账本供 verify/rollback 对账 | P01 §3.5；`cmd/storage-migrate` 实测、迁移 000007 |
| 41（规划） | 密码重置用 `users.session_version` 让旧会话失效，而不是扫描 Redis 删除所有 token | 会话版本在数据库同一事务内推进，跨重启/多实例成立；扫描 Redis 在大规模下不可控，且容易漏掉。旧会话 JSON 无版本字段按 0 处理 | P01 §5.2；旧会话 401、管理员/自助重置测试 |
| 42（W4 已落地） | 头像不复用 `attachments` 表，单独使用 `users` 头像列 + `avatars` bucket | `attachments` 的 CHECK 要求 project_id/task_id 恰有一个非空，头像不属于项目/任务；单独 bucket 便于生命周期与备份；头像不计入附件配额。头像上传/清除只推进 `avatar_updated_at`，不推进 `users.updated_at`（避免资料表单 409） | P01 §4；头像上传/删除/可见性/ETag、`TestAvatarLifecycleAndProjection`、`TestAvatarAuditAndOldObjectCleanup` |
| 43（规划，W5） | 密码重置请求同步发送邮件，接受“存在账号 ~700ms、未知邮箱即时”的计时侧信道 | 初版优先简单与可观测；全局限流 + 请求端点按 IP 桶 + 内部网络降低滥用。彻底消除需异步出站表/worker，复杂度高，留到有实际需求时再评估 | P01 §5.6；后续异步化时补测试 |

## 7. 文档约定

### 7.1 唯一主线

**本仓库是需求、契约、数据模型与代码的唯一权威来源。**
不存在需要回查的外部仓库：任何"另一份实现里是怎么做的"都不再是论据，
需要保留的结论都已写进 `docs/S01`–`backend/docs/B05`。

### 7.2 编号约定

**四套编号各自独立、从 01 起**：`S` = 共用（shared）、`A` = 逐接口详解（API）、`B` = 服务端（backend）、
`F` = 前端（frontend）。正文里写《A09》、《B03》§3.5.1、《A05》§3、《F01》§5.1 即可——
**引用不需要写路径**，因此文档搬家、改名都不会让引用失效。

| --- | --- | --- |

也不写某一端的实现路径）。原因见 `docs/README.md`：两端都会往里加内容，混入单端进度就会互相打架；
推进与证据一律留在各自工程目录内（服务端是 `B05`、前端是 `F05`）。

文档里的路径：跨端引用写**相对仓库根**（`backend/docs/B03-配置与运行.md`、
`docs/S02-HTTP接口契约.md`），服务端文档内部引用自家代码写**模块内相对路径**（`internal/...`）；
Markdown 链接按惯例相对所在文件。

## 8. 变更规则

1. 新增"有意偏离"必须在第 6 节登记，并同时给出防回归测试；未登记的偏离视为缺陷。
2. 每一处偏离都必须能回答"解决了哪个已确认缺陷"或"带来了什么可验证收益"。
3. 不得为"未来可能需要"引入未被使用的抽象层（承接《B01-Go服务端架构设计.md》9.4）。
4. 设计约定发生变化时同步更新本文件，保持"约定 → 理由 → 证据"三列完整。
