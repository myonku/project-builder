## 1. 评估结论与目标

建议采用 **一个统计路由页、两类统计视角、两处页面局部增强**：

1. 将现有“视图”更名为“进度视图”，保留 `/gantt` 地址及项目/成员甘特图能力。
2. 新增 `/statistics`“数据统计”页，提供“组内概况”和“成员分布”两个页签，承担即时汇总与汇报。
3. 概览页增加一块紧凑的任务状态构成；项目详情增加一块任务状态构成及到期提示。

首批复用现有完整计划投影，在前端派生统计，不新增接口、迁移或图表依赖。若后续实测数据规模、快照一致性或历史汇报要求超出现有接口能力，再单独评估只读聚合接口。

本轮要帮助使用者快速回答三个问题：当前工作推进到什么状态、近期哪些任务需要关注、成员之间的任务分布如何。图形用于识别结构和差异，表格与任务详情继续负责核查和操作；不将每个表格改成图表。

### 2.1 实施前需要消除的表述差异

1. `PlanSummaryTiles` 的总体进度提示仍写“任务平均进度，不含已取消任务”；实际 `summary.overall_progress` 是返回项目有效进度的等权平均，排除取消项目。后续应纠正提示，不改变原有计算。
2. A06 前部“汇总与视图范围”及 S01 已明确项目进度读取持久化有效结果，但 A06 后部部分字段说明、计划服务部分注释仍保留“按可见任务计算项目进度”的旧表述。实际服务读取 `record.Progress`。后续按当前业务规则统一这些说明，不据旧文字另造前端算法。
3. “个人计划”是本人作为项目成员所能看到的项目及任务，包含其他成员的任务。概览新图标题应使用“参与项目的任务状态”；只有按 `members.user_id` 过滤后，才能称为“本人承担任务”。

## 4. 统计范围与指标口径

### 4.1 数据集合

新统计使用独立、可测试的派生模型，避免将原 `PlanSummary` 改造成另一套含义。

| 集合 | 定义 |
| --- | --- |
| 基础项目 P | 计划接口按工作组、可选项目及归档开关返回的授权项目集合 |
| 基础任务 T | 同一响应中的可见任务，按 `id` 去重；逻辑删除任务已由接口排除 |
| 可见叶子任务 L | T 中 `has_children === false` 的任务；不能以“当前结果中找不到子任务”推断叶子 |
| 统计任务 F | L 中截止日期符合已应用范围的任务；未设置范围时等于 L |
| 涉及项目 Q | 无截止日期筛选时为 P；有截止日期筛选时，仅保留 F 中任务所属的项目 |
| 成员任务 F(u) | F 中 `members` 含该成员 `user_id` 的任务，按任务 id 去重，包含 owner 角色 |

默认范围为单工作组共享计划，归档关闭、截止日期不限。截止区间含首尾自然日，界面必须称“截止日期范围”，不能称“完成期间”。日期筛选可在完整响应上本地执行，以便项目/成员选项保持完整；初版不向现有接口传入它不认识的新参数。

新图形固定以叶子任务作为任务统计单位，排除父子重复计数。原计划/概览的汇总卡继续显示 A06 原有的全部可见任务条目；应在原卡片处补充“含父任务”的口径提示，新图标题明确标出“叶子任务”，不要求两个总数相等。概览新图不额外冒充个人工作量。

### 4.2 核心指标

| 指标 | 定义和显示规则 |
| --- | --- |
| 涉及项目 | `count(Q)`；截止日期筛选后表示命中任务所属项目数 |
| 叶子任务 | `count(F)`，包含取消任务；用于状态构成的总数 |
| 已完成 | F 中 `status === completed` 的数量；不能用 `progress === 100` 替代 |
| 未完成 | F 中 `status` 为 `not_started` 或 `in_progress` 的数量，不含取消 |
| 逾期 | F 中 `is_overdue === true` 的数量；它是未完成任务的子集，不是第五种状态 |
| 状态构成 | 未开始、进行中、已完成、已取消四段，段数之和必须等于叶子任务总数；取消使用中性色 |
| 完成占比（图内辅助文字） | 已完成 /（叶子任务数 − 已取消）；分母为 0 显示“—”，不显示虚假的 0%/100% |
| 项目进度 | Q 中项目的服务端 `progress`；不在前端按 F 重算，不与完成占比等同 |

项目进度对比旁常驻说明：“项目进度由完整任务层级汇总，截止范围仅决定此处展示哪些项目。”它可能包含不可见下级对父级/项目有效进度的影响，这是现行业务允许展示的聚合结果；不得进一步推算、列出或补取隐藏任务的数量、名称和成员。

取消任务仍占状态构成的一段，但不进入未完成、逾期及到期分布。里程碑如为叶子，作为一条普通统计任务计入，不再额外加一次。显式状态与进度可以不一致，统计以各自字段含义为准，不尝试“修正”业务记录。

### 4.3 成员统计与多人协作

成员分布图以 F 为基础，展示每位成员的未开始/进行中/已完成/已取消堆叠条，右侧显示逾期数量。默认按未完成任务数降序，再按显示名、用户 id 稳定排序；支持按姓名查找并展开全部，不能只展示前 10 人而不提示。

- 同一个任务有多位成员时，对每人各计一次参与；同一人在 `members` 内重复出现时只计一次。成员条形合计可以大于 F 的任务数。
- 图名使用“成员任务分布”，单位为“参与任务数”，不使用“工时”“饱和度”“效率”或绩效排名。当前没有任务工作量、投入工时及成员容量数据。
- 成员维度来自授权响应中的任务成员，默认仅展示在 L 中有任务的成员；日期过滤后可保留零值行。不能据此宣称其他组员“没有工作”。首批不为补齐零任务成员额外抓取成员目录。
- 无成员的可见叶子任务单列“未分配”汇总；owner 为空但仍有 members 的任务不视为未分配。成员已经移出工作组但仍存在于授权任务成员投影时，仍按投影统计，不自行隐藏。
- 组级任务数按 id 去重；成员对比标注“多人任务会分别计入，成员合计不等于组级任务数”。图中“未分配”属于独立汇总入口，不伪造用户 id。

### 4.4 日期与当前状态边界

“未完成任务到期分布”将 F 中未完成任务分入互斥区间：逾期、今天、未来 1–7 天、未来 8–30 天、30 天后。分桶合计等于未完成任务数；逾期沿用接口 `is_overdue`，其他日期按请求者配置时区下的今天比较自然日。无未完成任务时显示空态和原因，不画等高的零柱。

页面展示当前用户时区和最近成功读取时间；自然日仍按 `YYYY-MM-DD` 处理，不以 UTC 零点转换任务日期。跨当地零点、用户修改时区或页面重新获得焦点且已跨日时重读，保证逾期与到期桶不沿用前一天结果。若发现服务端逾期标记与日期桶不一致，先刷新核对，不默默归入错误区间。

这里展示的是**当前状态在截止日期范围内的分布**。现有计划投影没有可靠的完成时间、每日历史进度或历史成员快照，因此本期不提供“本周完成了多少”“环比增长”“历史完成趋势”、燃尽图及按期完成率；不能用 `updated_at` 充当完成时间，也不能由当前 progress 反推历史曲线。

## 5. 各页面的具体改进

### 5.1 数据统计：组内概况

| 图形 | 用途 | 交互和限制 |
| --- | --- | --- |
| 叶子任务状态构成 | 快速看出未开始、推进和完成的比例 | 用单条水平堆叠条，显示数量/占比；点击或键盘选择某状态，展开同口径明细 |
| 未完成任务到期分布 | 区分已经逾期和近期将到期的压力 | 五个固定日期桶；选择后显示该桶任务，不把“近期到期”称为确定风险预测 |
| 项目当前进度对比 | 横向比较当前需要汇报的项目 | 水平进度条及精确百分比，附本次统计的未完成/逾期叶子任务数；默认按这些逾期数降序、截止日期和 id 排序，最多 8 项，提供展开全部 |

项目无可见叶子任务且未设置截止筛选时仍可显示服务端进度，旁注“无可见叶子任务”；不能写成“该项目没有任务”。仅取消任务的项目状态、是否归档继续独立标注，不按进度 0 简化为“未开始”。

### 5.2 数据统计：成员分布

上部展示组内成员任务对比；点击成员进入下部成员详情，显示该成员 F(u) 的状态构成、到期分布、项目数与短任务清单。无选择时提示“选择成员查看详情”，不默认选择任务最多者作为异常结论。

同名成员以用户名辅助区分，内部标识始终使用 `user_id`。成员统计仅反映所选工作组的已共享可见叶子任务，不代表该成员的全部项目、全部任务或工作投入。

### 5.3 概览页局部图形化

在原汇总与待办之间增加一块“参与项目的叶子任务状态”，复用当前 `payload.tasks`，按 §4 的叶子和状态规则生成紧凑堆叠条，显示精确数量。保持原待办任务和项目信息为主要操作区，不再增加第二套项目进度对比。

原账号信息和使用提示可默认收起到页面底部，个人信息入口保持可见。保留原汇总数值与原请求数；修正总体进度提示、补充任务条目口径即可。图块点击在本页展开当前集合明细，避免跳到一个未带筛选的页面造成“点了图却找不到对应任务”。

### 5.4 项目详情局部图形化

在任务表格前增加一块“可见叶子任务概况”：状态堆叠条 + 逾期、未来 7 天内到期的数字提示，不再绘制第二张项目进度仪表。后一个数字含今天，即今天至今天 + 7 天的未完成任务，文案写明“含今天”，逾期独立显示。

使用 `GET /api/v1/plan-views/projects/{project_id}/gantt` 获取该请求者完整可见投影，初次进入最多增加一次数据读取。图块固定反映整个可见项目范围，不随下方任务表格的分页、状态筛选或“包含删除”开关变化，标题旁明确说明。

图块有独立加载和失败状态，失败不阻塞既有项目资料与任务表格。任务、成员、共享及归档变更后需刷新图块，权限丢失时清除其数据。项目资料与统计分别读取，不承诺二者属于同一数据库快照；刷新时展示加载状态，避免新旧结果被误当成同一时点。直接访问归档项目仍允许只读概况。

## 6. 即时汇总、明细与汇报

本阶段提供轻量汇报能力，复用已读取的数据，不建立定时报表系统。

1. **范围可核查。** 页首常驻工作组、项目、截止范围、归档开关、叶子口径、时区及最近成功读取时间。图表显示具体数量；被截取的项目/成员图明确“显示前 N / 共 M”。
2. **明细可追溯。** 图块选择在统计页内部展开精确匹配的任务列表，列表可分页展示，但总数基于完整集合；成员详情按 F(u) 展开。条目沿用 `TaskDetailDrawer`，修改成功后重读并重算全部图形。图形筛选应有“清除选择”。
3. **可复制摘要。** 复制当前成功加载且筛选已应用的数据，生成范围、时间、核心指标、需关注项目/成员和最多 5 条任务的纯文本，长清单明确省略数量；任务附可用的项目/任务详情链接。选中成员时明确输出其姓名和参与口径。
4. **可打印汇报。** 统计页提供打印样式，隐藏导航/操作控件，保留范围、图例、数值、读取时间及截取说明，打印当前已展开内容，支持浏览器打印或另存 PDF；不将虚拟滚动未渲染行误当作完整报告。无数据、失败或刷新中不允许生成一份看似有效的新汇报。
5. **筛选可恢复。** 统计页使用 URL 保存 `tab`、`groupId`、可选 `projectId`、`dueFrom` / `dueTo`、`includeArchived` 及选中 `memberId`。这些是前端页面参数，不原样透传 API；解析时白名单校验，未授权组/项目/成员不能回退显示上一组数据。浏览器前进后退应恢复筛选。

URL 分享的是实时查询条件，不是不可变历史快照；接收者重新按自身权限读取。复制摘要与打印件包含的是当前查看者可见内容，页面给出范围说明，不自动发送邮件或推送给他人。本期不加入 Excel/CSV 导出、报告存档、跨组大屏及订阅发送。

## 7. 数据获取与接口评估

| 场景 | 首批数据来源 | 是否扩展接口 |
| --- | --- | --- |
| 组内概况、成员分布 | `GET /api/v1/plan-views/groups/{group_id}`；复用工作组选项加载机制 | 否；两个页签共享同一完整响应 |
| 概览新图 | 当前 `GET /api/v1/plan-views/personal` 响应 | 否；不增加请求 |
| 项目详情新图 | 现有项目 Gantt GET 的完整可见投影 | 否；独立于分页表格 |
| 图形明细及任务查看 | 本次统计集合 + 现有任务详情接口/抽屉 | 否；不逐任务补查成员来构造图表 |

首批数据量随计划响应规模增长，应在实施阶段记录完整响应大小、网络耗时和前端聚合耗时。默认不自动高频轮询；首次进入、范围变化、手动刷新、写入后及跨日时读取。只改变本地截止范围、成员选择或展开数量不重复请求完整计划。

权限继续由服务端决定：普通成员仅可读有权限组的共享计划，系统管理员按现有规则进入；系统管理员身份也不使组内统计自动纳入私有项目和未共享任务。组/项目选项不是权限依据，404 时清空旧数据并提示范围不可用。现有工作组选项最多读取 100 条，实施时若真实数据触达上限，应使用已有分页能力补齐选项，不能把未列出误报为没有权限。

复用 Hook 时需补齐统计页面的范围隔离：当前 `usePlanView` 开始新请求时仍可能保留旧 payload，统计页面必须把 payload 绑定到请求范围；工作组、项目或归档条件变化后，旧图不能继续挂在新标题下。取消过期请求，并防止旧响应及旧 `projectOptions` 覆盖新范围；刷新失败显示失败状态，不能回填“全为 0”。

### 7.1 何时才扩展接口

首批不预建统计专用端点。若代表性数据下出现以下情况，再启动独立契约设计：

- 完整计划传输量/聚合耗时无法达到阶段 5 的响应目标，需要服务端聚合并分页返回明细。
- 汇报要求严格一致的统计时点，需要服务端同一快照中的统计、明细依据、`as_of` / 有效时区；当前前端“最近成功读取时间”无法保证这一点。
- 明确提出历史趋势、按完成时间汇总、历史成员归属或可复现的历史报表，需要可靠的事件/快照和留存规则。

届时应先修订 S01/S02、补充 A 系列契约，定义权限过滤、叶子口径、多人计数和明细一致性，再实现查询；必要索引通过真实查询计划决定。不能为了视觉展示直接引入缓存、MQ、预聚合表或复用管理员审计接口拼接所有成员历史。

## 8. 前端实现边界与视觉约束

- 一屏优先给出范围、核心数字和两块主要图形，长列表通过展开呈现，不让新增图块挤走原任务操作。

## 10. 验收标准与关键样例

### 10.1 统计正确性

| 样例 | 预期 |
| --- | --- |
| 父任务 A 下有叶子 B/C，C 取消 | 新统计计 2 个叶子，取消 1；父任务 A 不重复加入，项目进度仍来自服务端 |
| 父任务有未共享子任务，当前只看到父任务 | `has_children=true`，不得把父任务当叶子，也不得补查隐藏子任务 |
| 一条叶子有甲、乙两位成员 | 组级计 1；甲、乙各计 1；选中甲的明细只有该任务一次 |
| 全部叶子取消 / 根本无叶子 | 完成占比为“—”，不报错；区分“只有取消任务”和“无可见叶子任务” |
| `completed` 但 progress 非 100，或未完成状态且 progress=100 | 状态构成依 status；进度依服务端值，不互相推导 |
| 日期为昨天、今天、今天+7、+8、+30、+31 | 六个边界进入正确桶，桶合计等于未完成数量；使用请求者时区 |
| 截止筛选命中部分子任务 | F 和 Q 相应缩小；项目有效进度保持不变，未命中的隐藏/父任务不误计 |
| 筛选后 0 条任务 | 明确“当前筛选无结果”；不生成 NaN、假进度或错误全组结论 |
| 分页表格只显示部分任务 | 项目概况仍使用完整可见投影，翻页不改变图形总数 |

### 10.2 权限、交互与汇报

- 同组共享项目、私有项目、共享项目内未共享任务、普通成员/管理员、移出组后的 404 均有覆盖；图表、数字、成员选项、摘要和打印不额外暴露隐藏任务资料。
- 快速 A 组 → B 组、前进后退、过期请求晚返回、刷新失败、未授权 URL 及归档切换时，标题与数据不串组；未成功读取时不显示“0 个任务”作为成功结论。
- 数据统计、概览和项目详情在同一范围下，新图与明细采用同一模型；跨范围的差异有明确说明。
- 任务详情修改、成员变更、取消/恢复、共享变更和归档后正确刷新；旧甘特图日期/进度编辑、版本冲突处理不退化。
- 桌面和 390px、深浅主题、键盘和触屏可查看精确数值并打开明细；打印无图例丢失、截字、导航覆盖或“前 N”冒充全部。
- 摘要/打印记录工作组、项目、截止范围、归档口径、成员口径、时区和成功读取时间；未提供历史完成量、工时或效率等无数据依据的结论。

### 10.3 工程与性能

- 前端完成 `pnpm typecheck`、`pnpm build`，为聚合模型补充有实际业务意义的用例，并进行上述浏览器验收；实际执行结果和覆盖边界单独记录于 §12。
- 性能建议基准：生产构建、桌面浏览器，1,000 条可见任务和 100 位任务成员的代表性夹具；本地派生目标不超过 100ms，数据就绪后图形首轮呈现目标不超过 500ms。此为待验证目标，记录设备、响应大小、实测耗时；超标先定位网络、聚合和渲染成本。
- 首批概览新增 0 次读取；统计两个页签复用同次计划读取；项目详情初次新增最多 1 次 Gantt 读取；不得逐成员/逐任务请求来计算图形。
- 保持本阶段统计模型一次或少量线性遍历，先按任务/项目/成员建立索引，明细分页与展开不反复全量重算。
- 若确实修改后端权限、SQL 或接口，按仓库要求增加真实数据库验证与相应后端回归；否则不将本次前端展示改造扩大为无关后端重构。
