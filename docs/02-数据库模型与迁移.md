# 数据库模型与迁移

## 1. 文档定位

本文档是 Go 版本数据库结构的权威来源，内容由 Python 版本**已在真实 PostgreSQL 16 上验证通过**
的迁移文件逐字提取而来（验证方式：空库执行全部迁移、模型与迁移 autogenerate 零漂移、
约束实际生效测试）。Go 版本的 SQL 迁移应以本文档为准。

## 2. 通用约定

- 所有业务表主键为 `UUID`，使用 **UUIDv7** 生成（时间有序）。
- 所有业务表包含 `id`、`created_at`、`updated_at`。
- 瞬时时间列统一 `TIMESTAMPTZ`，存储 UTC。
- 业务日期列使用 `DATE`（不含时分秒）。
- 表名与字段名使用 `snake_case`，表名复数。
- 枚举值使用稳定英文机器值，并用 `CHECK` 约束保护。
- 需要保留历史的数据使用逻辑删除（`deleted_at`），查询默认排除。

`created_at` / `updated_at` 的数据库默认值与更新语义：

```sql
created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
```

> **重要**：原 Python 实现把 `updated_at` 的更新放在 ORM 层（`onupdate=now()`），
> 数据库没有 `ON UPDATE` 触发器。Go 版本应在每条写语句中显式 `SET updated_at = now()`，
> 或统一加触发器。无论选择哪种，都必须保证 `updated_at` **真实推进**且有测试覆盖，
> 因为客户端的 `expected_updated_at` 版本协议完全依赖它。

## 3. 表结构

### 3.1 `users`

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `id` | UUID | PK |
| `created_at` | TIMESTAMPTZ | NOT NULL, DEFAULT now() |
| `updated_at` | TIMESTAMPTZ | NOT NULL, DEFAULT now() |
| `username` | VARCHAR(64) | NOT NULL, UNIQUE `uq_users_username` |
| `email` | VARCHAR(320) | NOT NULL, UNIQUE `uq_users_email` |
| `display_name` | VARCHAR(128) | NOT NULL |
| `password_hash` | VARCHAR(512) | NOT NULL（Argon2 摘要，永不返回） |
| `status` | VARCHAR(16) | NOT NULL, DEFAULT `'active'`, CHECK `IN ('active','disabled')` |
| `system_role` | VARCHAR(16) | NOT NULL, DEFAULT `'member'`, CHECK `IN ('member','admin')` |
| `timezone` | VARCHAR(64) | NOT NULL, DEFAULT `'UTC'` |
| `reminder_enabled` | BOOLEAN | NOT NULL, DEFAULT `true` |
| `last_login_at` | TIMESTAMPTZ | NULL |

约束名：`pk_users`、`ck_users_user_status`、`ck_users_user_system_role`、
`uq_users_username`、`uq_users_email`。

### 3.2 `groups`

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `id` | UUID | PK |
| `created_at` / `updated_at` | TIMESTAMPTZ | NOT NULL |
| `name` | VARCHAR(160) | NOT NULL |
| `description` | VARCHAR(2000) | NULL |
| `status` | VARCHAR(16) | NOT NULL, DEFAULT `'active'`, CHECK `IN ('active','disabled')` |
| `owner_id` | UUID | NOT NULL, FK → `users.id` ON DELETE RESTRICT |

> **已知差异**：工作组所有者唯一性**没有**数据库约束（`owner_id` 是普通外键），
> 目前仅由应用层保证。Go 版本应明确该差异：要么补充数据库约束，要么在文档与测试中
> 显式声明"唯一所有者仅由应用层保证"。参见《业务规则与权限矩阵》。

### 3.3 `group_members`

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `id` | UUID | PK |
| `created_at` / `updated_at` | TIMESTAMPTZ | NOT NULL |
| `group_id` | UUID | NOT NULL, FK → `groups.id` ON DELETE CASCADE |
| `user_id` | UUID | NOT NULL, FK → `users.id` ON DELETE CASCADE |
| `role` | VARCHAR(16) | NOT NULL, DEFAULT `'member'`, CHECK `IN ('member','manager')` |
| `status` | VARCHAR(16) | NOT NULL, DEFAULT `'active'`, CHECK `IN ('active','removed')` |
| `joined_at` | TIMESTAMPTZ | NOT NULL, DEFAULT now() |

约束：`UNIQUE (group_id, user_id)` 名为 `group_member_identity`。

### 3.4 `group_join_requests`

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `id` | UUID | PK |
| `created_at` / `updated_at` | TIMESTAMPTZ | NOT NULL |
| `group_id` | UUID | NOT NULL, FK → `groups.id` ON DELETE CASCADE |
| `user_id` | UUID | NOT NULL, FK → `users.id` ON DELETE CASCADE |
| `status` | VARCHAR(16) | NOT NULL, DEFAULT `'pending'`, CHECK `IN ('pending','approved','rejected')` |
| `reviewed_by` | UUID | NULL, FK → `users.id` ON DELETE SET NULL |
| `reviewed_at` | TIMESTAMPTZ | NULL |

约束：`UNIQUE (group_id, user_id)` 名为 `group_join_request_identity`。

### 3.5 `projects`

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `id` | UUID | PK |
| `created_at` / `updated_at` | TIMESTAMPTZ | NOT NULL |
| `name` | VARCHAR(200) | NOT NULL |
| `description` | VARCHAR(4000) | NULL |
| `created_by` | UUID | NOT NULL, FK → `users.id` ON DELETE RESTRICT |
| `group_id` | UUID | NOT NULL, FK → `groups.id` ON DELETE RESTRICT（**单值，项目只属于一个组**） |
| `status` | VARCHAR(20) | NOT NULL, DEFAULT `'not_started'`, CHECK `IN ('not_started','in_progress','paused','completed','archived','cancelled')` |
| `visibility` | VARCHAR(20) | NOT NULL, DEFAULT `'private'`, CHECK `IN ('private','group_readonly','group_editable')` |
| `start_date` | DATE | NOT NULL |
| `end_date` | DATE | NOT NULL, CHECK `end_date >= start_date` |
| `color` | VARCHAR(32) | NULL |
| `archived_at` | TIMESTAMPTZ | NULL（注意：必须是**带时区**类型） |

约束名：`ck_projects_project_status`、`ck_projects_project_visibility`、`ck_projects_project_date_range`。

### 3.6 `project_members`

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `id` | UUID | PK |
| `created_at` / `updated_at` | TIMESTAMPTZ | NOT NULL |
| `project_id` | UUID | NOT NULL, FK → `projects.id` ON DELETE CASCADE |
| `user_id` | UUID | NOT NULL, FK → `users.id` ON DELETE RESTRICT |
| `role` | VARCHAR(16) | NOT NULL, DEFAULT `'member'`, CHECK `IN ('owner','member')` |

约束：
- `UNIQUE (project_id, user_id)` 名为 `project_member_identity`
- **部分唯一索引**：`CREATE UNIQUE INDEX project_single_owner ON project_members (project_id) WHERE role = 'owner';`

### 3.7 `tasks`

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `id` | UUID | PK |
| `created_at` / `updated_at` | TIMESTAMPTZ | NOT NULL |
| `project_id` | UUID | NOT NULL, FK → `projects.id` ON DELETE CASCADE |
| `parent_id` | UUID | NULL, FK → `tasks.id` ON DELETE CASCADE（自引用，最多 3 层） |
| `created_by` | UUID | NOT NULL, FK → `users.id` ON DELETE RESTRICT |
| `name` | VARCHAR(200) | NOT NULL |
| `description` | VARCHAR(4000) | NULL |
| `status` | VARCHAR(20) | NOT NULL, DEFAULT `'not_started'`, CHECK `IN ('not_started','in_progress','completed','cancelled')` |
| `progress` | INTEGER | NOT NULL, DEFAULT 0, CHECK `BETWEEN 0 AND 100` |
| `priority` | INTEGER | NOT NULL, DEFAULT 0 |
| `start_date` | DATE | NOT NULL |
| `end_date` | DATE | NOT NULL, CHECK `end_date >= start_date` |
| `is_milestone` | BOOLEAN | NOT NULL, DEFAULT false |
| `is_shared` | BOOLEAN | NOT NULL, DEFAULT false |
| `deleted_at` | TIMESTAMPTZ | NULL（逻辑删除） |

> **注意**：任务状态没有 `overdue`，逾期是派生展示字段（`end_date < today AND status IN ('not_started','in_progress')`），
> 不得作为持久化状态。

### 3.8 `task_members`

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `id` | UUID | PK |
| `created_at` / `updated_at` | TIMESTAMPTZ | NOT NULL |
| `task_id` | UUID | NOT NULL, FK → `tasks.id` ON DELETE CASCADE |
| `user_id` | UUID | NOT NULL, FK → `users.id` ON DELETE RESTRICT |
| `role` | VARCHAR(16) | NOT NULL, DEFAULT `'member'`, CHECK `IN ('owner','member')` |

约束：
- `UNIQUE (task_id, user_id)` 名为 `task_member_identity`
- **部分唯一索引**：`CREATE UNIQUE INDEX task_single_owner ON task_members (task_id) WHERE role = 'owner';`

### 3.9 `idempotency_keys`（本轮新增）

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `id` | UUID | PK |
| `created_at` / `updated_at` | TIMESTAMPTZ | NOT NULL |
| `user_id` | UUID | NOT NULL, FK → `users.id` ON DELETE CASCADE |
| `scope` | VARCHAR(120) | NOT NULL（如 `tasks.copy`） |
| `idempotency_key` | VARCHAR(200) | NOT NULL |
| `result_id` | UUID | NOT NULL（本次操作产生的主体对象 ID） |
| `result_secondary_id` | UUID | NULL（如成员关系 ID） |

约束：
- `UNIQUE (user_id, scope, idempotency_key)` 名为 `idempotency_key_identity`
- 索引 `idempotency_key_scope (user_id, scope)`

## 4. 迁移历史与本轮修正

原 Python 版本的迁移链（已验证可从空库顺序执行，单一 head）：

| 顺序 | revision | 内容 |
| --- | --- | --- |
| 1 | `0001_persistence_base` | 空基线 |
| 2 | `0002_add_users_and_groups` | users, groups, group_members, group_join_requests |
| 3 | `c01c2b55e9dc` | projects, project_members + `project_single_owner` |
| 4 | `0004_archive_timestamp` | `projects.archived_at` 改为带时区 |
| 5 | `12e6268c6fad` | tasks, task_members + `task_single_owner` |
| 6 | `0bce1b486d32` | idempotency_keys（本轮新增） |

Go 版本建议把上述 6 个 revision **合并为一组干净的初始迁移**（001 初始化），
因为 Python 版本的 0001/0004 只是历史演进产物（空基线与类型修正），
新项目从零开始直接按最终形态建表更清晰。生产环境尚未部署，不存在迁移兼容负担。

## 5. Go 迁移文件建议

使用 `golang-migrate` 风格的成对文件：

```text
internal/database/migrations/
├── 000001_init.up.sql
└── 000001_init.down.sql
```

要求：

1. `up` 与 `down` 必须成对且可逆（原 Python 版本的 downgrade 已逐一验证可用）。
2. 迁移内容必须可重复执行、可审查。
3. 部分唯一索引是本项目的核心不变式，必须在初始迁移中就建立。
4. 禁止在生产库手工修改表结构作为常规流程。

### 5.1 初始迁移要点清单

- 建表顺序：`users` → `groups` → `group_members` → `group_join_requests` → `projects` → `project_members` → `tasks` → `task_members` → `idempotency_keys`。
- 外键删除行为必须显式声明（RESTRICT / CASCADE / SET NULL），不得依赖默认值。
- 所有枚举字段必须带 `CHECK`。
- `project_members`、`task_members` 必须建立 `WHERE role = 'owner'` 的部分唯一索引。
- 日期范围约束 `end_date >= start_date` 在 `projects` 与 `tasks` 上都要有。
- 时间列统一 `TIMESTAMPTZ`（原实现曾出现过 `projects.archived_at` 用错类型的修正，注意不要重犯）。

### 5.2 后续模块预留

Users、Plan Views、Attachments、Reminders、Audit 尚未实现。它们的数据对象应在各自阶段
单独新增迁移，不要预埋空表。已确认的规划要点：

- **Attachments**：需归属项目**或**任务（二者其一，不可同时），保存原始文件名、大小、
  MIME、存储标识、上传人、上传时间；存储标识不得使用用户提供的文件名；
  需要与项目/任务的逻辑删除策略明确对应。
- **Reminders**：需保存任务、收件人、提醒类型、计划时间、发送结果、失败原因、重试次数，
  并有去重键（同一任务+收件人+提醒类型+时间窗口不得重复发送）。
- **Audit**：至少保存操作人、时间、对象、动作和关键变更摘要；不得记录密码、令牌、
  完整邮件内容或文件内容。

## 6. 验收要求

1. 空库执行全部迁移后，schema 与本文档一致。
2. 迁移 `down` 可回退，且回退后 `up` 可再次成功。
3. 部分唯一索引在真实数据库上被验证**确实拒绝**第二个 owner。
4. 所有 `CHECK` 约束在真实数据库上被验证确实生效。
5. 逻辑删除的默认过滤在**单查与列表两条路径上行为一致**。
