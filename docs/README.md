## 跨端边界

- 系统面向内部网络。Worklane 品牌改变用户可见展示；Go module、包名、数据库名与 Cookie 等技术标识保留现有值。登录/注册页使用 W 图标与 Worklane 字标；WILT 位图是历史备用资产。
- PostgreSQL 保存业务元数据、权限及汇总结果；Redis 管会话/限流；local 或 MongoDB GridFS 存附件和头像字节。local 为默认，切换存储前须停写迁移及校验，不常驻双读/双写，回退先反向复制。
- 层级汇总、全取消分支、删除父任务和手工/自动切换以 S01 §5.4.1 为准；字段和写入边界以 A04/A05 为准。完整任务树参与聚合，视图筛选不改变父级/项目结果；隐藏任务资料仍受原权限限制。
- 归档为独立管理操作，所有普通内容只读。持有者/系统管理员可通过单独的解除归档操作恢复；接口复用 A04 的 PATCH，不新增路由。
- 头像仅 PNG/JPEG，与附件配额独立；前端原图限 10 MiB，裁剪/旋转后保存 512×512 PNG，保存接口仍限 2 MiB。版本和缓存规则见 A02。
- 密码重置使用邮箱单次链接；令牌、次数/冷却及会话失效规则见 A01/A02。当前同步 SMTP 是内部网络 MVP 取舍，异步发送未交付。
- 工作组目录仅提供启用组基本信息和本人状态；详情、成员和组内计划继续鉴权。本人申请每组保留一条最新记录，重新申请更新原记录；停用组的既有申请仍保留。
- 附件继承项目/任务权限；本人管理页不扩权。逻辑删除保留字节和配额，彻底删除需先逻辑删除并确认；常见格式预览仅在浏览器本地解析。

## 发布和验收

业务/接口变更按“需求和契约 → 实现 → 验收 → 提交”推进。涉及权限或 SQL 的行为用真实数据库验证；前端执行类型检查、生产构建和相应浏览器验收。生产发布按 B03，工程验收不表示已经发布。

层级汇总发布顺序为：备份并停写 → 应用迁移 000010 → 更新后端 → 发布完整前端 dist → 刷新页面并验收。回退会恢复既有对象的旧状态/进度，必须先备份；详见 B02/B03。测试环境不得指向生产数据库。

## 可选增强

甘特图拖拽改期/更多筛选、邮件异步发送/出站表未排期。任务恢复 HTTP 入口未新增，存储层恢复会重新参与汇总。已交付的层级汇总、头像、附件预览与工作组申请不再列为待办。

## 文档维护

S01 定义业务范围；S02 定义跨端协议；A 文档定义字段与端点。B/F 分别保存各端设计、运行、取舍和证据，编号独立。共用规范不混入单端推进过程，按日期的证据归 B05/F05；历史结论不能替代当前规范。

Markdown 链接相对所在文件；正文代码路径相对仓库根。新增接口先更新 S02 和相应 A 文档，再改代码；设计取舍同步登记 B04/F04。B05/F05 的历史记录保留日期及当时输出，不为清理旧数字而改写旧验收结果。
