# 共用文档（前后端）

本目录放**前后端共用**的文档；各端专属的文档放在各自的工程目录下：

| 位置 | 文档 | 编号 | 归属 |
| --- | --- | --- | --- |
| `docs/`（本目录） | 需求文档、HTTP 接口契约 | `S01`、`S02` | 前后端共用（需求方也要读 S01） |
| `docs/api/`（本目录） | 逐接口详解（按域拆分为 `A01`…`A10`） | `A01`–`A10` | 前后端共用，**前端为主** |
| `backend/docs/` | 架构设计、数据模型、配置与运行、偏离登记、进度与验证 | `B01`–`B05` | Go 服务端 |
| `frontend/docs/` | 架构设计、数据对象模型、运行与联调、偏离登记、进度与验证（**接续指南见 `F05` §7.4**） | `F01`–`F05` | 前端 |

仓库级总览见 [../README.md](../README.md)；服务端入口见 [../backend/README.md](../backend/README.md)；
前端入口见 [../frontend/README.md](../frontend/README.md)；接口详解入口见 [api/README.md](api/README.md)。

## 四套编号互不冲突

`S` = shared（共用）、`A` = API（逐接口详解）、`B` = backend（服务端）、`F` = frontend（前端）。
各套**从 01 起独立编号**，因此：

- 引用写成《S02》§2.4、《B03》§3.5.1、《A05》§3、《F01》§5.1 即可，**不需要写路径**；
- 文档搬家或改名都只影响链接，不影响正文引用；
- 前端新增 `F0x` 不会与服务端编号撞号。

## 为什么这样拆

- **S01 与 S02 是接口两侧的共同前提**：需求定义"做什么"，契约定义"怎么对接"，接口详解（`A`）定义"字段长什么样"。
- **S02 只写约定**（信封、分页、并发与幂等、限流、错误码、校验顺序），**不写每个接口的请求/响应体**；
  具体结构在 `docs/api/`，这样契约不会随接口数量膨胀，前端也能按域查阅。
- **B01–B05 是服务端的实现与过程记录**（分层、表结构、配置、偏离登记、验证证据），
  **F01–F05 是前端的实现与过程记录**（架构、类型映射、运行联调、偏离登记、验证证据）。
  改动它们不影响另一端，因此各自放在本端工程目录下与该端代码同处一地。

## 共用文档不写"某一端的推进过程"

这是硬约束：共用文档里**不出现**"第几阶段""已完成/未实现""下一步做 X"这类叙述，
也不写某一端的实现路径与文件布局。原因是两端都会往里加内容——
一旦混入单端的推进记录，两边各写一笔就会互相打架。

- 推进过程、实现取舍、验证证据 → 服务端在 `backend/docs/B05`（取舍在 `B04`），
  前端在 `frontend/docs/F05`（取舍在 `F04`）。
- 共用文档只回答两个问题：**业务要什么**（S01）、**接口怎么调**（S02 + `docs/api/`）。

## 约定

1. **文档是权威来源**：代码与文档冲突时先修文档，再改代码。
2. **改接口的顺序**：先改 `S02`（约定/错误码/校验顺序），再改 `docs/api/` 里对应域的字段结构，
   最后改代码；实现侧的取舍按端登记到 `backend/docs/B04`（服务端）或 `frontend/docs/F04`（前端）。
3. **路径写法**：跨端引用写**相对仓库根**（`backend/docs/B03-配置与运行.md`、`docs/S02-HTTP接口契约.md`、
   `frontend/src/api/client.ts`）；各端文档内部引用自家代码时用**模块内相对路径**（服务端的 `internal/app/audit/`、
   前端的 `src/api/client.ts`）。Markdown 链接按惯例相对所在文件。
4. **引用用编号**：正文引用其它文档时优先写《编号》§小节，例如《S01》§4.1、《A09》、《A03》§2、《F01》§5.1。
5. 编号与各自的更新时机另有细则，见
   [../backend/docs/B04-设计偏离与差异登记.md](../backend/docs/B04-设计偏离与差异登记.md) 第 7 节与
   [../frontend/docs/F04-设计偏离与差异登记.md](../frontend/docs/F04-设计偏离与差异登记.md) 第 6 节。
