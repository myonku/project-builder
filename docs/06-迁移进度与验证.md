# 迁移进度与验证

## 1. 文档定位

本文档记录 Go 重写的**阶段状态**、**验证方法与可复现证据**、**契约覆盖矩阵**与**剩余工作**。
它是 Python 版本 `backend/服务端推进计划.md` 的对应物，但采用更严格的完工判定：
**只有真实依赖上的验证结果才构成交付依据。**

### 5.5 第二阶段开发中修掉的缺陷（均由测试发现）

记录在此以说明"集成测试是常规测试"的实际价值——这些缺陷全部通过真实依赖用例暴露，
没有一条是靠人工审查或单元测试发现的：

| # | 缺陷 | 表现 | 发现者 |
| --- | --- | --- | --- |
| 1 | `RETURNING` 复用了带表别名的列清单 | 创建工作组报 500（`missing FROM-clause entry for table "g"`） | 集成测试 |
| 2 | 次级排序键写成裸 `id` | 列表报 500（`ORDER BY "id" is ambiguous`） | 集成测试 |
| 3 | 存在性查询传入空 UUID | 版本冲突判断报 500（`invalid input syntax for type uuid: ""`） | 集成测试 |
| 4 | `updated_at` 只渲染到秒 | 回传版本立刻被判为冲突，PATCH 永远 409 | 集成测试 |
| 5 | **归一化漏传日期字段** | PATCH 返回 200、`updated_at` 推进，但目标字段**静默未更新** | 集成测试 |
| 6 | `CountTasks` 未复用列表的成员筛选 | `pagination.total` 与实际条目数不符 | 集成测试 |
| 7 | 可见性条件的参数下标错位 | 任务列表恒为空（把 projectID 当成 userID） | 集成测试 |
| 8 | `ListAncestors` 的递归 CTE 引用别名 `t` | 创建子任务报 500（`missing FROM-clause entry for table "t"`） | 集成测试 |
| 9 | 清理可选文本写成 `''` 而非 `NULL` | 详情返回 `""` 而不是 `null`，引入第三种状态 | 集成测试 |
| 10 | 创建响应未补 `membership_role` | 创建者看不到自己在对象中的角色 | 冒烟脚本 |

第 5 条最危险：没有错误码、没有 5xx，只有一个字段没生效，人工验证极易漏过。
为此在 projects 与 tasks 的更新路径上加了 `assertNotDropped` 断言，
让"归一化丢弃已提供字段"这类缺陷在开发期就 panic。

### 6.3 不满足即不交付的红线（承接到后续阶段）

以下条件必须持续成立，任何阶段都不得突破：

1. 不得用空路由或仅返回成功的占位实现冒充"已实现"。
2. 不得以"单元测试通过"作为交付依据；涉及 SQL 或约束的改动必须有真实数据库验证。
3. 不得在 handler 中复制权限规则或拼接 SQL。
4. 不得向客户端泄漏堆栈、SQL、物理路径或敏感值。
5. 不得引入未被使用的抽象层。
6. 归一化/校验函数接收"部分字段"结构体时，必须断言已提供的字段没有被静默丢弃
   （见 5.5 第 5 条）。
