# 迁移映射与差异

## 1. 文档定位

本文档记录 Python/lihil 版本 → Go/Gin 版本的**文件级映射**与**有意偏离**。

区分三类内容：

1. **等价映射**：行为必须一致，重写不得改变语义。
2. **有意偏离**：结构或行为**刻意**不同，且给出理由。偏离必须在此登记，不得默默发生。
3. **已知待补**：Python 版本有、Go 版本尚未实现的内容，登记在《06-迁移进度与验证.md》。

基准仓库：`D:\Projects\py_backend\project-builder`（Python，已从 GitHub 移除）。

## 3. 分层映射

Python 版本有一次请求穿过五层的间接结构：

```text
struct → domain → core → modules/*/repository(Protocol) → infrastructure/database/repositories
```

Go 版本收敛为三个有实际收益的边界：

```text
cmd/api → httpapi → app/* → domain
                ↓       ↓
             platform ←─┘
```

| Python | Go | 类型 | 理由 |
| --- | --- | --- | --- |
| `core/errors.py` | `domain/errors.go` | 有意偏离 | 错误语义属于领域；Go 版本在错误上直接携带错误码 |
| `api/errors.py` | `httpapi/problem.go` | 有意偏离 | 错误→HTTP 映射单点集中，用显式映射表而非"注册求解器" |
| `domain/*.py` | `domain/*.go` | 等价映射 | 保持"纯规则、无 IO、无框架"的边界；Go 版本额外只允许依赖标准库与 `clock.Clock` |
| `core/ids.py` | `platform/idgen/` | 等价映射 | UUIDv7 语义一致；额外提供 UUIDv4 与安全令牌区分 |
| `core/time.py` | `domain/time.go` + `platform/clock/` | 等价映射 | 业务日期规则留在领域，时间源抽象放在 platform |
| `modules/*/service.py` | `app/*/service.go` | 等价映射 | 用例编排、权限、事务语义 |
| `modules/*/repository.py`（Protocol） | **删除** | 有意偏离 | 该 Protocol 从未发生过替换；Go 版本把接口定义在消费方，且只在测试需要替身时定义 |
| `infrastructure/database/repositories/*.py` | `app/*/repo.go` | 有意偏离 | 每个模块一个仓储实现，使用显式 pgx SQL，不再分离 contract 与实现 |
| `infrastructure/database/models/*.py`（SQLAlchemy ORM） | **删除** | 有意偏离 | 不再有 ORM 实体；SQL 是唯一的持久化表达 |
| `struct/api/*.py`、`struct/repositories/*.py` | 各模块 `http.go` / `repo.go` 内的结构与 `domain` 实体 | 有意偏离 | 减少纯数据搬运层；Go 结构体可同时承担传输与持久化出参 |
| `factory/factory.py` | `cmd/api/main.go` 显式装配 | 有意偏离 | 装配点透明，避免反射式 DI |
| `infrastructure/runtime.py` | `platform` + `main.go` 生命周期 | 有意偏离 | Go 无异步生命周期钩子需求；资源用 `defer` 关闭 |
| `api/middlewares/ensure_cookie.py` | `httpapi/session.go` | 等价映射 | 语义一致：只检查 Cookie 存在性；白名单路径一致 |
| `api/tools/cookies.py` | `httpapi/session.go` | 等价映射 | Cookie 属性一致：HttpOnly + SameSite=Lax |

### 4.1 关键行为对照

| 行为 | Python | Go |
| --- | --- | --- |
| 密码摘要 | `argon2-cffi` Argon2id | `golang.org/x/crypto/argon2` Argon2id，PHC 字符串格式与 argon2-cffi 兼容 |

### 4.2 Users 域结构映射（第三阶段）

Python 版本没有把"用户资料"独立成模块，账号能力集中在 `modules/auth`，
资料维护散落在接口层。Go 版本把它独立为 `app/users`，使 `app/auth` 只负责
"谁能成为当前用户"（注册、登录、会话），`app/users` 负责"已登录用户如何查看与维护资料"。
这样 `app/auth` 的职责不再随用户管理需求膨胀。

| Go | 职责 | Python 对应 |
| --- | --- | --- |
| `app/users/http.go` | 六个端点：详情 / 更新 / 停用 / 创建 / 列表 / 重置密码 | 接口层的用户资料端点 |
| `app/users/service.go` | 可见性、修改权限、最后管理员不变式；`Accounts` 接口把账号级操作委托给 auth | 分散在用例层，无集中实现 |
| `app/users/repo.go` | 显式 SQL；资料列清单**不含 `password_hash`** | `modules/*/repository.py` |
| `domain/user.go` | `NormalizeUserProfileUpdate`、`ApplyUserProfileUpdate`、`WouldRemoveLastAdmin`、`NormalizeNewPassword` | `domain/users.py` |
| `auth.Service.CreateAccount` / `ResetPassword`（`app/auth/adapter.go`） | 供装配点注入 `users.Accounts` 的适配入口：代建账号复用注册用例，重置密码复用摘要写入 | 无对应（Python 版本由同一模块直接处理） |
| `users.Service.TimezoneOf` | 按用户时区计算"今天"的唯一来源，由装配点注入 projects 与 planviews | 无对应；需求文档 5.7 记载 Python 版本固定默认 UTC+8 |

`app/users/repo.go` 的列清单**刻意排除** `password_hash`：把摘要列挡在查询之外，
让"密码摘要不出现在用户资料响应里"成为结构性保证，而不是"记得别返回"的纪律要求。
这一点由 `TestUserProfileNeverExposesPasswordHash` 与
`TestUserProfileShapeMatchesAuthMe`（形状漂移守卫）共同锁住。

**账号级操作为什么委托而不是复制**：管理员代建账号与用户自助注册必须逐条一致
（归一化、密码强度、唯一性检查、约束冲突翻译），`password_hash` 的写入语义也应当
只有一个维护者。因此 `app/users` 只声明 `users.Accounts` 这一最小接口，
由装配点注入 `*auth.Service`；两个业务模块之间不产生 import 依赖，
装配点也不需要额外写适配器（方法签名与接口完全一致）。

**首个管理员的初始化入口**：系统**刻意不提供**"把自己变成管理员"的 HTTP 端点，
改为由 `auth.Service.EnsureAdministrator` 在服务启动时按 `security.bootstrap_admin_*`
配置录入一个系统级后台账号（本系统面向内部小组，普通用户不需要管理员角色，
因此不做分发）。该方法是幂等的，且账号已存在时只确保角色、绝不覆盖密码，
所以配置里的一次性密码在账号建好之后即失效。配置语义见
《03-配置与运行.md》3.6.1。

### 4.3 Plan Views 域结构映射（第三阶段）

计划视图是**只读聚合**模块，Python 版本没有对应包（汇总逻辑散在接口层与查询里）。

| Go | 职责 |
| --- | --- |
| `app/planviews/repo.go` | 只读 SQL：视图范围（我的项目 / 本组已共享项目）与机械筛选（状态、优先级、日期区间、成员、持有者） |
| `app/planviews/service.go` | 逐对象权限收敛、派生字段与汇总统计、筛选校验 |
| `app/planviews/http.go` | 三个 GET 端点、查询参数解析与严格校验 |

两条**必须保持**的设计约束：

1. **权限判定不在本模块的 SQL 里**。SQL 只负责视图范围（这是视图定义）与机械筛选；
   逐对象的可见性与可编辑性一律调用 `domain.ProjectPermission` / `domain.TaskPermission`
   ——与 `projects`、`tasks` 模块用的是同一份规则。若在计划视图里再写一套 SQL 可见性谓词，
   "谁能看到什么"就会有两份实现，迟早分叉。
2. **统计与列表同源**。汇总统计由返回给客户端的**同一个切片**算出，
   因此 `summary.task_count` 恒等于 `tasks` 的长度，不存在"两条 SQL 各算一套"的空间。

本模块不依赖 `projects` / `tasks` 包，因此装配点也不需要适配器：
它直接读同一批表，并把原始事实（我在项目中的成员关系、组是否可用、任务是否已共享）
交给领域函数判定。

### 5.1 迁移中新增的内容（Python 版本没有）

以下内容在 Go 版本的初始迁移中**新增**，属于有意加强：

| 新增项 | 内容 | 理由 |
| --- | --- | --- |
| 不区分大小写唯一索引 | `uq_users_username_lower`、`uq_users_email_lower`（基于 `lower()`） | 并发注册同一账号的最终保证。Python 版本只有区分大小写的唯一约束，`Alice` 与 `alice` 可共存 |
| 列表查询索引 | `ix_projects_end_date_id`、`ix_tasks_end_date_id`、`ix_tasks_project_id_deleted_at` 等 | 支撑"排序带 `id` 次级键"与"默认排除逻辑删除"，避免全表扫描 |
| 逻辑删除部分索引 | `ix_tasks_project_id_deleted_at ... WHERE deleted_at IS NULL` | 让单查与列表共用同一条件（对应 Python 版本的逻辑删除过滤不一致缺陷） |

### 5.2 约束命名差异

Python 版本由 Alembic 的命名约定生成 `ck_<table>_<name>`、`fk_<table>_<cols>_<reftable>`、
`pk_<table>` 等名称，且 `0002` 中的约束名未加前缀（如 `user_status`），存在不一致。

Go 版本统一为确定性方案：

- 主键 / 检查 / 外键：`pk_*`、`ck_*`、`fk_*`，语义与 Python 版本相同。
- 唯一约束：沿用 Python 版本的业务名（`group_member_identity`、`project_member_identity`、
  `task_member_identity`、`group_join_request_identity`、`idempotency_key_identity`），
  因为这些名称是业务不变式的标识，已在文档中被引用。
- 部分唯一索引：沿用 `project_single_owner`、`task_single_owner`。

约束名差异**不影响行为**，但影响错误信息与运维排查；`app/auth/repo.go` 中把约束名
映射为领域错误，因此名称变化必须在同一处更新（已内联注释说明）。

## 6. 有意偏离汇总（必须保留）

| # | 偏离 | 理由 | 防回归措施 |
| --- | --- | --- | --- |
| 1 | 删除 `struct/`、`factory/`、Repository Protocol、ORM 模型 | 这些间接层从未被真正替换，只增加穿透成本 | 《01-Go服务端架构设计.md》4.4 与本文档第 3 节登记 |
| 2 | 用显式 SQL + `RETURNING` 替代 ORM | 消除"更新后访问过期属性触发隐式 IO"这一 Python 版本最严重缺陷 | `TestUpdatedAtMustBeAdvancedExplicitly` + Auth 集成测试 |
| 3 | 错误映射改为单张显式表 | Python 版本只注册 500，其余错误全部退化 | `TestErrorCodesAllHaveStatusAndMessage`、`TestEveryDomainErrorConstantIsMapped` |
| 4 | 请求体未知字段返回 422 | Python 版本静默忽略，导致版本协议静默降级 | `TestUnknownFieldIsRejected` |
| 5 | 生产环境拒绝通配 CORS 与开发占位密钥 | 修复 Python 版本的凭据型 CORS 缺陷 | `TestLoadRejectsProductionUnsafeDefaults` |
| 6 | 会话网关只挂在版本化路由组上 | 挂全局会把 404/405 误报为 401 | `TestNoRouteReturnsErrorEnvelope`、`TestNoMethodReturnsErrorEnvelope` |
| 7 | panic 恢复直接写信封 | `ErrorHandler` 的 defer 在 panic 展开时已执行完，必须由 Recovery 补信封 | `TestRecoveryMiddlewareConvertsPanicToEnvelope` |
| 8 | 用户名/邮箱不区分大小写唯一 | 并发注册同一账号需要数据库兜底 | `TestUserIdentityIsCaseInsensitiveInDatabase`、并发注册集成测试 |
| 9 | Redis 可禁用且不影响启动 | Python 版本关闭 Redis 时全站 500 | `TestLoginFailsWhenSessionBackendUnavailable` |
| 10 | 集成测试为常规测试一部分 | Python 版本 45 个 fake 测试未发现真实缺陷 | 见《06-迁移进度与验证.md》验证矩阵 |
| 11 | 集成测试串行化（咨询锁 + 禁 `t.Parallel()`） | 共享物理数据库，并发会互相清空数据 | `internal/testsupport` 的 `sharedState` 与 `TestMain` |
| 12 | 迁移日志打印脱敏目标库 | 避免"迁移到了错误的库"这类难以察觉的事故 | `RedactedDSN()` + `TestRedactedDSNNeverContainsPassword` |
| 13 | 资料更新除 `expected_updated_at` 外还必须**至少提供一个可改字段**，否则 422 | 一次没有任何变更的请求同样会推进 `updated_at`，让其他客户端手里的版本无谓失效，使"版本变了"不再等于"数据变了" | `TestUserProfileUpdateHasChanges`（单测）、`TestUserProfileUpdateRejectsEmptyAndInvalidPayload` |
| 14 | 系统必须**至少保留一个启用中的管理员**：降级或停用最后一个管理员返回 409 | 管理员是唯一能停用用户、改系统角色与处理全局异常的入口。允许清零会让系统永久失去管理能力，且没有任何接口可恢复，只能直接改数据库 | `TestWouldRemoveLastAdmin`、`TestLastActiveAdminCannotBeDemotedOrDisabled`、`TestAdminGuardTakesRowLocksOnAllActiveAdmins`、`TestAdminGuardSerializesConcurrentDemotions` |
| 15 | `POST /users/{id}/disable` 对已停用用户返回 409，而不是成功的空操作 | 同 13：不让无变更请求推进版本，也不让"停用成功"掩盖"本来就已经停用" | `TestDisableUserKeepsRowAndInvalidatesExistingSession` |
| 16 | "今天"按请求者 `timezone` 计算，而不是服务器 UTC 日历日或固定 UTC+8 | 需求文档 5.7 要求底层统一 UTC、上层按用户时区计算业务日期。固定时区会让不在该时区的成员看到错误的逾期标记与逾期计数 | `TestTodayFollowsRequesterTimezone`、`TestUserTimezoneChangeTakesEffectImmediately`、`TestInvalidTimezoneDoesNotBreakReadPaths`、`TestToday`（`domain.Today`） |
| 17 | 创建用户的端点不接受 `system_role`，新账号固定为 `member` | 允许在创建时直接指定管理员就绕过了"系统至少保留一个启用中管理员"的判定，也不会留下一次显式的角色变更记录 | `TestAdminCreateUserEqualsSelfRegistration` |
| 18 | 管理员代建账号复用注册用例（`users.Accounts` 由装配点注入 `*auth.Service`），不复制注册流程 | 两份实现迟早会在密码强度、归一化与唯一性检查上分叉，而这三项都属于安全边界 | `TestAdminCreateUserEqualsSelfRegistration`、`TestPasswordRuleIsSharedBetweenRegistrationAndReset` |
| 19 | 用户列表的 `total` 与列表条目必须来自同一套筛选（`ListFilter.where()` 单点生成） | 第二阶段实测"计数漏掉列表筛选"会让 `pagination.total` 与实际条目数不符，接口看着正常但翻页结果错 | `TestUserListRequiresAdminAndHonoursIncludeDisabled` |
| 20 | 首个管理员改为**配置驱动、启动时初始化**，不提供"自我提升为管理员"的端点 | 本系统面向内部小组，普通用户不需要管理员角色，因此没有分发需求；开放一个自我提升的端点等于把权限提升暴露在 HTTP 面上。初始化保持幂等且**绝不覆盖既有账号的密码**，否则每次重启都会把管理员改过的密码打回配置里的初始值 | `TestEnsureAdministratorPromotesExistingAccountWithoutTouchingPassword`、`TestEnsureAdministratorIsIdempotent`、`TestBootstrapAdministratorUnlocksAdminEndpoints` |
| 21 | 引导管理员配置要求**整组配置或整组留空**，部分配置导致启动失败 | 只配用户名会让一次本该创建管理员的初始化静默地什么都不做，而操作者以为已经录入完毕 | `TestLoadRejectsInvalidValues`（引导管理员三条） |
| 22 | 计划视图的逐对象权限收敛放在**领域层**而不是 SQL；SQL 只做视图范围与机械筛选 | 权限规则出现两份 SQL 实现时必然分叉，而"多看到一条不该看的数据"不会有任何报错 | `TestGroupPlanViewOnlyExposesSharedContent`、`TestGanttViewHidesUnsharedTasksFromGroupVisitors` |
| 23 | 计划视图**未知查询参数一律拒绝**，并用 `project_*` / `task_*` 前缀消歧 | 拼错参数名会被静默忽略，客户端以为筛选生效却拿到全量数据 | `TestPlanViewFiltersAndValidation` |
| 24 | 组内视图的 `progress` 基于**该视图可见任务**，与项目详情的口径不同 | 组内访客看不到未共享任务，按全部任务计算会用进度数值泄漏它们的存在与进展 | `TestGroupPlanViewOnlyExposesSharedContent`、§4.7 实测行为要点 |
| 25 | 计划视图不分页，数组完整返回 | 甘特图必须一次拿到全部条目；分页会让"计划"变成"计划的第一页"，而静默截断更糟。规模增长时应改契约而不是悄悄截断 | §4.7 共同约定 |
| 26 | 持有者转移：`role: owner` = 同事务内先降现任、再升目标；拒绝降级唯一持有者 | 修复"持有者永远无法变更"这一不可用状态。单条 SQL 无法同时满足"至多一个"（部分唯一索引）与"至少一个"（不允许出现无人可管理的中间态），因此必须显式事务 + 固定顺序 | `TestProjectMemberInvariants`（含"转移给非成员必须整体回滚"）、`TestTaskMemberMustBeProjectMember`、`TestOwnershipTransferConcurrencyKeepsExactlyOneOwner` |
| 27 | **系统管理员对所有工作组/项目/任务放行**（需求文档 4.1）；放行只豁免权限判定，不豁免状态规则与领域不变式 | 管理员是异常情况下的兜底：持有者离职或被停用后，转移所有权是唯一的补救路径。放行若无边界，管理员就成了可以绕过归档只读与唯一持有者的后门 | `TestAdminCanReachDataWithoutMembership`、`TestAdminBypassDoesNotBreakInvariants`、`TestCanManageGroupMembers`、`TestCanUpdateGroupAllowsSystemAdmin` |
| 28 | 工作组的 `owner_id` 用组更新接口转移，并同事务改写 `group_members` 的 manager 行 | `owner_id` 是组自身的治理属性而非成员角色（docs/02 §3.2.1）；两处表示分开写会静默不一致，而"所有者但没有 manager 行"会让所有者看不到自己也管不了组 | `TestGroupOwnershipTransfer`、`TestAdminCanTransferOwnership` |
