# 配置与运行

## 1. 文档定位

本文档是运行配置、启动流程和迁移操作的权威来源，承接《01-Go服务端架构设计.md》第 7 节与
Python 版本的《项目计划管理系统-全局基线约定.md》第 7 节。接口行为见《04-HTTP接口契约.md》。

对应实现：`internal/config/config.go`、`cmd/api/main.go`、`cmd/migrate/main.go`。

## 2. 配置优先级

```text
代码默认值  <  config.toml  <  .env 文件  <  进程环境变量
```

- 代码默认值集中在 `internal/config/config.go` 的 `defaultConfig()`，全部可安全落到开发环境。
- `config.toml` 提供本地开发默认值；文件不存在**不算错误**（纯环境变量部署场景）。
- `.env` 用于本地覆盖；文件不存在同样不算错误。
- 进程环境变量优先级最高，用于生产与 CI。

实现要点：

- 空字符串的**进程环境变量**视为"未设置"，不会覆盖 `config.toml` 的值。
  这避免了 CI 中常见的 `DATABASE_HOST=` 把配置清空。
- `.env` 中的空字符串是**有意覆盖**（例如显式清空 `MAIL_PASSWORD`）。
- 新增配置项必须同时在 `envBindings()` 中登记，否则无法通过环境变量覆盖；
  `internal/config/config_test.go` 有唯一性断言防止重复登记。

## 4. 启动校验与快速失败

配置在启动时读取一次，解析、校验后成为不可变对象注入各模块。校验失败**立即退出**，
并输出脱敏后的字段名与原因。

校验覆盖：

- 端口范围、超时与连接池正数性、`min_conns <= max_conns`。
- 必填项非空（`database.name`、`database.user`、`session_secret`、`session_cookie_name`）。
- `password_min_length >= 8`。
- `storage.backend` 必须是 `local`。
- `mail.enabled = true` 时 `mail.host` 必填。
- 枚举与布尔/整数格式合法性。

### 4.1 生产环境附加校验

`APP_ENV=production` 时额外强制：

1. 不得沿用开发占位会话密钥 `dev-only-change-me`。
2. `session_secret` 长度不得少于 32 字符。
3. `cors_allowed_origins` 不得包含 `*`。

第 3 条直接修复 Python 版本的安全缺陷：生产环境使用 `allow_origins=["*"]` 且允许凭据，
在浏览器规范下既是配置错误，也让任意站点可携带用户 Cookie 发起请求。

## 5. 敏感值边界

- `config.toml`、`.env.example`、`docker/config.test.toml` **只包含字段名与占位符**，
  不得写入真实密码、令牌或私钥；`.gitignore` 忽略 `.env`、`.env.local`、`*.local.toml`。
- 启动摘要（`Config.Summary()`）对 `database.password`、`redis.password`、`mail.password`、
  `session_secret` 只输出 `set` 或 `unset`，绝不输出内容。
- 数据库连接串在日志与错误信息中一律使用 `RedactedDSN()`。
- 错误响应绝不包含堆栈、SQL 语句或物理路径；未识别错误统一为 500 `internal_error`，
  内部原因只进日志。

## 6. `updated_at` 语义（迁移相关的重要约定）

数据库 schema **不引入** `ON UPDATE` 触发器。`updated_at` 由应用在每条写语句中显式推进：

```sql
UPDATE projects SET name = $1, updated_at = now() WHERE id = $2 RETURNING updated_at;
```

理由：

1. 显式写出比隐式触发器更易审查，且与 `RETURNING` 一起保证"回读到的就是数据库真实值"。
2. 客户端的 `expected_updated_at` 版本协议完全依赖 `updated_at` 真实推进；
   触发器与 ORM 两种机制混用会让"版本何时变化"变得难以推理。
3. Python 版本把更新放在 ORM 层（`onupdate=now()`），数据库没有触发器，
   且更新后读取该属性会触发隐式同步 IO 并抛异常。

该语义由集成测试 `TestUpdatedAtMustBeAdvancedExplicitly` 锁住：单纯 `UPDATE` 其他列
不会改变 `updated_at`，显式 `SET updated_at = now()` 必须推进。

## 7. 运行

### 7.1 启动 HTTP 服务

```powershell
go run ./cmd/api
# 或
make run
```

启动日志依次输出：配置摘要（脱敏）→ 数据库连接池就绪 → Redis 客户端就绪 → HTTP 服务已启动。

收到 `SIGINT`/`SIGTERM` 后进入优雅关闭：停止接收新请求，等待在途请求完成，
超过 `server.shutdown_timeout_seconds` 后强制结束。

### 7.2 使用测试依赖运行

```powershell
make deps-up            # 启动 PostgreSQL 15432 / Redis 16379 / Mailpit 11025
make migrate-test-up    # 对测试库应用迁移
make run-test-config    # 以测试依赖启动服务
make smoke              # 端到端冒烟检查
```

## 8. 数据库迁移

迁移使用 `golang-migrate` 风格成对 SQL 文件，位于 `internal/database/migrations/`，
通过 `go:embed` 编译进二进制，因此部署物自包含、无需额外挂载迁移目录。

### 8.1 命令

```powershell
go run ./cmd/migrate up                # 应用全部未执行的迁移
go run ./cmd/migrate down              # 回退全部迁移（清空 schema）
go run ./cmd/migrate steps -1          # 相对当前版本后退 1 步
go run ./cmd/migrate version           # 输出当前版本与脏标记
go run ./cmd/migrate force 0           # 人工修复：强制设置版本并清除脏标记
```

`version` 在检测到**脏状态**时返回非零退出码。脏状态意味着上一次迁移中途失败，
必须人工介入，绝不能让 CI 在 schema 不确定的情况下继续跑测试。

### 8.2 目标库选择

```powershell
$env:DATABASE_URL = "postgres://user:pass@host:5432/dbname?sslmode=disable"
go run ./cmd/migrate up
```

迁移命令与 API 服务使用**完全相同的配置加载路径**，因此不会出现"迁移到了 A 库、
服务连的是 B 库"。迁移日志会打印脱敏后的目标库，便于确认。

迁移使用独立的 `database/sql` 连接（`golang-migrate` 需要会话级咨询锁），
不复用 API 服务的 `pgxpool`。

### 8.3 迁移规范

1. `up` 与 `down` 必须成对且可逆，`down` 后可再次成功 `up`。
2. 内容必须可重复执行、可审查；禁止在生产库手工修改表结构作为常规流程。
3. 外键删除行为必须显式声明（RESTRICT / CASCADE / SET NULL），不得依赖默认值。
4. 所有枚举字段必须带 `CHECK` 约束。
5. `project_members`、`task_members` 必须保留 `WHERE role = 'owner'` 的部分唯一索引。
6. 时间列统一 `TIMESTAMPTZ`；业务日期列使用 `DATE`。

新增迁移时，同步更新《02-数据库模型与迁移.md》与《05-迁移映射与差异.md》。

## 9. 测试配置

集成测试的依赖地址可通过环境变量覆盖（默认值对应 `docker/compose.test.yml`）：

| 变量 | 默认值 |
| --- | --- |
| `TEST_DATABASE_DSN` | `postgres://project_builder_test:...@127.0.0.1:15432/project_builder_test?sslmode=disable` |
| `TEST_REDIS_ADDR` | `127.0.0.1:16379` |
| `TEST_REDIS_PASSWORD` | `project_builder_test_redis_password` |

集成测试使用 Redis 的 **DB 15**，与开发用 DB 0 隔离。

### 9.1 串行化约定

集成测试共享同一个物理数据库，`TRUNCATE` 会清掉并发用例的数据。因此：

- 集成测试**不得**使用 `t.Parallel()`。
- 测试包通过 `TestMain` 获取 PostgreSQL 咨询锁（`pg_advisory_lock`），
  把 `go test ./...` 下并行执行的多个测试包串行化。
- `make test` 额外使用 `-p 1` 显式串行编译。

这套机制解决的是实测过的假故障：并发用例互相清空数据，表现为"注册返回 409"
或"查不到刚写入的用户"，与真实缺陷难以区分。

### 9.2 脏状态自愈

若上一次迁移被中断（例如测试进程被强杀），集成测试入口会检测到脏状态并重建
`public` schema 后重新迁移。否则一次中断会让之后所有集成测试永久失败。
