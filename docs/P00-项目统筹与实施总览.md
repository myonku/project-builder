## 3. 跨端固定边界

- 产品面向内部网络。品牌只改变用户可见展示；Go module、数据库名、包名、会话 Cookie 等技术标识保持现有值。登录/注册顶栏 W 图标、卡片 W + Worklane + tagline；WILT 位图保留作历史备用，不是当前字标。
- PostgreSQL 管业务元数据与权限，Redis 管会话/限流，Mongo GridFS 或 local 存字节。保留 local 作迁移/回退来源，不常驻双读/双写；迁移后切 GridFS 前必须完成校验，回退先反向复制。运行与备份命令以 B03 为准。
- 头像接口仅 PNG/JPEG，独立于附件配额；可见性与用户资料一致。注册不生成头像对象，UserAvatar 处理默认图、首字及失败回退。前端裁剪不改变服务端校验或头像缓存/版本规则。
- 密码重置策略、令牌与会话失效规则以 A01/A02 为准；管理员重置也吊销会话。当前同步 SMTP 的响应计时差异是已登记的内部网络 MVP 取舍，不把异步发送写成已完成。
- 工作组目录对登录用户开放启用组的基本资料和本人状态；详情/成员/组内计划权限保留。本人申请每组一条最新记录，重新申请更新原记录；停用组不再被发现，但申请仍保留可见。
- 附件没有独立权限，始终继承所属项目/任务；本人管理页不授予额外清理权限。逻辑删除保留对象和配额，彻底删除需确认并先逻辑删除，既有端点实时重新校验权限。
- 现行需求在 S01，HTTP 在 S02/A，架构/运行在 B/F；本页只统筹、索引及说明全局取舍，不复制成第二份字段或配置规范。

## 4. 验收与发布顺序

前端运行类型检查和构建，并按本轮交互做真实浏览器验收；涉及接口/权限时补真实数据库集成测试。按实际范围分阶段提交，远程推送后核对提交及工作区。生产发布按 B03 执行；需要新接口的前端应在后端就位后发布，无接口变化的交互更新只需重新发布完整 dist。

当前头像裁剪轮验收包含选图未保存不上传、裁剪结果字节与预览一致、取消与重试、损坏/超限文件和窄屏；计划页包含个人/组内表格高度、长列表滚动及页底分隔留白。证据归 F05，过程记录不在此展开。

## 5. 后续增强池

当前已批准范围以 §2 为准，以下仅是可选增强，尚未获准进入实施：

| 方向 | 实施前需明确 |
| --- | --- |
| 甘特图拖拽改期 | 日期约束、权限、版本冲突、父子区间及交互验收 |
| 邮件异步发送/出站表 | 消息事务、重试和速率控制、运维部署成本 |
| 项目状态自动推进及手动维护（本轮仅评估） | 开始日期触发规则、手动状态优先级、统一业务时区、列表/详情/计划/筛选一致性 |


项目状态评估（2026-10-26）：projects.status 为持久化字段，创建默认 not_started，开始日期不会触发自动推进；现有 PATCH 支持状态但前端编辑表单缺少入口。百分比 progress 则在查询时对未删除且未取消任务取平均，不是时间进度。影响范围为中等，可复用现有字段/接口，不必因 status 已存储就重建表；本轮不变更状态业务。

下一步建议：先确定到开始日是否将未开始视为进行中，以及手动选择未开始的优先级、统一使用哪个业务时区；优先评估后端集中派生对外展示状态，保留原存储状态，不在 GET 时写库，也不在各前端页面各算一套。暂停、取消、完成、归档应保留，不按结束日期推断实际完成，不让百分比随时间增长。随后统一列表/详情/个人计划/组内计划/甘特图与状态筛选口径，补前端手动状态入口并沿用版本校验；最后覆盖创建时日期已过、跨日/时区、手动状态、筛选分页、归档只读和各页面一致性的验收。是否新增展示字段及其它契约调整，在规则确定后再落实。

新需求直接进入本页的统筹表与对应规范，不再以新的日期阶段文档作为永久入口。附件 404 口径等已修复事项不再作为待办；旧 W1–W5 已完成，不再重复排期。
