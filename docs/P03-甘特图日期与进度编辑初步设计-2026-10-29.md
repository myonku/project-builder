## 1. 需求与评估结论

在现有甘特图内，通过图形操作修改任务的开始日期、截止日期和进度百分比，并满足两项限制：

1. 提供“允许编辑”开关，默认关闭；关闭时甘特图保持锁定，开启后才开放有权限的编辑操作。
2. 每笔编辑都显示提醒/确认面板，用户确认后才保存；同一页面一次只处理一笔编辑，防止连续拖动、重复确认和多任务同时提交。

**采用现有自绘甘特图 + 单笔草稿 + 模态确认面板 + 现有任务 PATCH 接口。** 日期端点在条外拖动，进度在条内深浅填充分界处拖动，主体其余区域用于整条平移；短条等空间不足的场景使用面板。所有有效拖动均在松开后确认、确认后保存。工作量集中在前端手势、交互状态和保存后的刷新协调，不需要新表、新接口、迁移、缓存、MQ 或拖拽依赖。现有 React/MUI、dayjs、Pointer Events 及请求层足以实现。

需要明确三条边界：

- “允许编辑”是当前页面的交互开关，不授予业务权限，也不是跨用户数据库锁；服务端继续校验权限、归档状态、版本及层级日期约束。
- “每次编辑”指一次完成的手势或一次面板编辑会话，不是每个 pointermove / 滑块刻度都弹窗。拖动只预览，松开后确认；取消、无变化、未达到拖动阈值均不写库。
- “防止连续编辑”采用**严格串行，上一笔确认/保存/刷新完成前不接收下一笔**；不添加固定冷却时间，也不要求每次操作后重新勾选。正常完成后保留按钮选中状态，下一笔仍须独立确认。

## 3. 初版范围

### 3.1 编辑对象与资格

项目视图和成员视图共用同一套任务编辑能力。同一任务在多个成员泳道出现时，按 task_id 视为一个对象，而非多份任务。

| 对象/状态 | 日期 | 进度 | 说明 |
| --- | --- | --- | --- |
| 有编辑权限的普通叶子任务 | 可编辑 | 可编辑 | 使用服务端 can_edit；进度为 0–100 整数。 |
| 有编辑权限的父任务 | 可编辑 | 只读 | 依据 task.has_children，不能依据当前筛选/折叠后可见子行数量判断。 |
| 已完成叶子任务 | 可编辑 | 可编辑 | 进度下降可能重新变为未开始/进行中，确认面板必须提示。 |
| 已取消任务 | 可编辑 | 初版禁用 | 避免仅拖进度就隐式恢复任务；需要恢复时走既有详情中的显式状态编辑。这是本入口的产品限制，非服务端新增禁令。 |
| 里程碑 | 可编辑 | 按叶子规则 | 当前 is_milestone 是展示标志，不能假定开始和截止必为同一天。 |
| 只读/归档任务 | 不可编辑 | 不可编辑 | 即使“允许编辑”已选中也不开放；归档包括系统管理员。 |
| 项目汇总行、成员泳道汇总行 | 不可编辑 | 不可编辑 | 初版修改任务，不修改项目周期或汇总进度。 |

不包含批量改期、父任务拖动带动整棵子树、依赖关系/自动排期、工作日吸附、撤销栈、自动保存、跨任务队列及新的实时协作机制。现有权限不变。

### 3.2 编辑开关

甘特图上方的标签提示行右侧放置 `允许编辑` Switch，使用 checked / switch 语义表达状态，启用时使用 warning 色调。“只读模式”或“已启用编辑模式”及暂不可编辑的原因通过悬浮/聚焦提示显示，保留可见的开关标签与可访问说明；蓝色线框内的操作说明保持常驻。

标签提示行采用 `minmax(0, 1fr) max-content` 两列布局：左列标签与图例在自身内部折行，右列开关保持右对齐、不折行，并与左列第一行顶部对齐。窄屏时不得把开关整体移到左列下方。

- 页面首次进入、刷新、离开再返回均默认锁定；不写 URL、localStorage 或全局 UI store。
- 切换项目/工作组/成员筛选/项目与成员视图、切换时间尺度时，清理草稿并重新锁定；不得把旧图上的编辑带入新图。
- 数据加载失败或发生权限、版本、结果不确定等异常时重新锁定。没有可编辑任务时按钮禁用并解释原因。
- 有编辑会话（dragging / confirming / saving / refreshing）时暂时禁用图内其他编辑入口、筛选、尺度、折叠、手动刷新及开关切换；允许查看图中信息，但暂停打开任务详情抽屉及项目详情导航，避免另一编辑器并行写入。异常后的只读核对刷新不受此限制。若已打开任务抽屉，先关闭再开启图形编辑；ready 时打开详情则先退出图形编辑并重新锁定。
- 该开关仅约束甘特图的图形编辑，锁定时仍保留原有查看能力；不会禁止用户通过其他页面执行既有合法编辑。

## 4. 图形交互与确认面板

### 4.1 日期

- 拖动条形主体中未被进度手柄占用的区域：开始、截止同时平移相同的自然日数，保持原跨度。
- 拖动左右独立日期手柄：只修改开始或截止日期，另一端保持不变；不允许两端交叉，最短区间是同一天。日期手柄的有效命中范围完全位于任务条外侧，条与手柄之间保留隔离带，具体见 §4.4。
- 手势开始前检查编辑开关、资格及页面是否空闲；移动超过小阈值（初始 5px）才认定拖拽。主体未超过阈值时继续原“点击查看”；专用手柄未达到阈值时不改值、不打开详情。真正拖拽结束后屏蔽随后的合成 click，即使候选值最终回到原值，也不再打开详情。
- 拖动中显示临时轮廓与候选日期，不改已加载的权威 payload、不发 PATCH。松开且自然日值确有改变，弹出日期确认面板；无变化直接还原。
- 短条、同日任务及里程碑不依赖狭小手柄：任务行提供仅在编辑模式出现的“编辑日期”图标，可直接打开同一面板，通过两个日期控件修改并确认。普通任务的两个日期手柄无法完整显示或无法独立命中时，隐藏受影响的手柄并使用面板，不扩大命中区覆盖条内。里程碑在桌面可拖菱形平移两端，分别改端点走该面板；不强行把原区间压成一天。
- 触屏/粗指针初版使用面板修改日期和进度，不启用条内外拖动手势；条形主体和里程碑保留默认滚动，不拦截滑动。不要对整张图设置 touch-action:none；桌面专用手柄所需的手势限制仅作用于自身。

初版不做拖至边缘自动滚屏/无限扩展。用户可先滚动时间轴或在面板精确输入任意合法日期；不以当前可见时间窗口作为业务日期边界。

### 4.2 进度

采用**长条内拖拽优先，短条使用面板**的策略：

- 桌面精细指针下，在“允许编辑”开启、任务有进度编辑资格且页面空闲时，长度足够的普通任务条默认显示进度竖形手柄，无需先悬停才能发现。手柄位于深色已完成区域与浅色未完成区域的交界处，视觉宽初始 5–6px，命中宽初始 12–16px，悬停/聚焦增强轮廓并提示“拖动修改进度”。
- 拖动手柄只更新本笔进度草稿、深色填充与候选百分比，不移动任务日期、不写库。松开且整数值确有改变后，打开 §4.3 的同一个进度确认面板，直接带入候选值；可继续使用 MUI Slider 或数字输入修正，再按“确认修改”保存。
- 初始条内拖动阈值为 **72 CSS px**，按当前尺度下实际可见条宽判断，不按任务天数判断。当前日/周/月尺度日宽分别为 34/12/16px，同一任务切换尺度后允许切换入口策略。低于阈值时隐藏条内手柄，使用任务行百分比/编辑图标打开面板。阈值及手柄尺寸在浏览器验收中可微调，但不得牺牲命中范围互斥。
- 里程碑、触屏/粗指针均使用面板。长条也始终保留任务行百分比/编辑图标入口，供精确输入和键盘使用；从该入口进入时以原值初始化。父任务和已取消任务遵守 §3.1 的禁用规则。
- 0% / 100% 的逻辑分界分别位于真实左、右端点；手柄视觉本体及命中区域向条内展开，不能伸入日期隔离带或日期手柄区。保持 0–100 全范围，不为安放手柄把进度限制为 1–99，也不压缩填充的比例范围。
- 条内百分比文字避让手柄；空间不足时隐藏条内文字，保留行标签百分比。拖动提示显示候选整数值；取消、Esc 或无变化均恢复权威显示。

面板滑块变化仅更新本笔草稿，按“确认修改”才发一次 PATCH；不按 onChange/onChangeCommitted 自动保存，不逐刻度重复弹窗。条内拖动和面板直接编辑共用一次确认，不串联嵌套弹窗。

进度请求只发 progress，不发旧 status。沿用服务端推导：0 → not_started，1–99 → in_progress，100 → completed。即使进度只从 100 调为 99，也可能重新激活任务及其提醒资格；只改进度不等同于“状态不变”。父任务禁用入口并提示“进度由下级汇总”。

### 4.3 共用确认面板

使用一个 MUI Dialog，日期/进度两种模式，不串联两个弹窗。手势生成的候选值直接填入面板；从图标进入时以原值初始化。面板内容如下：

| 内容 | 要求 |
| --- | --- |
| 对象 | 项目名、任务名；必要时展示任务路径，避免成员泳道重名误改。 |
| 变更 | 日期显示原区间 → 新区间及平移天数；进度显示原百分比 → 新百分比。 |
| 状态影响 | 进度模式明确显示服务端规则推导的目标状态，包括完成或重新开始；最终以保存响应为准。 |
| 关联影响 | 提示“保存后将同步相关提醒计划；已获发送授权的邮件可能仍按原内容发送”。进度模式补充“可能更新父任务和项目的汇总状态/进度”。不列出无权查看的人员或子任务详情。 |
| 校验 | 日期合法且 start≤end，进度为 0–100 整数；无变化或非法值时确认按钮禁用。只编辑当前模式字段，不把日期和进度混成两次请求。 |
| 动作 | “取消” / “确认修改”；取消不写库。提交后显示“保存中”，禁用确认、取消、遮罩和 Esc 关闭，防止把关闭误认为撤销请求。 |

确认前 Esc/取消还原临时图形并恢复焦点。确认按钮不能因面板刚打开而被手势残留点击触发；使用独立点击事件，避免 Enter 长按或双击产生二次提交。无额外“确认后再确认”。

### 4.4 命中区域与操作互斥

从左到右的布局为：左日期手柄 → 隔离带 → 任务条主体（含进度手柄）→ 隔离带 → 右日期手柄。

| 区域 | 初始布局与行为 |
| --- | --- |
| 左/右日期手柄 | 命中宽各约 10–12px，完全位于条外；分别改开始/截止，鼠标显示水平缩放提示。 |
| 两端隔离带 | 各约 3–4px，位于条与日期手柄之间；不启动编辑手势，不透传为主体平移或点击查看。 |
| 进度竖形手柄 | 命中范围仅位于条内；只改进度，与主体平移区域互斥。0%/100% 也遵守此规则。 |
| 条内剩余主体 | 桌面拖动整条平移；普通点击打开详情。进度手柄所在命中区域不再触发主体操作。 |

手柄尺寸、隔离带均为屏幕 CSS 像素，不随日宽放大；它们只服务交互，不改变任务条表示的日期长度或深浅填充比例。手势类型在 pointerdown 时固定为 move / resize-start / resize-end / progress，整个手势不得跨区切换；拖出条外仍维持原操作。不得通过重叠命中区再依赖事件冒泡顺序决定操作类型。

当前整个任务条使用 button；实施时调整为可容纳独立操作入口的容器，避免 button 内嵌 button/slider。保留任务名称的查看入口；日期、进度替代入口可独立聚焦，提供明确的可访问名称。若进度手柄可聚焦，应提供 slider 语义、0–100 当前值和方向键/Home/End 操作；键盘调整同样只形成单笔草稿，由明确动作进入确认，不逐键弹窗或保存。取消后恢复到来源入口，入口已不可用时回到对应任务行。

## 5. 单笔状态与连续操作限制

页面维护一个编辑控制器，不在每行/每泳道各自维护保存状态。草稿至少保存 task_id、来源行/入口、操作类型（move / resize-start / resize-end / progress）、原日期/进度/状态、原样 updated_at、候选值及当前视图身份；指针会话另捕获 pointerId、起始 clientX / scrollLeft、时间轴起点及原始任务条宽度。键盘进度调整进入 dragging 所代表的预览阶段，Enter 结束预览并进入确认，Esc 取消；若 Tab 离开且有变化则进入确认，无变化结束会话，避免遗留未确认草稿。

| 状态 | 可执行行为 | 出口 |
| --- | --- | --- |
| locked | 浏览、打开详情；不能图形编辑 | 选中允许编辑 → ready |
| ready | 允许一个合格任务进入编辑 | 拖拽 → dragging；点击编辑图标 → confirming |
| dragging | 只更新该笔预览，拒绝第二指针/其他任务 | 有效变化 → confirming；取消/无变化 → ready |
| confirming | 仅修改当前草稿或取消，其他编辑禁用 | 确认 → saving；取消 → ready |
| saving | 只允许一个 PATCH 在途，屏蔽重复确认 | 明确成功 → refreshing；明确拒绝 → 展示原因；结果不确定 → 锁定核对 |
| refreshing | 已保存，等待当前图及相关汇总重新读取 | 成功 → ready；失败 → locked，提示“已保存，视图刷新失败” |

关键约束：

- 除 React 渲染状态外，提交入口使用同步 in-flight 标记（如 ref），在发请求前置位。只禁用按钮不足以阻止同一帧双击；不得缓存第二笔操作等待自动执行。
- 一笔编辑期间，不允许从同任务的另一个成员泳道开启第二笔；临时预览可按 task_id 映射到其重复行，但只存在一份草稿。确认面板只弹一次。
- 释放锁的条件是本笔已经结束且权威数据可用；不能在 PATCH 的 finally 内不分结果地立即允许下一次拖动。
- pointercancel、Esc、失焦/窗口隐藏或捕获丢失应取消未提交的拖拽、恢复预览；onLostPointerCapture 与 pointerup 必须幂等，不能重复打开面板或误取消已经进入确认的草稿。
- 页面卸载时清理监听、捕获和读请求。已发出的写请求不能靠取消 fetch 保证撤销；返回页面默认锁定并重新读取，不恢复未保存草稿。

## 6. 写入、冲突与刷新

### 6.1 请求复用

日期使用 `PATCH /api/v1/tasks/{task_id}/dates`，始终提交两端及**手势/面板开始时捕获的版本**：

```json
{
  "start_date": "2026-11-02",
  "end_date": "2026-11-06",
  "expected_updated_at": "2026-10-29T01:00:00.123456Z"
}
```

进度使用 `PATCH /api/v1/tasks/{task_id}`：

```json
{
  "progress": 60,
  "expected_updated_at": "2026-10-29T01:00:00.123456Z"
}
```

不回传完整任务，不附带 status、parent_id 或未修改字段；每笔仅一个 PATCH。时间戳原样传递，不格式化/截断亚秒。确认前不另取新版并悄悄替换 expected_updated_at，否则会绕过用户基于旧图作出的判断。

### 6.2 层级、权限及错误

- 日期须满足现有层级约束：子任务落在有效父区间内；修改父任务后的区间仍覆盖其未删除直接下级。父任务平移不带动子任务，可能因此被拒绝；面板提前说明，不自动扩父、改子或连发多次 PATCH。
- 可见树可能被权限/筛选裁剪，前端只能提示已知约束，不能推算完整可写范围；服务端为最终裁决。项目行的显示区间不是本计划新增的任务日期限制。
- 409 version_conflict：提示“任务已变化，请刷新后重新编辑”，丢弃旧预览、重新锁定并刷新；不自动合并、不替换版本重放旧草稿。
- 403/404、归档 conflict：提示无权/不存在或不可见/已只读，结束本笔并重新锁定；刷新权限，不暴露隐藏对象。
- 400/422：在面板展示字段原因，本笔可在原版本上修正后再次明确确认；不得自动提交。若错误涉及结构已变化，刷新后重新发起。
- 网络断开、超时或未能确定是否提交的服务端错误：提示“保存结果未确认”，重新锁定，不乐观宣称已回滚，不自动重试；提供只读刷新核对。即使最新值恰好等于草稿，也只说明当前数据如此，不证明本次请求执行归属。再次编辑必须基于重新读取的版本并重新确认，服务端 CAS 仍承担并发裁决。

### 6.3 保存成功后的读取

不把返回的 Task 强行合并成 PlanTask，两个 DTO 字段不同。明确显示保存结果后，重取当前项目甘特图或成员组内计划，刷新任务、所有重复泳道、祖先/项目汇总与顶部统计；已存在的相关详情/项目选项缓存按需失效。

编辑期间冻结时间轴范围、dayWidth 和起点，避免预览扩展日期导致图跳动。保存后的新数据可以重建时间窗口，但保留筛选、尺度、仍有效的折叠项；尽量恢复原可视日期锚点与垂直滚动位置。当前 dataKey 包含尺度，切换尺度本身仍沿用已有折叠重置行为。

应让数据 hook 的刷新返回明确完成结果，或提供可关联本次重载的 generation；不能通过观察 reload 调用后暂时仍为 false 的 loading 推断已完成。后端已保存但刷新失败时保留独立“已保存”提示并锁定，允许重读，不得再次提交旧草稿。

## 7. 日期、进度几何与实现划分

日期以 YYYY-MM-DD 自然日处理，复用 dayjs 日运算，不经 toISOString 或毫秒/24 小时换算。开始/截止均包含端点，同日任务跨度为一日。

- 固定手势开始时的原日期、时间窗口及日宽；平移天数按水平位移/dayWidth 四舍五入到整天，对正负方向采用一致规则。
- 若手势期间发生容器水平滚动，位移须包含 scrollLeft 的变化；不能只用 clientX 差值。纵向位移不改变日期。
- 使用原始未裁剪日期计算候选值，barGeometry 只负责显示；不能把裁剪后的左边界/最小像素宽度当真实起止日期。
- 只改端点时限制到合法区间，同日可存；日期面板允许精确输入。初版只吸附自然日，不跳周末，不自动调整到任务/项目边界。
- 拖拽手柄使用 Pointer Capture，专用手柄与进度入口分离；触屏和键盘可通过日期控件/滑块完成相同操作。进度 0%/100% 仍有可达入口，不依赖填充区域宽度。

进度几何与命中计算遵守以下规则：

- 使用完整任务区间的原始条宽 `W = 包含两端的自然日数 × dayWidth`；逻辑分界为 `原始条左端 + W × progress / 100`。隔离带、日期手柄及进度手柄宽度均不计入 W，也不为手柄预留而缩短填充轨道。
- 从手柄任意位置抓取均采用相对位移：`候选进度 = clamp(round(原进度 + 100 × Δx / W), 0, 100)`。Δx 包含 clientX 与 scrollLeft 的变化；纵向位移不改变进度。起手不将抓取点直接换算成绝对百分比，避免数值跳变。达到拖动阈值后再生成候选值。
- 手势期间固定 W、时间窗口、操作类型及入口策略；预览变化不能触发阈值判断重算而使手柄中途消失。拖回原整数进度则结束时不弹确认、不发请求。
- 可见条宽达到 72px 只是必要条件。真实进度分界及完整的向内命中区域也必须可见；若被时间窗口、滚动视口或 sticky 标签列裁剪/遮挡，则隐藏条内入口并保留行标签面板入口。不得把可见片段重新映射为 0–100%。
- 日期手柄仅在对应真实端点及其完整命中区/隔离带可见时出现；裁剪边缘不冒充真实端点。不在 overflow:hidden 的条容器中裁掉外侧日期手柄，也不让手柄覆盖 sticky 标签列或其他行。

建议文件职责：

| 文件/模块 | 计划职责 |
