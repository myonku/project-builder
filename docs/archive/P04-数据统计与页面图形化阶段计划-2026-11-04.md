## 1. 目标调整与设计结论

**下一阶段建设两种体验：日常工作的图形概览，以及面向会议屏幕的组内/成员周报、月报。** 周期汇报成为本阶段核心交付，不再等同于带截止筛选的任务列表、网页打印或复制摘要。

建议对已实现内容做以下调整：

| 现有内容 | 第二版决定 | 原因 |
| --- | --- | --- |
| `/gantt` 进度视图 | 保留名称、路由及编辑功能 | 时间线已经有独立承载位置 |
| `/statistics` 组内概况/成员分布 | 重组为“数据概览 / 周期汇报”，组内/成员改为范围选择 | 查看对象与使用目的分开，用户直接找到周报/月报 |
| 多个水平进度条及长名单 | 用有明确分工的柱状图、折线图、环形图替换主体，保留进度百分比作辅助 | 让分布、变化、成果成为视觉主角 |
| 概览的五项汇总 + 单条状态图 | 重排为行动数字、到期柱图、任务状态环图、近期动态/里程碑 | 增加信息种类，减少同一数字重复呈现 |
| 打印当前网页 | 改为打印汇报专用分页布局；网页明细打印保留次要入口 | 会议演示与纸面汇报都需要有组织的内容 |
| 原生 `type="date"` | 统一现有 MUI 日期选择器及中文本地化 | 消除浏览器混合格式占位及交互不一致 |
| 只在前端汇总计划投影 | 当前分布继续复用；周期成果/趋势和动态增加服务端数据投影 | 现有字段不足以支撑可信的历史汇报 |

第一轮的权限边界、叶子去重、URL 范围恢复和请求竞态保护继续复用。图形数量不作为成果指标：日常概览最多 2 张主图，统计概览最多 3 张，演示每屏 1 张主图或 3–5 个成果条目；用页签、切换和分屏控制信息密度。

## 3. 页面布局与信息层次

### 3.1 概览 `/`：今天需要做什么、近期发生了什么

默认范围为“本人承担”；切换到“参与项目”时，所有卡片、图表、待办和动态同时切换，并显示范围名称。本人承担覆盖本人作为任务成员的可见叶子任务；参与项目覆盖本人具有项目成员关系的项目，不自动扩成全组共享计划。

```text
概览      [本人承担 / 参与项目]                最近更新 · 刷新
[未完成]       [已逾期]        [未来7天到期，含今天]       [本周完成*]
[未来14天到期安排：每日柱状图，较宽]           [当前任务状态：环形图]
[需要处理：逾期/紧急/近期任务，最多5条]        [近期动态：最多6条]
[近期里程碑：未来30天，最多3条]               [关注项目：最多3项]
```

`*` 本周完成来自周期事件接口；历史覆盖不足时显示“记录不完整”及可用起始日，不显示伪造的 0。第一阶段接口未就绪时该卡使用“本周待到期”，明确表达当前安排，不能保留“完成”标题却换用截止日期计数。

- 到期柱图：横轴为请求者时区的自然日，纵轴为未完成叶子任务数；只画今天至未来 13 天，逾期另由行动数字提示。点击某天展示任务明细；条上数量和日期可直接读懂。
- 状态环图：未开始/进行中/已完成/已取消四段，中心为叶子任务总数；图例带数量。用于回答当前构成，不表示工时投入或项目有效进度。
- 待办：优先显示逾期，再按优先级、截止日期排序；一条含名称、项目、截止日和异常原因。继续复用任务抽屉。
- 近期动态：如“张三完成了接口联调”“测试计划由周四改至周五”“发布准备重新打开”。展示人、对象、变化和时间；只显示有权限的业务事件，不显示邮箱、账号维护、原始 JSON。
- 近期里程碑：展示名称、项目、日期、状态；已逾期未完成的里程碑可优先呈现并标明，不能混入“未来”而不解释。
- 关注项目：本人持有/参与且有未完成任务的项目，按逾期叶子数和最近截止日排序；保留简洁项目进度数字，不再铺一列重复进度条。
- 原账号信息收在底部，完整个人资料入口仍在用户菜单；原项目/任务全量数字移至范围说明或统计页，避免首屏同时出现两套不同口径的总数。

### 3.2 数据统计 `/statistics`：日常分析与周期汇报分离

顶层页签为“数据概览”和“周期汇报”。范围选择为“组内共享 / 组内成员 / 本人承担”；组内成员必须先选组，再选成员。本人承担不强制先选组，可再限定本人有权访问的项目。

“数据概览”推荐布局：

- 第一行 3–4 项数字：可见叶子任务、未完成、逾期、涉及项目。
- 主图一：状态环图；主图二：最近/未来截止安排柱图；主图三：组内时显示成员未完成任务堆叠柱图，单成员时显示按项目的任务构成柱图。
- 主图三最多显示 8 个分类，提供选择成员/项目及“其他”汇总，不能丢弃其余数据后仍称全组。成员按未完成数量排序，并注明参与计数可重复；不叫效率排名。
- 项目当前进度放入可展开项目区，作为上下文，不占主图位。当前截止筛选仍叫“截止范围”，与汇报周期分开。
- 详细名单进入抽屉/展开区，不在页面首次打开时铺满；保留现有统计模型及同口径下钻，禁止一个图块点击后跳到无筛选的全量列表。

原 `group/members` URL 可兼容映射到新“数据概览”的对应范围；旧 `dueFrom/dueTo` 继续表示截止范围，绝不能静默解释为历史汇报期间。

### 3.3 项目详情 `/projects/:id`

替换第一轮单条状态图：在基本信息之后、成员/附件之前，放“任务状态小环图 + 未来14天到期柱图”的单个概况区，现有项目有效进度百分比继续保留。再以折叠区呈现“近期里程碑 / 最近变更”，从信息流接口按项目过滤读取。

项目详情的图形固定反映整个可见项目，表格筛选仅影响下方表格；页首明确范围。表格保留全部编辑功能。项目列表首批仍不新增全局图表，避免由当前分页结果误算全项目分布。

### 3.4 个人/组内计划

继续承担查找、排期与修改，补充“查看数据概览”和“生成本周汇报”上下文入口，不再追加相同图表。成员/组切换、任务抽屉与甘特图入口保持现有习惯。

## 4. 周报/月报与会议演示设计

### 4.1 汇报编辑区

周期汇报页先选择范围、周期和观察时区，再生成预览：

- 范围：组内共享、组内指定成员、本人承担；项目可选。组内成员报告只含该组共享可见内容，不代表成员全部工作。
- 快捷周期：本周、上周、本月、上月、自定义；自然周为周一至周日，自然月为月初至月末。
- 本周/本月标题带“进行中，截至 ×月×日 ×时”，实际统计到 `as_of`；上一完整周期可显示同周期比较，进行中的周期首版不提供涨跌百分比，以免和完整上周期误比。
- 汇报以同一个聚合响应作为全部页面的数据源；默认不自动轮询。演示时保持本次读取值稳定，刷新时统一重算全部页。
- 可编辑汇报标题、3–5 条成果说明、阻碍/协助事项、下期安排；首版为本次会话草稿，可复制和打印，不默认持久化到服务器或共享给其他人。系统只能给有数据依据的候选条目，不能自动声称“风险已消除”“团队效率提升”。

### 4.2 会议屏幕的四屏叙事

| 屏幕 | 核心问题 | 展示内容 | 组内 / 单成员差异 |
| --- | --- | --- | --- |
| 1. 本期摘要 | 这段时间交付了什么，现在还有什么 | 报告标题、范围、周期；本期完成/新增/重开及期末未完成 4 个大数字；最多 3 条成果摘要 | 成员使用本人承担或组内参与口径，旁注多人重复计数 |
| 2. 推进节奏 | 新任务与完成是否持续发生 | 每日/每周新增与完成分组柱图；通过视图切换查看期末未完成数量折线，避免双轴叠加 | 同一任务集的周期流量和存量，不能把完成柱相加当成去重完成数 |
| 3. 工作分布与成果 | 哪些项目/成员在推进，代表成果是什么 | 组内显示最多 6 位成员的本期完成/期末未完成分组柱图；单成员显示按项目分布；侧边最多 3 条成果 | 其他成员/项目汇总为“其他”，完整名单回分析页查看 |
| 4. 待关注与下期安排 | 接下来要处理什么，需要哪些协助 | 最多 3 项逾期/重开/改期关注点、最多 3 项下期里程碑或计划、可编辑协助说明 | 选定历史期时，“下一期”按该周期的后续周期计算，而非永远从今天算起 |

第 4 屏首版的下期安排使用**生成时的最新计划**落在下一周期的截止/里程碑，常驻“最新安排”标记；不冒称历史报告当时已确定的计划。若以后需要当时承诺与实际交付对比，再引入计划基线。

```text
┌ 工作组甲 · 2026年11月周报              11/2–11/8（示意布局） ┐
│ [完成 12]   [新增 9]   [重开 2]   [期末未完成 18]             │
│                                                            │
│        本期推进节奏（主图占约2/3区域）    关键成果 1           │
│        柱状 / 折线二选一                 关键成果 2           │
│                                         关键成果 3           │
│ 范围 / 统计时区 / 数据完整性                       第 2 / 4 屏 │
└────────────────────────────────────────────────────────────┘
```

以上数字仅示意，不来自真实业务；实施原型必须使用独立样例并明确标识。标题实际日期由周期控件生成，不能手写不一致的周编号。

### 4.3 演示、打印与分享行为

新增“开始演示”进入专用呈现布局，可采用 `/statistics/present`；隐藏导航、编辑控件和明细，默认手动翻屏。支持左右键、屏幕按钮、Esc 退出，提供浏览器全屏按钮；全屏被浏览器拒绝时仍能使用大版布局。

按 16:9 设计，1920×1080 验收目标：标题约 36–44px、关键数字 48–64px、主要文字/图例至少 22–24px；最多 6–8 个横轴分类，长名称换行或简写并在汇报编辑区可查全称。每屏无需滚动；1366×768 下保持主图与要点完整。手机使用普通单列预览，不硬缩成会议屏幕。

打印直接使用汇报分屏数据，提供横向分页，每屏对应一页；隐藏翻屏按钮，保留标题、范围、时区、页码和数据覆盖提示。不是打印当前 DOM 的前几条或虚拟列表。首版不做 PPTX 导出、自动播放、自动发送或定时报表。

查询链接仅保存范围和周期，接收者按自身权限重算，不能携带未公开的自由文本草稿；它不是不可变历史报告。持久化报告库、共同编辑和正式发布作为后续扩展。当前会话的稳定预览也不授予新的访问权限，权限失败或切换身份时必须清除，进入演示和导出前重新校验访问资格。

## 5. 图表选择和统一视觉规范

| 图表 | 放置位置 | 数据含义 | 避免的误读 |
| --- | --- | --- | --- |
| 环形图 | 概览、数据概览、项目详情 | 当前叶子任务四状态构成 | 四类互斥，逾期是子集标记，不能作第五段；成员多人占比不能画成总和100%的饼图 |
| 普通柱状图 | 概览未来到期、项目详情近期安排 | 日期对应的未完成任务数量 | 是计划截止分布，不是历史产出趋势 |
| 分组柱状图 | 周/月报推进、成员/项目对比 | 周期新增/完成，或完成/期末未完成 | 流量与存量在标签中区分；不宣称工时、投入或效率 |
| 折线图 | 周/月报推进页的切换视图 | 各日/周末未完成任务存量 | 有真实基线及事件才画；未知区间断开，不补0、不平滑生成数据 |
| 简洁进度数字/条 | 项目摘要、甘特图 | 服务端有效项目进度 | 不等同于“本周完成比例”，不替代本期成果 |

环形图仅显示少量明确分类；不使用 3D 饼图、渐变仪表盘、双纵轴和无依据的预测线。条/柱从 0 起，计数为整数；百分比明确分母，分母为 0 显示“—”。所有主图具有标题、单位、数量标签和文字摘要，颜色不是唯一识别方式。

成员对比的柱长必须使用同一个数量标尺。第一轮“每人一条100%宽的状态构成”只能说明比例，无法说明任务数量差异，因此应替换。演示中关键数值常驻，不依赖悬浮；分析页支持悬浮、聚焦、触屏点选和明细下钻。

前端新增统一 `charts/` 表达层，业务统计放在模型/接口层；图表不自行决定权限或计数规则。实施前用同一份四状态、31天、8成员样例验证一个图表方案的主题、可访问性、响应式、按需加载和打印，再决定是否引入专用库；本计划不承诺未经核验的库版本/授权。图表依赖仅随统计/概览相关路由加载。

## 6. 指标口径：当前状态与周期事实

### 6.1 统一范围和计数单位

当前分布按返回的可见任务 id 去重，`has_children=false` 才算叶子，不能以筛选后无子行推断。周期事件按**事件发生时的叶子属性**判断，不能用今天的树结构改写上周完成事实。删除父任务导致子树处理、任务移动、新增子任务使原叶子变父任务，都属于统计资格变化，需要事件记录。

组级同一任务只计一次；成员报表按任务在事件发生时的成员关系归属，一个多人任务可在不同成员报告各出现一次，组级不重复。操作人只用于动态描述，不被当成成果归属人。无成员任务列“未分配”；持有者为空而 members 非空不能当作未分配。期末未完成按期末成员归属，新成员加入不能把加入前的完成记给他。

个人和组内报告均经当前访问权限过滤。组内历史事实还要求发生时属于该组、满足共享范围；不因今天新共享而公开此前私有活动。已失去访问资格、被撤销共享、逻辑删除对象的历史详情及贡献按当前授权集合剔除；在报告中提示“历史按当前可访问范围统计，权限变化可能改变结果”，不返回被隐藏对象的额外数量。

归档不等于撤销权限：周期报告默认保留周期内有贡献且当前仍可读的归档项目，避免完成后归档使成果消失；当前数据概览继续默认排除归档。两者分别显示范围说明。

### 6.2 周期指标定义

| 指标 | 拟定定义 |
| --- | --- |
| 本期新增 | 周期内创建时为叶子的可访问任务，按 task_id 去重；其他节点变成叶子单列结构调整，不算新建 |
| 本期完成 | 周期内存在有效状态由非 completed 进入 completed 的叶子任务，按 task_id 去重；取消不算完成 |
| 本期重开 | 周期内从 completed 转为 not_started/in_progress 的叶子任务，按 task_id 去重；completed→cancelled 单列取消 |
| 期末未完成 | 周期截止观察时点，授权集合内仍是叶子、未删除且状态为 not_started/in_progress 的数量 |
| 日/周完成柱 | 每桶内进入 completed 的唯一任务数；同一任务跨日重开后再完成可在两个桶各计一次，桶合计不保证等于周期去重完成数 |
| 存量折线 | 每个桶结束时点的未完成叶子数，来自基线与事件回放；不能用“新增−完成”简单代替，重开、取消、删除、成员及结构变化都会影响它 |
| 期末逾期 | 期末观察时点的未完成叶子，按该时点有效截止日和报告时区判断；不能拿今天的 `is_overdue` 填历史期末 |
| 代表成果 | 本期完成任务的候选集合，可由报告者选取并加说明；完成后又重开者标记“已重开”，不列为无条件已交付 |
| 改期动态 | 截止日期实际发生变化的事件，展示前后日期；只提示变化，不自动定性为延期责任或失败 |

区间使用报告时区的自然周/月：界面起止日含首尾，服务端转换为 UTC 半开区间 `[start, next_day(end))`。存量取结束边界之前最后状态；当前周期取 `min(周期结束边界, as_of)`，未来日期显示“未到期”，不画0值。月报默认按自然周分桶（边界周裁剪到月内），可切换按日；周报按日。

环比仅在本期与上一完整周期覆盖齐全、相同范围口径及桶规则下显示；上期为0时显示数量差，不生成无限增长率。未完成存量减少并不直接意味着交付更快，摘要不自动作因果评价。

## 7. 数据流与后端扩展方案

### 7.1 拟议读取接口

以下路径和字段为设计草案，实施前再写入正式契约；不修改 A09 的管理员权限。

| 接口草案 | 输入与输出 | 页面用途 |
| --- | --- | --- |
| `GET /api/v1/insights/overview` | scope（self/group/member）、组/成员/项目、时区；返回范围元数据、当前行动数字、状态构成、到期桶、里程碑和少量项目摘要 | 概览及统计概览；服务端批量聚合，避免前端下载全部任务再逐对象补信息 |
| `GET /api/v1/insights/reports` | 同一范围 + 周期起止、分桶；返回 `as_of`、有效时区、coverage、周期指标、series、成员/项目 breakdown、成果候选及下期安排 | 周报/月报全部分屏共用一个响应；统计主体必须来自同一读取快照 |
| `GET /api/v1/insights/activity` | 同一范围 + 事件类型、游标、条数；返回精简事件摘要及可访问对象链接 | 首页和项目近期动态；默认6条，查看更多才分页读取 |
| `GET /api/v1/insights/report-items` | 已规范化范围/周期 + 指标/桶筛选、游标；必要时带短期读取版本 | 分析页核查图表对应任务；不能把当前任务列表充当历史事件明细 |

公共响应需表达有效范围、生成时间、观测截止、时区、口径版本及 `coverage_start / complete / gaps`；明确数据是否可比较。所有事件 id、过滤字段由服务端白名单校验；普通用户只能查本人或有权组内成员，不允许任意 user_id 查询私有计划。

当前状态页可先用 A06 交付新图形，接口就绪后改为聚合投影。任务详情/甘特图仍用现有接口；历史明细可显示事件发生时数值和当前状态两列，明确时间，不混成一个字段。

### 7.2 可信事件的最小基础

建议新增专门的业务统计事件记录，不从现有审计的稀疏新值强行推导全部历史。事件在业务事务内写入，与任务/成员/层级/共享/归档变更同生共死；沿用当前事务基础，不为此引入 MQ。

事件至少包括：事件 id、任务/项目/组标识、发生时间、事务内稳定顺序或版本、动作、操作人、变更前后有效状态/进度/截止日期、变更前后叶子/删除资格、当时成员及共享范围的可回放信息。名称等展示快照只保存确有需要的字段，响应仍经当前权限裁剪。关联上下文变化可用独立关系事件，避免每次操作复制整棵任务树。

需覆盖手工改状态、只改进度导致状态推导、完成后回退、取消、删除/可用恢复路径、复制、移动父级、增删子任务、成员/持有者变更、项目共享与组归属变更。自动祖先汇总不能重复计成叶子完成，也不伪造成员操作动态。事务回滚、版本冲突、幂等重试不得多记事件。

上线时建立一致的初始基线，记录当时状态与关系及 `coverage_start`；基线快照不是“当天新建/完成”事件。初始化与开始捕获必须有共同切换点（停写短窗口或一致快照+可靠增量边界），不能在两者之间漏事件。

初版用基线+事件生成日/周期末状态；规模要求出现后再引入可重建的每日聚合快照。若实现每日快照，按任务事实保留可回放数据并在查询时鉴权，不能将所有成员统计无权限地缓存成公共组报表。索引按实际范围/事件时间查询验证，不预先建设完整数据仓库。

### 7.3 历史缺口与权限变化

现有审计可用于实现前的完整性抽查、定位个别行为，但初版不自动回填无法证明的状态和成员历史。事件采集上线前的周期显示“尚无完整历史记录”；跨覆盖起点的报告可以显示明确标识的部分数据，禁用环比，折线缺失段断开。

无需等待完整一个月才提供价值：当前分布图与真实到期安排先上线；事件启用后立刻可用本期已记录成果及近期动态，完整周/月周期逐步积累。只有完整历史具备后，才能把报告标为“完整周期”。这个分阶段策略不将真正周报/月报从本计划删除。

报表读取使用一致数据库快照；后续下钻若无法维持同一读取版本，应提示数据已更新并支持整份重读。服务端汇总、缓存键、导出均纳入观察者和权限范围，避免把管理员数据交给普通成员。动态请求失败不阻塞已有待办，报告请求失败则不能把空值包装为成功报告。

## 8. 日期选择器统一设计

统计页移除原生 `<TextField type="date">`，改用现有 `DateLocalizationProvider` + MUI `DatePicker`；采用 `format="YYYY-MM-DD"`、中文日历、`size="small"`、与计划页相同的边框/圆角/高度/日历图标及错误提示布局。接口仍提交自然日字符串，不通过浏览器日期输入本地化格式猜测日期。

- 数据概览标签为“截止（起）/截止（止）”；周期汇报为“周期开始/周期结束”，上方提供本周/上周/本月/上月快捷选择。
- 默认直接填入选中周期的日期，避免常驻大段占位；可清空的截止筛选使用现有本地化空值分段，必要时统一字段 placeholder，不保留“yyyy-mm-日”混合形式。
- 不机械照搬操作记录的时分秒输入：仅日期用 DatePicker；只有真正需要时刻的功能才用 DateTimePicker，并与操作记录一致。
- 采用草稿与已应用条件分离；非法/未填完整的日期只在输入区提示，不触发请求，不隐藏上一份成功报告。应用新范围时明确加载，旧报告仍标原范围或暂时遮蔽，不能换了标题却显示旧数字。
- 快捷周期计算使用所选报告时区；URL 保存已应用值，浏览器返回恢复；窄屏允许换行，错误提示不挤压另一日期框。
- 本地化 Provider 保持在懒加载页面子树内，不为日期样式统一增加登录首屏依赖。

## 10. 验收场景与效果标准

### 10.1 使用与视觉

- 用户可在明确范围后选择“上周/上月”，直接进入完整汇报预览，不必先阅读长列表；四屏能讲清成果、节奏、分布和下期安排。
- 1920×1080 与 1366×768 演示无需滚动，标题/单位/图例/数值可见；长名称、多人、零数据与仅取消数据均不溢出。键盘翻屏与 Esc、全屏失败回退可用。
- 概览在桌面首屏突出行动数字和两张主图；动态与里程碑提供新增信息，点击仍可追溯原对象。390px 单列查看，无整页水平溢出。
- 环图四段合计与同口径总数一致；柱图共用数量刻度；未知历史不补0，当前期未来段不伪造；深浅主题及色觉差异下仍能依文字辨认。
- 日期控件与计划/操作记录属于同一套视觉与交互，中文月份/周首日一致，空值、清空、闰日、非法区间和 URL 恢复有覆盖。
- 打印逐页渲染核对每屏主图、要点、范围、页码和覆盖说明，无导航遮挡或 DOM 裁剪，不打印未渲染列表来冒充全量。

### 10.2 数据与权限

| 场景 | 必须得到的结果 |
| --- | --- |
| 一任务本周完成→重开→再完成 | 周期完成去重为1，重开为1；两个不同日期可各出现一次完成；折线按真实最终状态变化 |
| 只提交 progress=100，未提交 status | 有效状态推导为完成时记录完成事件，不依赖审计里是否带 status |
| 甲乙多人任务、丙代为更新 | 组级完成1，甲乙参与完成各1；操作人丙不因此获得成果归属 |
| 周三转交给新成员 | 周三前完成归属原成员；期末存量归属期末成员；不能用今天成员替换整个周期 |
| 叶子后来新增子任务、或父级子树删除 | 旧完成按当时叶子资格保留；后续存量计入结构/删除变化，不重复计算父子 |
| 截止由周四改到下周、之后再提前 | 历史逾期与当期安排依据各时点的有效日期；动态可说明前后变化 |
| 采集周三启用、请求整周/月 | 明确不完整起点，未知段断线、环比不可用；初始化不伪造成当天完成 |
| 项目完成后归档 | 当前仍可读的周期成果保留，报告说明含归档贡献 |
| 撤销共享、移出组、换用户访问报告链接 | 重新按权限读取，隐藏对象不泄漏名称/成员/贡献数；不复用上一用户缓存 |
| 跨时区周/月边界、闰日、夏令时 | 由报告时区形成自然日边界，UTC 半开区间无重复或漏计 |
| 失败写入、版本冲突、事务重试 | 无虚假动态或重复统计事件，模型与真实数据库用例一致 |

### 10.3 工程证据

延续前端类型检查、生产构建和有意义的统计模型验证；新增真实 PostgreSQL 事务/权限测试及真实多账号浏览器联调，不能仅用第一轮静态夹具替代。记录 API 请求数、聚合查询计划、响应体大小、首图耗时和报表总耗时。

建议本地验收基准为 1,000 条当前任务、100 位成员、90 天/100,000 条事件，记录硬件与环境；预热后目标为概览聚合 p95 < 1秒、月报聚合 p95 < 2秒、响应后图形呈现 < 500ms。此为待实测目标，不是已达到的服务承诺；先定位查询、权限过滤与渲染成本，再决定是否需要每日聚合。
