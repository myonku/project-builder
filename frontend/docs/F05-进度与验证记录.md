**骨架期"完成"的口径**（四条同时成立）：

1. `pnpm typecheck`、`pnpm build` 零错误；
2. `pnpm dev` 起得来，浏览器里登录页渲染正常，**首屏无外网请求**；
3. **真实浏览器 + 真实后端**走通 登录 → 概览页（不是 mock，也不是只看 HTTP 状态码）；
4. 未实现的页面有明确的占位与"要接哪些端点"的说明，不伪装成已实现（《S02》§6 第 4 条的同一条原则）。

**明确不在骨架期内**（不要误判为"已完成"）：

- 任何列表/表单/甘特图/上传下载的实际交互；
- 自助注册入口（后端 `POST /auth/register` 存在，前端暂无页面）；
- `@mui/x-date-pickers` 的 `LocalizationProvider`（见《F04》D15）；
- 单元测试与 E2E（《F01》§2.1 的"测试暂不做"，并写明引入时机）。

### 5.2 未登录 / 未启动后端时的行为

```text
GET http://127.0.0.1:5173/api/v1/auth/me   → 502（Vite 代理 ECONNREFUSED 127.0.0.1:8000）
```

说明代理链路已经生效；此时前端应停在登录页并给出可读提示，而不是白屏——由
`stores/auth.ts` 的 `loadMe`（网络错误与 401 都归到 `anonymous`）+ 登录页的提示条承担。

### 5.3 认证与信封（**经 Vite 代理**，即浏览器看到的那条路径）

| 请求 | 期望 | 实测 |
| --- | --- | --- |
| `POST /api/v1/auth/login`（正确口令） | 200 + `Set-Cookie` | 200，`data` 为 `User`，Cookie `pb_session`（`HttpOnly=True`） |
| `GET /api/v1/auth/me`（带 Cookie） | 200 | 200，返回同一用户 |
| `GET /api/v1/auth/me`（无 Cookie） | 401 `authentication_required` | 401，`{error:{code,message,request_id}}` |
| `POST /api/v1/auth/login`（错误口令） | 401 `invalid_credentials` | 401，文案不区分"账号不存在"与"密码错误" |
| `POST /api/v1/auth/logout` | 204 | 204 |
| 退出后再 `GET /auth/me` | 401 | 401 |
| `POST /api/v1/projects/query` | 200 + `pagination` | 200，`pagination:{page:1,page_size:20,total:2,has_next:false}` |
| `POST /api/v1/projects/query`（`sort=not_a_field`） | 400 `invalid_request` | 400，`fields.sort` 给出可用字段清单 |
| `POST /api/v1/projects/query`（`page_size=500`） | 400 `invalid_request` | 400，`fields.page_size` |
| `GET /api/v1/projects/{不存在的 uuid}` | 404 `project_not_found` | 404 |
| `GET /api/v1/plan-views/personal` | 200 | 200，`projects/tasks/summary` 结构完整 |
| `GET /api/v1/plan-views/personal?bogus=1` | 400 `invalid_request` | 400，`fields.bogus` 列出可用参数 |
| `POST /api/v1/auth/login`（带未定义字段） | 422 `validation_error` | 422，`fields.unexpected_field`（中文明细，见《F04》C1） |
| `POST /api/v1/users/query`（`include_disabled=true`） | 200 | 200 |

**结论**：`api/client.ts` 的信封解包、Cookie 传递、错误码分支所依赖的**每一条实测行为**都与
《S02》§2.3 / §2.4 / §2.5 一致；`useApiError` 的映射表因此可以直接按状态码实现。

### 5.14 表格悬浮提示统一（用户反馈）

**现象**：项目列表里单元格的悬浮框是"白底黑框"，邮件列表里却有"灰底圆角"和"白底黑框"两种。

**真因不是截断函数**：MUI DataGrid 对**没有 `renderCell`** 的列，会把格式化后的文本塞进单元格的 `title` 属性

那是**浏览器原生提示框**；写了 `renderCell` 的列不加 `title`，提示来自里面显式写的 MUI `Tooltip`（默认灰底圆角）。DOM 实测：

| 页面 | 列 | 原生 title | MUI Tooltip |
| --- | --- | --- | --- |
| 项目列表 | 工作组 / 结束日期 / 进度 / 最近更新 | 有 | 无 |
| 项目列表 | 状态（归档时间）/ 操作 | 无 | 有 |
| 邮件列表 | 类型 / 计划发送 / 发送时刻 | 有 | 无 |
| 邮件列表 | 收件人 / 失败原因 / 状态提示 / 操作 | 无 | 有 |

**修法（F04 D33 方案 3）**：新增 `components/common/DataTooltip.tsx`（外观常量 + `DataTooltip` + `textCell()` 工厂）；
四张表的文本类列改用 `textCell()`（**写了 `renderCell` 才会去掉原生 `title`**）；单元格内的显式提示改用 `DataTooltip`；
`TruncatedText` 共用同一份样式常量。
