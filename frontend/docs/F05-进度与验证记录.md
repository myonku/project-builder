# 进度与验证记录

## 1. 文档定位

本文档记录前端工程的**阶段状态、验证方法与可复现证据**。

- 前端入口文档（怎么跑、怎么测、代码怎么分层）→ 见 [`frontend/README.md`](../README.md)；
- 技术选型与约定 → [《F01》](./F01-前端架构设计.md)；类型映射 → [《F02》](./F02-数据对象模型.md)；
- 怎么跑、怎么联调、怎么部署 → [《F03》](./F03-运行与联调.md)；
- 实现过程中的取舍与偏离 → [《F04》](./F04-设计偏离与差异登记.md)；
- 服务端的对应记录在 `backend/docs/B05-进度与验证记录.md`。

**证据原则**：每条结论都要能由"命令 + 输出"复现，不接受"应该是可以跑的"。

## 2. 状态基线

| 阶段 | 范围 | 状态 |
| --- | --- | --- |
| **骨架期**（本文档记录） | 工程配置、主题层、`api/` + `types/` 全量、状态与路由守卫、布局、登录页、各域占位页 | ✅ 已完成并验证（2026-10-14） |
| 功能期 | 项目/任务列表与表单、成员管理、计划视图、甘特图、附件上传下载、提醒重试、审计查询 | ⏳ 未开始 |

**骨架期"完成"的口径**（四条同时成立）：

1. `pnpm typecheck`、`pnpm build` 零错误；
2. `pnpm dev` 起得来，浏览器里登录页渲染正常，**首屏无外网请求**；
3. **真实浏览器 + 真实后端**走通 登录 → 概览页（不是 mock，也不是只看 HTTP 状态码）；
4. 未实现的页面有明确的占位与"要接哪些端点"的说明，不伪装成已实现（《S02》§6 第 4 条的同一条原则）。

**明确不在骨架期内**（不要误判为"已完成"）：

- 任何列表/表单/甘特图/上传下载的实际交互；
- 自助注册入口（后端 `POST /auth/register` 存在，前端暂无页面）；
- `@mui/x-date-pickers` 的 `LocalizationProvider`（见《F04》D15）；
- 单元测试与 E2E（《F01》§2.1 的"测试暂不做"，并写明引入时机）。


### 4.3 真实后端（等价于 `make deps-up` / `make migrate-test-up` / `make run-test-config`）

### 4.4 浏览器级冒烟（含截图）

## 5. 验证结果（2026-10-14 实测）

### 5.1 静态与构建

```text
$ pnpm typecheck
$ tsc --noEmit
（无输出，exit 0）

$ pnpm build
✓ 1903 modules transformed.
dist/index.html                     0.73 kB │ gzip:   0.54 kB
dist/assets/index-*.css             1.85 kB │ gzip:   0.40 kB
dist/assets/index-*.js            836.68 kB │ gzip: 261.93 kB
dist/assets/roboto-*.woff(2)         16 个字体文件（latin / latin-ext，共约 280 KB）
✓ built in 375ms
```

- 构建产物里 `index.html` 的标题来自 `VITE_APP_TITLE`，**没有任何指向 `fonts.googleapis.com` /
  `fonts.gstatic.com` 的 `<link>`**（自托管字体，见《F03》§5.3）；
- Vite 报了一条 `chunks are larger than 500 kB` 的提示：当前是**单块**产物（MUI 占大头），
  骨架期不做代码分割；引入甘特图/上传等重依赖时再评估（记为已知项，不是缺陷）。

### 5.2 未登录 / 未启动后端时的行为

```text
GET http://127.0.0.1:5173/api/v1/auth/me   → 502（Vite 代理 ECONNREFUSED 127.0.0.1:8000）
```

说明代理链路已经生效；此时前端应停在登录页并给出可读提示，而不是白屏——由
`stores/auth.ts` 的 `loadMe`（网络错误与 401 都归到 `anonymous`）+ 登录页的提示条承担。

### 5.3 认证与信封（**经 Vite 代理**，即浏览器看到的那条路径）

| 请求 | 期望 | 实测 |
| --- | --- | --- |
| `POST /api/v1/auth/login`（正确口令） | 200 + `Set-Cookie` | 200，`data` 为 `User`，Cookie `pb_session`（`HttpOnly=True`） |
| `GET /api/v1/auth/me`（带 Cookie） | 200 | 200，返回同一用户 |
| `GET /api/v1/auth/me`（无 Cookie） | 401 `authentication_required` | 401，`{error:{code,message,request_id}}` |
| `POST /api/v1/auth/login`（错误口令） | 401 `invalid_credentials` | 401，文案不区分"账号不存在"与"密码错误" |
| `POST /api/v1/auth/logout` | 204 | 204 |
| 退出后再 `GET /auth/me` | 401 | 401 |
| `POST /api/v1/projects/query` | 200 + `pagination` | 200，`pagination:{page:1,page_size:20,total:2,has_next:false}` |
| `POST /api/v1/projects/query`（`sort=not_a_field`） | 400 `invalid_request` | 400，`fields.sort` 给出可用字段清单 |
| `POST /api/v1/projects/query`（`page_size=500`） | 400 `invalid_request` | 400，`fields.page_size` |
| `GET /api/v1/projects/{不存在的 uuid}` | 404 `project_not_found` | 404 |
| `GET /api/v1/plan-views/personal` | 200 | 200，`projects/tasks/summary` 结构完整 |
| `GET /api/v1/plan-views/personal?bogus=1` | 400 `invalid_request` | 400，`fields.bogus` 列出可用参数 |
| `POST /api/v1/auth/login`（带未定义字段） | 422 `validation_error` | 422，`fields.unexpected_field`（中文明细，见《F04》C1） |
| `POST /api/v1/users/query`（`include_disabled=true`） | 200 | 200 |

**结论**：`api/client.ts` 的信封解包、Cookie 传递、错误码分支所依赖的**每一条实测行为**都与
《S02》§2.3 / §2.4 / §2.5 一致；`useApiError` 的映射表因此可以直接按状态码实现。

### 5.4 浏览器实测（登录 → 概览）

`scripts/browser-smoke.mjs` 的输出：

```text
→ 打开 http://127.0.0.1:5173/login
  登录页可见: true
  提交表单: submitted
→ 概览页可见: true
--- 页面文本（前 700 字）---
项目/计划管理系统（开发） / B / 工作台 / 概览 / 项目 / 个人计划 / 组内计划 / 邮件提醒 /
操作记录 / 系统管理 / 用户管理 / 工作组管理 / 概览 / 当前登录用户 / …
→ 截图已保存: .verify/dashboard.png
→ 窄视口截图已保存: .verify/dashboard-narrow.png
```

截图证据（本机 `.verify/`）：

- `login.png`（1440×1000）：登录卡片、中文文案、右上角亮/暗切换，**无外网字体请求**；
- `dashboard.png`（1422×904）：Header（Logo + 标题 + 主题切换 + 用户头像）+ 侧边栏
  （工作台 6 项、系统管理 2 项，管理员可见）+ 概览卡片（`GET /auth/me` 的真实字段）；
- `dashboard-narrow.png`（480×900）：窄视口下侧边栏收起为汉堡菜单、卡片单列堆叠。

同时验证到的三件事：

1. `RequireAuth` 的会话探测（`GET /auth/me`）在客户端路由里工作，登录后进入 `/`；
2. `useApiError` / `AuthStore` 的组合没有把 401 渲染成错误页；
3. 管理员守卫生效：`bootstrap_admin`（`system_role=admin`）能看到"系统管理"分组。

### 5.5 官方模板兼容性

- `verbatimModuleSyntax: true` 暴露了模板里 20 处"类型当值导入"（`Theme` / `Components` /
  `SxProps` / `SelectProps` / `IconButtonOwnProps` / `SvgIconProps` / `PaletteMode` / `Shadows`），
  全部改为 `type` 修饰；`noUnusedParameters` 暴露 1 处未使用参数。清单见《F04》§4；
- 模板里引用了**付费 Pro 包**（`@mui/x-data-grid-pro`、`@mui/x-date-pickers-pro`）的
  `themeAugmentation`，本项目只用免费版，已换成 `DataGridComponents` / `PickerComponents`；
- 模板的 `dataGrid.ts` 把同一个类型写了两遍（`DataGridProComponents<Theme> & DataGridProComponents<Theme>`），
  属上游笔误，已简化。

### 7.2 功能期的推荐顺序（每步都能单独验证）

按《F03》§7 的联调顺序，骨架期已完成第 1–3 步（起得来、主题、登录链路），接下来：

1. **项目列表**（`useListQuery` 的第一个真实使用者）：验证服务器模式分页、排序白名单、
   `rowCount = pagination.total`；
2. **项目详情 + 任务列表 + `TaskDetailDrawer`**：验证 `?taskId=` 与三处复用；
3. **版本协议**：两个标签页同时改一个项目，验证 `useVersionedForm` 的冲突弹窗
   （「放弃我的修改并刷新」/「保留我的修改」）；
4. **成员管理**：只提供"转移持有者"，不提供"改为普通成员"（《F01》§6 第 9 条）；
5. **计划视图**：个人 / 组内 / 甘特图；甘特图接入时才装 `frappe-gantt`（《F04》D3）；
6. **附件**：上传（`413/415/409` 分支）、`blob` 下载、逻辑删除 → 彻底删除；
7. **提醒与审计**：重试（`pending`/`sent` 409）、审计的可见性口径；
8. **权限分支**：用非成员与普通成员账号各走一遍 403 / 404 展示。
