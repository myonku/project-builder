## 引用约定（与后端文档一致）

- **引用用编号**：正文引用其它文档时优先写《编号》§小节，例如《S02》§2.6、《F01》§5.1、《A05》§4。
- **路径写法**：跨端引用写**相对仓库根**（`backend/docs/B03-配置与运行.md`、`docs/S02-HTTP接口契约.md`）；Markdown 链接按惯例相对所在文件。
- **改接口的顺序**：先改 `docs/S02`，再改 `docs/api/`，最后改代码；前端实现侧的取舍登记到 [F04](./F04-设计偏离与差异登记.md)。
- **前端文档不写后端实现细节**：分层、表结构、迁移、SQL 都属于 `backend/docs/`；前端只关心"契约给了我什么、我怎么用"。
- **偏离必须留痕**：与 F01–F03 不一致、或模板被结构性改造，都要在 F04 登记并回写主线文档（F04 §6 的变更规则）。

## 为什么 F04 / F05 是骨架期才建立的

`F04`（偏离登记）与 `F05`（进度与验证）在纯文档阶段**刻意不建**：那时没有实现，登记表只会是空壳。

2026-10-14 骨架期落地时两条触发条件同时成立，因此建立：

- **F04 的触发条件**：前端对既有设计做了**有意偏离**。骨架期一次就暴露了 15 条
  （版本号与文档不符、侧边栏不合并、`useNotifications` 没有 `showError`、模板引用付费 Pro 包……），
  散落在代码注释里没人找得到；
- **F05 的触发条件**：前端进入**多阶段推进**（骨架期 → 功能期），需要有"验证方法 + 证据 + 接续指南"
  的落点，否则每次交接都要重新问一遍"现在到哪了、怎么复现"。

两者与后端的 `B04` / `B05` 在**职责上呼应**，但**内容不平行**：前端没有表结构、迁移、连接池，
F05 的证据是 `typecheck` / `build` / 浏览器实测，而不是 SQL 与集成测试矩阵。

## 为什么不与后端文档一一对应

`F01–F03` 与 `B01–B03` 在**主题上呼应**（架构 / 数据 / 运行），但**内容并不平行**；`F04`/`F05` 与 `B04`/`B05` 同理：

- 后端有数据库、迁移、SQL、连接池；前端没有，所以 F02 是"类型与契约映射"，不是"schema"。
- 后端有配置优先级、启动校验、敏感值边界；前端的"配置"只是几个 `VITE_*`，所以 F03 更短。
- 后端有"必须规避的历史缺陷"（B01 §5，来自实际踩过的坑）；前端的 F01 §6 起初也只能从契约里**读出**容易做错的点——骨架期跑通后补进了三条**实测**才知道的坑（第 15–17 条）。

两端共用业务事实（S01）与接口约定（S02），但**实现路径各自独立**——这正是 `S` / `A` / `B` / `F` 四套编号分开的理由。
