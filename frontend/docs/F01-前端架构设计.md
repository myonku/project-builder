# 前端架构设计

## 1. 文档定位

本文档规定前端工程的**技术选型、目录结构、依赖方向**，以及**与后端 HTTP 契约的对接约定**。

业务范围以[《S01 需求文档》](../../docs/S01-需求文档.md)为准，HTTP 约定以[《S02 HTTP 接口契约》](../../docs/S02-HTTP接口契约.md)为准，逐接口字段以 [api/A01–A09](../../docs/api/README.md)为准。

文档全貌（四套编号各自独立，`F` = frontend）：

| 编号                    | 位置                                  | 内容                                                         |
| ----------------------- | ------------------------------------- | ------------------------------------------------------------ |
| S01 / S02               | `docs/`                             | 需求、HTTP 契约（前后端共用）                                |
| A01–A09                | `docs/api/`                         | 逐接口字段结构（前端为主）                                   |
| B01–B05                | `backend/docs/`                     | 服务端实现与过程记录                                         |
| **F01**（本文档） | `frontend/docs/`                    | **前端技术选型、目录结构、依赖方向、与契约的对接约定** |
| F02                     | `frontend/docs/F02-数据对象模型.md` | 前端 TypeScript 类型、端点映射、派生字段                     |
| F03                     | `frontend/docs/F03-运行与联调.md`   | 环境要求、`VITE_*` 变量、代理、联调顺序、同源部署          |

**本文档不写的东西**：组件 API、样式约定、页面细节——那些属于组件与状态约定，等页面铺开后另立文档。

## 2. 技术选型

### 2.1 核心选型

| 能力      | 选型                                           | 说明                                                                                    |
| --------- | ---------------------------------------------- | --------------------------------------------------------------------------------------- |
| 构建      | **Vite 8**                                | 冷启动快，`server.proxy` 与同源部署都只需少量配置                                       |
| 框架      | **React 19**                             | 函数组件 + Hooks；MUI 官方模板基于 React 19                                             |
| 语言      | **TypeScript 7**                         | 接口契约字段众多，类型能把"拼错字段名 → 422"挡在提交之前；注意 TS 7 **已移除 `baseUrl`**，路径别名写成 `"paths": { "@/*": ["./src/*"] }` |
| UI 组件库 | **MUI 9.5**（`@mui/material`）        | 官方模板生态最成熟的 React 组件库；中文文档完备                                         |
| UI 模板   | **CRUD Dashboard + Sign-in**（官方模板） | 直接复用官方模板的布局、表格、表单、登录页，见 §2.2                                    |
| 路由      | **React Router 8**                       | CRUD Dashboard 模板官方使用的路由方案（模板用的是 `react-router` 的 `create*Router` / `Outlet` / `Link` API，7 与 8 兼容） |
| 状态管理  | **Zustand 5**（或 React Context）         | **只放"窄状态"**：认证态、当前工作组、UI 偏好；业务数据不进全局 store（见 §4） |
| 表单      | **React Hook Form 7 + Zod 4**            | MUI 官方推荐组合；Zod 只做**结构校验**，语义判定交给后端（见 F02 §9）                 |
| HTTP      | **原生 `fetch` 封装**                  | Cookie 场景下`credentials: 'include'` 直接可用；错误信封与字段明细在一个函数里收敛    |
| 数据表格  | **`@mui/x-data-grid` 9**               | CRUD Dashboard 模板内置，服务端模式分页                                                 |
| 日期处理  | **dayjs + `@mui/x-date-pickers` 9**    | 与 MUI 日期组件同源；显示时格式化，回传时原样透传（见 §5.1、F02 §3）                   |
| 主题      | **MUI 默认主题 = Material Design 2**（`theme/AppTheme.tsx` 单文件） | **不采用**模板的定制主题层（Inter 字体 / 8px 圆角 / 自定义阴影 / 10 组组件覆盖）；全站统一 MD2 默认观感（见 §4.1、F04 D16） |
| 字号      | **MD2 阶梯上调一档**                       | body1 18px / body2 16px / h5 28px / h6 24px（见 §4.1、F04 D17）                        |
| 字体      | **`@fontsource/roboto`（latin / latin-ext 子集）** | MD2 默认字体栈就是 `Roboto`，自托管后零外网请求（见 F03 §5.3）；**不要**用不带子集的写法，那会多打进 50 个字体文件 |
| 甘特图    | **`frappe-gantt`（暂缓接入）**           | MIT、轻、API 简单；但它不带类型声明，骨架期没有真实拖拽交互可验证，因此**到甘特图功能开始时再安装**并补 `.d.ts`（F04 D3） |
| 测试      | **暂不做**                               | 见下方说明                                                                              |

### 2.2 官方模板的采用方式

MUI v9.5 官方在 `docs/data/material/getting-started/templates/` 下提供了多套免费模板，其中与本项目直接相关的两套：

**CRUD Dashboard**（`crud-dashboard/`）——项目的主体骨架：

- 提供响应式侧边栏布局、基于 `@mui/x-data-grid` 的服务器模式数据表格、带表单校验的增删改查页面；
- 内置 `useDialogs`（Promise 化对话框栈）与 `useNotifications`（Snackbar 通知）两套全局交互 Hook；
- 目录结构为“组件 + 上下文 + 数据 + Hook + 主题定制”分层，入口组件 `CrudDashboard.tsx` 负责路由与 Provider 组合；
- 官方使用方式：将 `crud-dashboard/` 目录复制到项目中，确保安装 `@mui/material`、`@mui/icons-material`、`@emotion/styled`、`@emotion/react`、`react-router`，然后导入并使用 `CrudDashboard` 组件。

**Sign-in**（`sign-in/`）——登录页：

- 提供完整的登录表单、表单校验、忘记密码弹窗、Google/Facebook 社交登录图标（本项目不需要，可删除）；
- 依赖 `shared-theme/` 主题层：`AppTheme.tsx`（ThemeProvider 封装）、`themePrimitives.ts`（调色板、字体、形状、阴影等设计令牌）、`ColorModeSelect`（亮/暗切换）；
- 官方使用方式：将 `sign-in` 和 `shared-theme` 两个目录复制到项目中，确保安装 `@mui/material`、`@mui/icons-material`、`@emotion/styled`、`@emotion/react`，然后导入 `SignIn` 组件。

**集成策略**：本项目将 `shared-theme/` 作为**全局主题层**放在 `src/theme/` 下，CRUD Dashboard 和 Sign-in 模板**共享同一个主题**。CRUD Dashboard 的布局与组件作为项目骨架，Sign-in 仅用于登录页，不引入社交登录。

**模板副本的存放**：四套模板（crud-dashboard / shared-theme / sign-in / sign-up）的原样副本放在 `frontend/.templates/` 并**随仓库入库**（自 2026-10-14 起，见该目录的 `README.md`）。按 §3.1 复制到 `src/` 后再改造，每个复制过来的文件头部都标了来源与改造说明，便于将来按对应关系表逐文件 diff 升级（见 F03 §5.2、F04 §4）。入库的理由：换机器或多人协作时不必再去官方仓库找同一份组件代码。

**放弃的方案及理由**：

- **Vue 3 + Element Plus**（原方案）：原生视觉风格无法满足需求，需更多自定义样式编辑。
- **Tailwind / UnoCSS**：与 MUI 的 `sx` 属性体系会互相打架，增加心智负担；自定义样式写 `sx` + `styled()` 即可。
- **Ant Design**：组件库质量高，但 MUI 的官方模板生态（CRUD Dashboard / Sign-in / Dashboard）是开箱即用的，更贴合“借用官方模板简化开发”的需求。
- **TanStack Query / SWR**：初版页面数量与数据复用度还不到非引不可的程度；如果后续出现明显的缓存新鲜度问题（版本协议会让缓存很快过期），再评估引入。

```text
  │                    │                     │                  │
  └────────────┬───────┴─────────────────────┘                  │
               ▼                                                ▼
            stores/（只放窄状态）                             types/
```

**规则（与后端 `B01` §4.3 同构）** ：

1. `api/` 只做 HTTP 与信封解包，**不加工字段**（尤其 `updated_at` 必须原样字符串返回）。
2. `types/` 只放类型，**不 import 任何运行时代码**。
3. `stores/` 只放跨页面共享的窄状态。业务数据**不进 store**。
   骨架期实际只有两个 store：`auth.ts`（当前用户 + 登录/登出）与 `ui.ts`（当前工作组 id）；
   **侧边栏展开态留在 `DashboardLayout` 的局部 state**——它没有跨页面消费者（F04 D8）。
4. `hooks/` 是可复用逻辑层，可以调用 `api/`，不直接操作 DOM。
5. `views/` 可以 import 上面任何一层；`components/` 只能 import `hooks/`、`api/`、`types/`。

**为什么业务数据不放 store**：项目/任务/计划视图都是“按 id、按筛选条件”取的数据。放进全局 store 会立刻出现“缓存新鲜度”问题——用户在 A 页面改了任务，B 页面 store 里的还是旧版本，`expected_updated_at` 提交必然 409。**推荐做法：视图层用 Hook 加载，局部保存**。等页面复杂到真的需要缓存复用，再评估 TanStack Query。

### 4.1 主题层的位置与"统一用 MD2"

`src/theme/` 是所有页面共享的 MUI 主题配置层。它**不依赖任何业务代码**，只被 `App.tsx` 在顶层包裹：

```tsx
// src/App.tsx
import AppTheme from '@/theme/AppTheme';

export default function App() {
  return (
    <AppTheme>
      <CssBaseline enableColorScheme />
      <NotificationsProvider>
        <DialogsProvider>
          <RouterProvider router={router} />
        </DialogsProvider>
      </NotificationsProvider>
    </AppTheme>
  );
}
```

**主题选型：MUI 默认主题，也就是 Material Design 2。** MUI 的默认主题本身就是 MD2
（`styles/createTypography.js` 的实现注释直接指向 `m2.material.io`，默认字体栈
`"Roboto", "Helvetica", "Arial", sans-serif`，圆角 4px、25 级标准阴影、标准组件形态）。
官方模板另外带了一套**文档站自己的定制风格**（`shared-theme/themePrimitives.ts`：Inter 字体、
8px 圆角、自定义阴影与调色板，外加 10 组组件覆盖）。本项目**不用那套定制风格**，
理由与代价见 F04 D16。

`src/theme/` 现在只有一个文件 `AppTheme.tsx`，它在 MD2 默认值之上只做两件事：

1. **打开亮/暗两套颜色方案**：`cssVariables: { colorSchemeSelector: 'data-mui-color-scheme' }`
   + `colorSchemes: { light: true, dark: true }`。MUI 把当前方案写到 `<html>` 的
   `data-mui-color-scheme` 属性上，顶栏的明暗切换（`layouts/ThemeSwitcher.tsx`）用
   `useColorScheme()` 改它，`theme.getColorSchemeSelector('dark')` 读它。
2. **把正文与控件字号上调一档**：MD2 的默认阶梯偏紧凑（body1 16px / body2 14px / caption 12px），
   内部工具以桌面端长时间阅读为主，统一放大一到两像素。完整对照表写在 `AppTheme.tsx` 的注释里。

**两条禁止**（F01 §6 第 13、18 条）：

- 组件里**不要**再写 `createTheme` 或改调色板——主题只在一个文件里创建；
- 页面里**不要**各自放大字号（`sx={{ fontSize: ... }}`、`<Typography fontSize>`），
  要调就改 `AppTheme.tsx` 的 `typographyScale`，否则字号会散落成几十处不一致的值。

**颜色模式只有一个入口**：顶栏的 `ThemeSwitcher`（图标切换亮/暗）。模板自带的
`ColorModeSelect`（System / Light / Dark 下拉）与 `ColorModeIconDropdown` 未采用，
因此 `System` 只作为初始默认值存在——需要让用户显式切回"跟随系统"时，再把下拉接回来
（F04 D21）。

### 4.2 为什么用 Zustand 而不是 Redux

认证态和 UI 偏好（侧边栏展开、当前工作组 id）是典型的窄状态——字段少、更新频率低、不需要中间件。Zustand 的 API 更简洁，且不强制 action/reducer 模式。如果团队已有 Redux 经验，也可以用 React Context + `useReducer` 替代，两者在这个规模下没有本质差别。

## 5. 与后端契约的对接约定

这一节是**前端能不能顺滑接住后端契约**的核心，先落这几个 Hook 再铺页面。

### 5.1 `updated_at` 只做“原样透传”

《S02》§2.6.2 明确：`updated_at` 带亚秒精度，客户端必须**原样回传**作为 `expected_updated_at`；截断到秒会让原子 CAS 必然失败。

**约定**：

- `utils/datetime.ts` 暴露三类函数（骨架期已实现）：
  - `formatForDisplay(iso, timeZone?, pattern?)` —— 展示用，按用户 `timezone` 格式化；
  - `passThrough(iso)` —— 直接返回原字符串，用于提交；
  - `formatNaturalDate` / `todayIn` / `naturalDateToDayjs` / `dayjsToNaturalDate` —— `YYYY-MM-DD` 自然日的边界转换。
- **组件里不允许**直接 `dayjs(x).format()` 后回传。所有版本字段经由 `useVersionedForm` 走。
- `start_date` / `end_date` 是 `YYYY-MM-DD` 自然日，**不要用 `Date` 对象**（时区会把日期带偏一天）。

### 5.2 API 客户端（`api/client.ts`）

`api/client.ts` 是**唯一**直接使用 `fetch` 的地方，承担五件事：

1. **Cookie**：`credentials: 'include'` 必须每请求带上——会话是 HttpOnly Cookie，前端读不到也不能读（《S02》§2.2）。
2. **信封解包**：成功响应统一解包 `{ data, pagination }`；`204` 返回 `undefined`。
3. **错误封装**：非 2xx 一律抛 `ApiError`，携带 `status` / `code` / `message` / `fields` / `requestId` / `retryAfterSeconds`；网络/代理不通归一为 `status: 0` + `code: 'network_error'`。
4. **限流**：`429` 时读取 `Retry-After`，写入 `ApiError.retryAfterSeconds`；**不做自动重试**。
5. **上传与下载**：`apiUpload`（`multipart/form-data`，字段名 `file`）与 `apiDownload`（取 `blob`，兼容"错误以 JSON 返回"）。

对外只暴露 `apiGet` / `apiPost` / `apiPatch` / `apiDelete` / `apiPostQuery` / `apiGetQuery` / `apiUpload` / `apiDownload` / `toApiError`。各域文件（`auth.ts` 等）只做"路径 + 类型"的拼装，**不加工字段**。

**`ApiError` 到 UI 的映射规则**（`useApiError`）：

| 状态码  | 处理                                                                                            |
| ------- | ----------------------------------------------------------------------------------------------- |
| `401` | 清`authStore` → 跳 `/login?redirect=<原路径>`                                              |
| `403` | 提示"权限不足"，**不要**当成"未登录"                                                      |
| `404` | 文案统一为"对象不存在或你没有访问权限"——`*_not_found` 同时代表不可见（《S02》§5 加强项） |
| `409` | 默认不弹提示，交给调用方分流：`version_conflict` / `duplicate_member` / `conflict`（归档只读等） |
| `422` | `applyApiFieldErrors` 把 `fields` 回填 React Hook Form 的字段级错误                            |
| `429` | 提示"请求过于频繁，请 N 秒后再试"                                                             |
| `5xx` | 提示服务端异常，并附上 `request_id`                                                           |

> **注意**：模板的 `useNotifications` **只有** `show(message, { severity })` 与 `close(key)`，
> 没有 `showError` / `showSuccess`。所有错误提示统一经 `useApiError().handle(error)`，
> 不要在页面里各写一份映射（F04 D6）。

### 5.3 `useVersionedForm`：版本协议

后端把 `expected_updated_at` 设为**必填**（《S02》§2.6），PATCH 类端点全部覆盖。统一的 Hook：

- `load()`：`GET` 拿到对象，缓存 `updated_at` **原字符串**；
- `save(patch)`：只提交用户实际修改的字段 + `expected_updated_at`（**由 Hook 注入，表单里不渲染这个字段**）；
- 收到 `409 version_conflict` 时**不自动重试、不静默合并**，弹窗让用户选：
  - **「放弃我的修改并刷新」** （重新 `load()`，返回 `resolution: 'reloaded'`）
  - **「保留我的修改」** （重新取一次服务端 `updated_at` 写入本地版本号，**不动**用户已输入的内容，返回 `resolution: 'kept'`，用户可再次提交）
- 冲突信息里带上 `request_id`（《S02》§2.4），便于排查；
- 返回值是判别式联合 `SaveOutcome`，调用方必须显式处理 `ok: false` 的三种 `resolution`。

### 5.4 `useListQuery`：`POST .../query` 统一状态机

后端有多个 `POST .../query`（Users / Groups / Projects / Tasks / Attachments / JoinRequests）。它们形状一致：`{ 筛选..., page, page_size, sort }`。用一个 Hook 收敛：

- **排序表达式语法**：`field` 升序、`-field` 降序、逗号分隔多字段；MUI `DataGrid` 的 `onSortModelChange` 事件映射到该表达式（`toSortExpression`）。**白名单要硬编码**（`sortWhitelist`），不能给用户任意输入（未知字段 400）。
- **筛选由页面自己维护**：Hook 只提供 `filters` / `setFilters` / `patchFilters`，**不透传 `DataGrid` 的 `filterModel`**——后端没有对应的表达式协议（F02 §2.1 第 4 条，F04 D7）。
- **筛选与排序变化都要重置到第 1 页**；`page` 的 0/1 基换算只在 Hook 内做一次。
- 初始 `page_size` 显式取后端默认值 **20**（不设的话 `DataGrid` 默认 100，打开列表就会打一条 `page_size=100`）。
- `rowCount` 直接取 `pagination.total`，**不要**用 `rows.length`。
- 额外依赖（如 `projectId`）通过 `deps` 传入，值变化时重新查询。

### 5.5 幂等

只有 `POST /tasks/{task_id}/copy` 用到 `Idempotency-Key`（《S02》§2.6.1）：

- 一次“用户点击复制”生成一个 key（`crypto.randomUUID()`）；
- 网络抖动重试**复用同一个 key**；
- 换一个任务复制时**换 key**。

### 5.6 文件上传与下载

- 上传：`multipart/form-data`，字段名固定为 `file`，单文件（《A07》）。用 MUI `Button` + 隐藏 `<input type="file">` 自定义上传，把 `413 / 415 / 409（配额）` 分别映射为可读提示。**配额满时提示“先彻底删除”** （逻辑删除不释放配额）。
- 下载：`GET /attachments/{id}/download` **不是 JSON 信封**，响应体是字节流。**不要**直接用 `<a href>`——错误会以 JSON 返回，浏览器表现为下载坏文件。推荐 `fetch` 取 `blob` 后 `URL.createObjectURL` 触发下载，这样能统一处理错误。

### 5.7 任务详情用 Drawer

决策：任务详情用 **Drawer** 而非路由页。任务单端点挂在 `/api/v1/tasks/{task_id}`（与项目无嵌套），且几乎总是从项目详情或计划视图点开：

- Drawer 用 `?taskId=xxx` 承载，关闭后回到原列表，筛选/滚动位置天然保留；
- 项目详情、个人计划、组内计划三处复用同一个 `TaskDetailDrawer.tsx`；
- 甘特图拖拽改日期不需要路由跳转；
- 如果日后需要“可分享链接”，再加一条 `/tasks/:taskId` 路由渲染同一个组件即可。

### 5.8 页面容器与面包屑

CRUD Dashboard 模板的 `PageContainer` 组件（标题 + 面包屑 + 操作区）直接复用。每个 view 的顶部用 `<PageContainer title="..." breadcrumbs={[...]} actions={...}>` 包裹，保证所有页面的头部结构一致。

### 5.9 列表页的标准结构（照 `ProjectListView` 抄）

后端有多个 `POST .../query`，它们的页面长得一模一样。第一个落地的列表页（项目列表）已经把结构定型，
后续用户列表 / 工作组列表 / 提醒 / 审计**照抄**即可，不要各写一套：

1. **筛选栏**：文本条件用"草稿 state + 查询按钮/回车"提交（避免每敲一个字打一次请求）；
   下拉与开关这类离散条件**立即生效**。任何筛选变化都走 `setFilters`，它会自动重置到第 1 页。
2. **请求体只放有值的字段**：空的 `name` / `group_id` / `status` 不要出现在 JSON 里
   （后端对未知或非法枚举会 400/422）；`page` / `page_size` 永远显式带上（`page_size` 用后端默认 20）。
3. **DataGrid 四件套**：`paginationMode` / `sortingMode` / `filterMode` 全 `"server"`，
   `rowCount={pagination.total}`，`getRowId={(row) => row.id}`。
4. **排序白名单写进页面**：只有《A0x》允许排序的字段设 `sortable: true`（其余 `sortable: false`），
   白名单常量与 `useListQuery` 的 `sortWhitelist` 用同一份。让用户点不出一个必然 400 的排序。
5. **列筛选关掉**：`disableColumnFilter`——筛选由页面维护，DataGrid 的 `filterModel` 不透传。
6. **数据区高度自己算**：`height: 'clamp(360px, calc(100dvh - 320px), 900px)'`。
   **不要**用 `flex: 1` 让内容撑开页面——20 行会把分页条推到屏幕外，用户就看不到"共 N 条"。
7. **证书 / 派生字段只展示**：`updated_at` 用 `formatForDisplay` 显示，`start_date`/`end_date` 用
   `formatNaturalDate` 原样显示；提交一律走 `useVersionedForm` 注入 `expected_updated_at`。
8. **路由懒加载**：列表页会引入 `@mui/x-data-grid`（约 490 kB），在 `router/index.tsx` 里用
   `page(() => import(...))` 包一层，别让它进入首屏包（F04 D23）。
   连概览页也懒加载：它引入的 `utils/datetime`（dayjs）实测约 91 kB（gzip），登录页用不到。

**详情页（"一个对象 + 它的子列表"）的补充约定**（照 `ProjectDetailView` 抄）：

- 主体对象用 `useVersionedForm` 加载（拿到 `updated_at` 供 PATCH 使用），子列表用 `useListQuery`；
- 页头的"编辑 / 归档"按钮按 `usePermission` 决定禁用，**归档项目一律禁用**（F01 §6 第 7 条）；
- **不可逆操作要二次确认**（归档没有反向端点，《A04》§端点 5）；
- 详情页的表格**不追求分页条常驻视口**（页面本身内容多、需要滚动），
  高度用 `clamp(320px, calc(100dvh - 520px), 620px)` 给一个合理区间即可；
- 子列表同样按白名单设 `sortable`、同样把次要列（如"开始日期 / 最近更新"）默认收进列菜单。
- **单元格里的悬浮提示统一走 `components/common/DataTooltip`**（`textCell()` 工厂 + `DataTooltip`）：白底 / 2px 黑边 / 无圆角，与 `TruncatedText` 共用同一份样式常量。写了 `renderCell` 才会去掉 DataGrid 自动加的原生 `title`（§6 第 34 条）；顶栏、对话框、普通按钮的提示仍用 MUI 默认外观，不做全局覆盖（F04 D33）。


### 5.10 计划视图的标准结构（个人计划 / 组内计划，F05 §7.2 第 4 步）

计划视图**不是列表页**：它是"一次拿到全部数据、按项目分组渲染"的只读视图（《A06》三个端点都不分页）。
照 `PersonalPlanView` / `GroupPlanView` 抄，下面 9 条是踩过之后定下来的：

1. **加载用一个专用钩子** `hooks/usePlanView.ts`：没有分页/排序状态机，只有"参数 → 一次 GET"，
   内部用 `AbortController` + 请求序号双保险丢弃过期响应；
2. **筛选的"空值"必须从查询串里消失**（空串、`false` 都不能发）：服务端对未知参数一律 `400`，
   `overdue=false` 与不带该参数等价、`include_archived` 默认就是 `false`——
   这份映射收在 `PlanFilters → buildPlanQuery` 一处，页面不自己拼查询串；
3. **项目下拉的选项来自"未按项目筛选"的那次响应**：一旦带上 `project_id`，响应里的 `projects`
   就只剩一个，拿它当选项会"选完就没了别的选项"。`usePlanView` 只在 `!query.project_id` 时更新选项；
4. **项目行是客户端合成的分组头**：服务端把项目与任务分成两个数组，层级只有任务侧的 `parent_id`；
   `planRows.ts` 把它们合成为"项目行 + 缩进的任务行"（同一父任务下保持服务端顺序，带环守卫）；
5. **不排序、不列筛选**：服务端已按 `end_date` / `start_date` 固定顺序，客户端重排会打乱分组，
   因此列一律 `sortable: false` + `disableColumnMenu`；次要列（成员、最近更新）默认收进列菜单；
6. **可编辑性直接用投影里的 `can_edit`**（服务端已按归档 / 组内只读共享算好）——
   不要用"我是不是项目成员"重新推断（§6 第 10 条）；
7. **任务行点击走 `?taskId=`**，与项目详情页复用同一个 `TaskDetailDrawer`（§5.7）；
8. **筛选区是一个独立区块**：`pb: 2` + `borderBottom: 1px`（一条分割线就够，不加背景色），
   内部固定三层——① 全部选择项；② 截止区间；③ 开关 + 查询/重置。**②③ 靠右**
   （`justifyContent: 'flex-end'`），因为它们通常占不满一行，靠右可以避免右侧留一大片空白。
   三层都用 `Box` + `display:flex + gap`，**不要用 `Stack` 的 `spacing`**（折行后左边缘会错位，见 §6 第 30 条）；
9. **第一层的项宽度可变**：每项 `flex: 1 1 0` + `minWidth`（按最长内容定）+ `maxWidth`（默认 `2 × minWidth`）。
   固定宽度会让每行右侧留下"随视口变化的空白"；可变宽度后：空间够 → 所有项在**同一行**等宽铺满；
   空间不够 → 折行且**每一行都被撑满**；`maxWidth` 只用来兜住"某行只剩一两项"的残行。
   间距**始终只有 `gap`**，三层完全一致——这也是不采用"可变间隔"方案的原因。
   第 8、9 两条已抽成 `components/common/filterLayout.ts`（`filterRowSx` / `filterItemSx`），
   项目列表、计划视图、提醒列表**共用同一份实现**——散在各页面里迟早会漂移。

> **组内计划的两处特有语义**：只含**已共享**的项目（`group_readonly` / `group_editable`）与
> **已共享**任务；`projects[].my_role` 为 `null` 表示"我不是项目成员，是通过组内共享看到的"，
> 界面上显示为"组内访客"而不是空白。
>
> **概览页复用同一套**（F05 §5.11）：`DashboardView` 不新增接口，直接用 `usePlanView({ groupId: null })`
> + `PlanSummaryTiles` + `TaskDetailDrawer`——卡片、待办任务、我的项目都来自
> `GET /plan-views/personal`，因此概览与计划视图**永远不会互相矛盾**。
> 登录后的落地页应当是"我该做什么"，而不是"这个系统连到了哪个后端"：身份与运行信息留在页面底部。
> **甘特图留到下一步**：`GET /plan-views/projects/{id}/gantt` 已实现（类型与 API 都在），
> 但可视化要先决定交互（时间尺度、拖拽改日期、折叠），本轮不做——见 F05 §7.2。


## 6. 必须规避的坑

下面这些是从契约里**读出来的**、一旦做错会非常难排查：

| #  | 坑                                                    | 正确做法                                                                                                                                                                    |
| -- | ----------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1  | 用 dayjs 格式化`updated_at` 后回传                  | 版本字段原样透传（§5.1）；`passThrough` 是唯一出口                                                                                                                       |
| 2  | 用`Date` 对象处理 `start_date` / `end_date`     | 只用`dayjs` 或字符串，避免时区偏移一天                                                                                                                                    |
| 3  | 全量提交（先 GET 再全量 PATCH）                       | 只发用户修改的字段；未知字段会被后端 422（《S02》§2.7）                                                                                                                    |
| 4  | 把`404` 渲染成“404 页面”                          | 统一文案为“不存在或不可见”（`*_not_found` 双语义，见《S02》§5）                                                                                                        |
| 5  | 把`403` 当作“未登录”                              | 明确区分：`401` = 未登录，`403` = 已登录但无权限 / 账号停用                                                                                                             |
| 6  | 业务数据进全局 store                                  | 视图层局部加载；只有认证态与 UI 偏好进 Zustand（§4）                                                                                                                       |
| 7  | 归档项目上仍然显示编辑/上传/删成员按钮                | 加载后立刻根据`status === 'archived' \|\| archived_at !== null` 计算 `isReadOnly`，提前禁用；否则用户会撞一堵 409 墙（《A04》§5）                                        |
| 8  | 用“我是不是任务成员”判断能否改任务                  | 能改的依据是**项目权限 + 任务是否共享**（《A05》权限速查）；任务成员的 `membership_role` 常常是 `null`                                                            |
| 9  | 展示“改为普通成员”按钮                              | 项目/任务域的`role: member` 永远不能成功（《A04》§8、《A05》§10 备注）；只展示“转移持有者”                                                                            |
| 10 | 用`can_manage_project === false` 推断“没有管理权” | 《A06》§3 备注：系统管理员若不是项目持有者，该字段为`false`，但实际可以管理。真正的判定依据是 `GET /projects/{id}` 的 `membership_role` + 当前用户的 `system_role` |
| 11 | 未知排序字段 / 筛选字段                               | 白名单硬编码；`useListQuery` 统一校验                                                                                                                                     |
| 12 | 甘特图拖拽后不处理`409`                             | `can_edit` 只是 UX 提示；拖拽后必须处理 `409`（归档只读）与 `403`（只读共享）                                                                                         |
| 13 | 在组件里直接写`createTheme`                         | 主题只在`src/theme/AppTheme.tsx` 一处创建；组件用 `useTheme()` 读取，不要各自建主题                                                                                     |
| 14 | 用`styled()` 覆盖 MUI 组件样式时忽略主题            | 优先用`sx` + `theme.palette` / `theme.spacing`；`styled()` 用于需要多次复用的样式化组件（如 Sign-in 模板的 `Card`、`SignInContainer`）                          |
| 15 | 在页面里自己写一遍"错误码 → 文案"                | 只有 `useApiError`（与 `describeApiError`）负责映射；模板的 `useNotifications` **没有** `showError`，不要假设它存在（F04 D6）                              |
| 16 | 直接改 `frontend/.templates/` 里的模板源码         | `.templates/` 是**上游原样副本**（已入库），生效的代码在 `src/`；改模板不会改变应用行为，还会让"来源可追溯"失效（下一轮升级覆盖时丢失）                    |
| 17 | 用 `@fontsource/roboto/400.css` 这种不分子集的写法 | 用 `latin-*` / `latin-ext-*` 子集；否则会把 cyrillic / greek / vietnamese / math / symbols 全部打进产物（实测多 50 个文件，F04 D12）                    |
| 18 | 在页面里各自放大字号 / 改主题色                     | 字号只在 `theme/AppTheme.tsx` 的 `typographyScale` 里调；页面里写 `fontSize`、`sx={{ color: '#...' }}` 会让字号与配色散落成几十处不一致的值（§4.1）        |
| 19 | 照抄 MUI v6/v7 时代的模板写法                      | v9 已把 `inputProps` / `primaryTypographyProps` / `InputProps` 等改成 **`slotProps`**（`slotProps={{ input: {...} }}`、`slotProps={{ typography: {...} }}`）；`typecheck` 会拦住旧写法（F04 D22） |
| 20 | 列表页让内容把页面撑开（`flex: 1`）                | 数据区用 `clamp(360px, calc(100dvh - 320px), 900px)` 自己滚；否则 20 行就把分页条推到屏幕外，"共 N 条"看不见（§5.9） |
| 21 | 把 `@mui/x-data-grid` 引进首屏包                    | 列表页走路由懒加载（`router/index.tsx` 的 `page(() => import(...))`）；表格库约 490 kB，登录页不需要它（F04 D23） |
| 22 | 在 DataGrid 的 `renderCell` 里返回**块级**元素      | 单元格靠 `line-height` 垂直居中，**只有行内内容**才被居中：默认的 `<Typography>` 是 `<p>`（块级），实测"逾期任务"列里的 `0` 比同行高 **13.6px**，而 `Chip`（`inline-flex`）正常。单元格里的纯文本一律用 `components/common/CellText.tsx`（渲染成 `<span>`），复杂布局自己写 `display:flex; alignItems:center; height:100%` |
| 23 | 把 `LocalizationProvider` 挂在 `App.tsx` 顶层       | 日期组件只在懒加载页面用得到，挂顶层会让**登录页首屏**多下载约 92 kB（gzip）。需要日期组件的子树自己包 `components/common/DateLocalizationProvider.tsx`（F04 D25） |
| 24 | 给"详情页"也套用列表页的分页条常驻规则             | 详情页内容多、本来就要滚动：表格高度用 `clamp(320px, calc(100dvh - 520px), 620px)`，**不要**为了把分页条顶进视口而把表格压到只剩两三行（§5.9） |
| 25 | 用 `{...register('x')}` 绑 MUI `Select`（`TextField select`） | **必须用 `Controller`**：`register` 不给 `value`，MUI Select 会先以"非受控"挂载，随后 `reset()` 写入默认值就变成"受控"，React 直接报 `A component is changing an uncontrolled input to be controlled`（实测在项目/任务表单里各出现一次）。`Controller` 从首帧就给 `field.value`，从根上避免 |
| 26 | 认为"换个父任务"只跟层级/环有关                         | 后端还会校验**日期区间覆盖**：子任务的 `start_date`/`end_date` 必须落在父任务区间内，否则 `422` 且错误挂在 `start_date` 字段上（实测：子 10-05~10-08、父 09-01~09-10 → 422）。父任务候选下拉**不预先过滤**（列表是分页的，前端算不准），靠 `applyApiFieldErrors` 把消息回填到字段 |
| 27 | dev server 卡住时去查应用代码                             | 新增依赖（如第一次 import `@mui/x-date-pickers/DatePicker`）后 Vite 可能**在依赖预构建上打转**：表现是**连 `/src/main.tsx` 都请求超时**（用 `Invoke-WebRequest` 打模块地址即可判定），页面白等、CDP `Runtime.evaluate` 也超时。处置：停掉 dev server → 删 `node_modules/.vite` → 重启（F03 §9） |
| 28 | 在 `renderCell` 里放"一行多个元素"的块级容器（如进度条 + 文字） | 块级容器**不会**被单元格的 `line-height` 居中：实测进度条与 `0%` 都贴到单元格顶部（比同行内容高约 13px）。要么用行内元素，要么给容器 `width: 100%; height: 100%; alignItems: center`——已封成 `components/common/ProgressCell.tsx`，照用即可（第 22 条是它的"纯文本版"） |
| 29 | 把 `truncatedText(...)` 再包一层 `<Typography>`            | `truncatedText` **自己就返回** `<Typography component="span">`，外层再包一层会让字号/颜色被外层覆盖（`caption` 里套 `body2`）。要改样式就传 `typographyProps`：`truncatedText(text, { typographyProps: { variant: 'caption' } })` |
| 30 | 用 `Stack direction="row" spacing={n}` 做**会折行**的工具条 | `Stack` 的 `spacing` 靠"容器负 margin + 子项正 margin"实现，一旦 `flexWrap` 折行，第二行起的左边缘会比第一行多缩进一个 margin（用户看到的"左边空了一块"）。**会折行的行一律用 `Box` + `display: flex; flexWrap: wrap; gap: n`**：`gap` 只作用在项目之间，每行都从容器左边缘开始 |
| 31 | 给会折行的工具条里的控件设**固定宽度** | 固定宽度会留下"随视口变化的右侧空白"，而且每行都补不齐。改用 `flex: 1 1 0` + `minWidth`（按内容定）+ `maxWidth`（兜住残行）：空间够时同行等宽铺满、不够时折行且每行仍铺满，间距始终只有 `gap`（§5.10 第 9 条）。**不要**用"可变间距"去补——那会让这一行和相邻行的间距不一致 |
| 32 | 给"没有该筛选参数的端点"硬加一个筛选下拉 | `GET /reminders` **没有 `status` 参数**（传了 `400`），但"只看失败"是真实需求。做法：**客户端过滤当前页 + 界面明说"只作用于当前页"**（`Alert` 里给出"本页 N 条里只有 M 条符合、总数仍是服务端的 X 条"），同时把 `status` 列设为可排序（在白名单里）用于归拢全部数据。**不要**静默过滤——用户会以为总数也变了 |
| 33 | 把**内联对象字面量**放进自定义 Hook 的 effect 依赖 | `usePlanView({ query: {} })` 这种写法每次渲染都产生新对象 → 依赖永远在变 → "请求 → setState → 重渲染 → 再请求"的**无限请求**（实测概览页 8 秒发出 **404 次** `GET /plan-views/personal`）。两条一起做：① hook 内部用**序列化值**（`JSON.stringify(query)`）当依赖，并用 ref 读最新参数；② 调用方传**模块级常量**而不是内联 `{}`。修好后同样 10 秒只有 3 次请求（其中 1 次是路由切换） |
| 34 | 以为"表格里的悬浮提示都是我们写的" | **MUI DataGrid 会自动给"没有 `renderCell`"的列加浏览器原生 `title`**（源码 `GridCell.mjs`：`if (children === undefined) { ...; title = valueString }`），那是原生提示框、**不受主题控制**，于是同一个应用里会同时存在"原生白底黑框"与"MUI 灰底圆角"两套观感。要统一只能**给列写 `renderCell`**（DataGrid 没有关闭它的开关）；另外空值与 `—` 也会弹框，是噪点 |
| 35 | 把**函数组件**直接放进 `<Tooltip>`（或只转 ref 不摊 props） | MUI 会给子元素注入 `onMouseOver` / `onFocus` / `aria-label` / `data-mui-internal-clone-element`，**子组件必须把这些 props 摊到"接了 ref 的同一个元素"上**；只 `forwardRef` 而不透传 props 时提示会**静默失效**（悬停无反应、DOM 里没有克隆标记），控制台只给一句 `The children component of the Tooltip is not forwarding its props correctly`。`CellText` 因此同时 `forwardRef` + `{...rest}` |

## 7. 变更规则

1. 新增域（新 API 文件）前必须明确：对应的 A0x 文档、请求/响应类型、错误码映射、缓存策略。
2. **契约变更的顺序是“先改 S02 → 再改 api/ → 最后改代码”** （见 `docs/README.md`）；前端类型定义与调用点必须跟着走。
3. 不引入未被使用的抽象层或依赖（与后端 `B01` §9.4 同规则）。
4. 新增第三方库必须在本节的技术选型表里登记，并说明“不用它会怎样”。
5. 从官方模板复制过来的文件，在文件头注释里标注来源（模板名 + 官方路径），便于后续对照升级。
