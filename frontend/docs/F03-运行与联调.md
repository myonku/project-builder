## 3. 环境变量

Vite 只把 `VITE_` 前缀的变量暴露给浏览器，因此**所有前端可见的配置都以 `VITE_` 开头**。

| 变量               | 默认值                | 说明                                                         |
| ------------------ | --------------------- | ------------------------------------------------------------ |
| `VITE_API_BASE`  | `/api/v1`           | API 前缀；**开发与生产都用相对路径**，靠同源或代理转发 |
| `VITE_APP_TITLE` | `项目/计划管理系统` | 浏览器标签标题                                               |

**约定**：

- **不要**放任何密钥、令牌、内部地址到 `VITE_*`——它们会打进构建产物。
- `.env.development` 与 `.env.production` **都入库**，因为不含敏感值。
- 如需本地覆盖，建 `.env.development.local`（`.gitignore` 忽略 `*.local`）。

```dotenv
# .env.development
VITE_API_BASE=/api/v1
VITE_APP_TITLE=项目/计划管理系统（开发）
```

```dotenv
# .env.production
VITE_API_BASE=/api/v1
VITE_APP_TITLE=项目/计划管理系统
```

## 4. 开发代理

开发期前端在 `5173`、后端在 `8000`。**用 Vite 代理把 `/api` 与 `/healthz` 转发到后端**，让浏览器眼里前后端**同源**——Cookie 天然带上，不用处理 CORS。

```ts
// vite.config.ts
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';

export default defineConfig({
  plugins: [react()],
  server: {
    port: 5173,
    proxy: {
      '/api':     { target: 'http://127.0.0.1:8000', changeOrigin: true },
      '/healthz': { target: 'http://127.0.0.1:8000', changeOrigin: true },
    },
  },
});
```

**为什么不用后端 CORS**：后端 `server.cors_allowed_origins` 的默认值是"本机 5173"（B03 §3.1），能打通；但**代理方案更省心**：

- 浏览器看到的始终是同一 origin，Cookie 的 `SameSite=Lax` 与 `Secure` 语义不引入额外变量；
- 生产是同源部署（见 §7），开发与生产的传输路径一致；
- 代理没有暴露 `*` 的风险。

如果因为调试原因需要绕过代理直连后端，把 `VITE_API_BASE` 设为 `http://127.0.0.1:8000/api/v1` 即可（此时前端需要 `credentials: 'include'`，后端 `cors_allowed_origins` 必须显式列出 `http://localhost:5173`）。

> **用 `http://localhost:5173` 访问，不要用 `127.0.0.1:5173`**：`vite.config.ts` 没有设 `server.host`，
> Vite 默认只绑 `localhost`，在 Windows 上本机表现为**只监听 `::1`（IPv6）**——
> 实测 `http://127.0.0.1:5173` 会连接被拒，而浏览器访问 `localhost` 正常（Happy Eyeballs 会选到 `::1`）。
> 需要按 IPv4 访问时显式启动：`pnpm dev --host 127.0.0.1`。

> **dev server 卡住时先别怀疑业务代码**：新引入依赖（例如第一次 `import '@mui/x-date-pickers/DatePicker'`）后，
> Vite 的依赖预构建有可能打转——症状是**连 `/src/main.tsx` 都请求超时**，页面一直白等，
> 浏览器调试协议里的 `Runtime.evaluate` 也会超时（主线程没在烧 CPU，所以看着像"页面卡死"）。
> 判定与处置：
>
> ```powershell
> # 判定：正常应在 100 ms 量级返回
> Invoke-WebRequest http://localhost:5173/src/main.tsx -TimeoutSec 10 -UseBasicParsing | Select-Object StatusCode
> # 处置
> Get-Process node | Where-Object { $_.CommandLine -match 'vite' } | Stop-Process -Force
> Remove-Item -Recurse -Force frontend/node_modules/.vite
> pnpm dev            # 或在 backend/ 下 pwsh -File ./scripts/dev-test-env.ps1 -WithFrontend
> ```

### 5.2 官方模板的获取方式

MUI 官方**不建议把模板作为 npm 依赖引入**，而是**从仓库复制源码到项目里**。理由：模板代码需要按项目改造（删社交登录、接自己的路由、接自己的 API），作为依赖会失去可控性。

**推荐做法**（保持可追溯）：

1. 从 MUI 仓库对应 tag（本项目的基准是 `v9.5.0`）下载下列目录到**临时目录**（不要直接往 `src/` 里拖）：

   - `docs/data/material/getting-started/templates/shared-theme/`
   - `docs/data/material/getting-started/templates/sign-in/`
   - `docs/data/material/getting-started/templates/crud-dashboard/`
2. 按 **F01 §3.1 的对应关系表**，把文件复制到 `src/` 下的目标位置。
3. 每个复制过来的文件**在文件头加注释**，标明来源（模板名 + 官方路径 + tag），例如：

   ```tsx
   // Source: MUI material-ui v9.5.0
   // Path: docs/data/material/getting-started/templates/crud-dashboard/components/DashboardLayout.tsx
   // Modified: 接入本项目路由与主题；删除官方 demo 的导航项
   ```
4. 后续升级 MUI 版本时，按同一张对应关系表逐文件 diff，而不是整体覆盖。

**不要做的事**：

- 不要为了"保持与官方一致"而保留模板里的 demo 数据（`data/` 目录下的假数据、假头像、假通知）；
- 不要把三个模板的 `shared-theme` 各自复制一份——**只保留 `src/theme/` 一处**；
- 不要在模板文件里直接 `import` 官方 demo 的 `data/` 目录（那会把你锁在模板的目录结构上）。

### 5.3 字体：内部网络的关键取舍

MUI 默认使用 **Roboto** 字体，官方模板从 **Google Fonts CDN** 引入（`index.html` 里的 `<link href="https://fonts.googleapis.com/...">`）。

**内部网络部署下这会出问题**：页面首屏会因为拉不到字体而回退到系统字体，观感不一致，且会产生对外请求（与"系统仅内部网络使用"的需求相悖）。

**决策：自托管 Roboto 字体**。具体做法：

1. 通过 `@fontsource/roboto` 引入（推荐）：

   ```bash
   pnpm add @fontsource/roboto
   ```

   然后在 `src/main.tsx` 顶部按需引入字重——**必须带子集前缀**：

   ```ts
   import '@fontsource/roboto/latin-300.css';
   import '@fontsource/roboto/latin-400.css';
   import '@fontsource/roboto/latin-500.css';
   import '@fontsource/roboto/latin-700.css';
   import '@fontsource/roboto/latin-ext-300.css';
   import '@fontsource/roboto/latin-ext-400.css';
   import '@fontsource/roboto/latin-ext-500.css';
   import '@fontsource/roboto/latin-ext-700.css';
   ```

   `@fontsource` 会把字体文件打进构建产物，运行时**零外网请求**。

   > **不要**写成 `@fontsource/roboto/400.css`：不带子集的写法会把 cyrillic / greek /
   > vietnamese / math / symbols 全部引入，实测产物里多出 **50 个字体文件**（约 500 KB）；
   > 带子集后是 16 个文件（约 280 KB）。见 F04 D12。
2. 从 `index.html` **删除**所有指向 `fonts.googleapis.com` / `fonts.gstatic.com` 的 `<link>`
   （骨架期的 `index.html` 里只有一条注释提醒，没有任何外链）。
3. **不需要**在主题里再声明字体族：MUI 默认主题（Material Design 2）的 `typography.fontFamily`
   就是 `'"Roboto", "Helvetica", "Arial", sans-serif'`，与 `@fontsource` 注册的族名一致
   （本项目已不使用模板的 `themePrimitives`，见 F04 D16）。

**实测确认**（浏览器里查 `document.fonts.check('16px Roboto')` 与 `getComputedStyle`）：

- 计算样式为 `Roboto, Helvetica, Arial, sans-serif`，`document.fonts.check('16px Roboto') === true`；
- 这一步同时修掉了一个**此前没被发现的问题**：模板的 `themePrimitives` 把 `fontFamily` 写成
  `Inter, sans-serif`，而项目里并没有引入 Inter —— 于是界面实际回退到浏览器默认无衬线字体，
  自托管的 Roboto 白装了。改用 MD2 默认主题后两者才对上。

**已知取舍**：Roboto **不含中文字形**，界面里的中文由系统字体栈回退渲染（Windows 上是微软雅黑）。
因此本系统的中文字体观感取决于客户端操作系统，这是"内部工具 + 不外网"前提下最省事的做法；
如果要求中文也用统一字体，需要额外自托管一套中文字体（体积以 MB 计），属于部署侧决策。

如果团队有既定的内部字体标准，也可以在这里替换为系统字体栈（`"-apple-system, BlinkMacSystemFont, 'Segoe UI', ..."`），代价是放弃 MUI 的默认观感。

## 6. 脚本命令

`package.json` 建议固定以下脚本：

| 命令               | 作用                                                                      |
| ------------------ | ------------------------------------------------------------------------- |
| `pnpm dev`       | 启动 Vite 开发服务器（`5173`），带 `/api` 代理                        |
| `pnpm build`     | `tsc -b && vite build`，类型检查 + 生产构建到 `dist/`                 |
| `pnpm preview`   | 本地预览`dist/`（**注意**：`preview` 不带代理，联调用 `dev`） |
| `pnpm typecheck` | `tsc --noEmit`，提交前与 CI 使用                                        |

**`build` 里带上 `tsc -b` 是有意的**：TypeScript 的类型错误不应该只在 IDE 里提示，构建时直接失败比上线后才发现要便宜。MUI 模板自带的 `.tsx` 文件也一并受此约束。

`tsconfig.json` 里把 `tsBuildInfoFile` 指到了 `./node_modules/.tmp/`，避免 `tsc -b` 在仓库根留下
`tsconfig.tsbuildinfo` 这种不该入库的中间产物。类型检查的严格度（骨架期已全部通过）：

- `strict` + `noUnusedLocals` + `noUnusedParameters`；
- `verbatimModuleSyntax: true`——**类型必须用 `import type` / `type` 修饰符导入**，
  这一条在复制官方模板时抓出了 20 处"类型当值导入"（F04 §4）；
- `noUncheckedSideEffectImports`（允许 `import './styles/index.css'` 这类副作用导入）；
- 别名 `@/*` → `src/*`。注意 **TS 7 已移除 `baseUrl`**，只能写 `"paths": { "@/*": ["./src/*"] }`
  （相对 tsconfig 解析），`vite.config.ts` 里用 `fileURLToPath(new URL('./src', import.meta.url))` 保持同一套别名。

**建议的默认做法**：初版**只装这四个脚本**，其余按需引入。理由与后端 B01 §9.4 一致——不为"未来可能需要"引入未被使用的工具链。

**明确不引入**（当前阶段）：

- 单元测试与 E2E（见 F01 §2 的测试处置）；
- ESLint / Prettier（团队如无固定习惯，先不引入；等代码成规模后一次性接入）；
- 提交钩子（husky / lint-staged）——等 lint 落地后再加。

## 7. 与后端联调的顺序

后端已经跑起来之后（参照 B03 §7.2 的 `make deps-up` / `make migrate-test-up` / `make run-test-config`），前端联调按这个顺序推进，**每一步都能单独验证**：

> **进度**：第 1–3 步已在骨架期验证通过（实测结果与截图见 [F05](./F05-进度与验证记录.md) §5）；
> 第 4 步的布局与响应式也已验证，但内容区仍是占位页；第 5 步起属于功能期。

1. **`pnpm dev` 起得来**：打开 `http://localhost:5173`，看到登录页（来自 Sign-in 模板，已删除社交登录）。
2. **主题生效**：右上角的 `ColorModeSelect` 能切换亮/暗模式；`shared-theme` 的调色板在两个模式下都不刺眼。
3. **登录链路**：`POST /auth/login` → `GET /auth/me` 能恢复登录态。这一步验证：Cookie、代理、401 处理。
4. **CRUD Dashboard 布局**：登录后进入 `/`，看到 Header + Sidebar + 内容区；三视口（`xs` / `md` / `lg`）下侧边栏响应式正确。
5. **列表 + 分页**：拉一次 `POST /projects/query`，绑定到 `DataGrid` 的 `paginationMode="server"`，验证：信封解包、分页、筛选、排序。
6. **版本协议**：`GET` 一个项目 → `PATCH` 改名 → 制造一次 409（同时用两个标签页改同一项目）→ 验证 `useDialogs` 的冲突弹窗。
7. **上传/下载**：上传一个附件 → 下载 → 逻辑删除 → 彻底删除。
8. **计划视图**：个人计划、组内计划、项目甘特图三个端点各拉一次。
9. **权限分支**：用一个非成员账号登录，验证 403 / 404 分支展示正常。

**踩坑提示**：

- 如果后端用 `make run-test-config` 启动，**集成测试会 TRUNCATE 业务表**（把引导管理员一并删掉）。跑完集成测试后要先**重启后端**再跑联调（B03 §7.2 的提示）。
- 后端限流默认是 3000/分钟（B03 §3.8），正常操作**不会**触发；如果为了复现 429 把 `RATELIMIT_BURST` 调小，记得改回来。
- 后端的引导管理员只在**服务启动时**初始化一次（B03 §3.6.1）；如果账号被误删或数据库被重建，需要重启后端让它重建。
- **MUI 的 `DataGrid` 默认在客户端分页**。接后端时**必须**设 `paginationMode="server"` + `rowCount`，否则会出现"后端返回 20 条、DataGrid 显示 1 页但 total 是 100"的假象。
- 官方 Sign-in 模板自带"记住我""忘记密码"等本项目**不实现**的入口。**处理方式（2026-10-14 起）**：
  入口保留，但做成**有反馈的占位**——点击弹出 Snackbar 说明现状与替代路径（注册 → 管理员建号；
  忘记密码 → 管理员重置）。F03 原先"直接删掉"的建议是为了避免"点了没反应"，
  而"点了给出明确说明"同样满足这个目标（F04 D18）。**不要**把这两个入口改成无反馈的死链。
- 登录页的"记住登录信息"**不是"延长登录"**：它只把用户名存进本机 `localStorage` 并在下次预填，
  同时用 `autoComplete` 示意浏览器可以保存表单。会话有效期由服务端 Cookie / Redis 决定
  （《S02》§2.2），后端也没有"记住我"这类语义。改这一块时不要顺手承诺"7 天免登录"。

## 8. 同源部署

**决策：前端与服务端同源部署。** 具体做法：

- 前端构建产物 `frontend/dist/` 是纯静态文件；
- 反向代理（Nginx / Caddy）把 `/api/v1/*` 与 `/healthz` 路由到后端进程，其余路径回落到 `index.html`（SPA 路由）；
- **不需要 CORS**：浏览器眼里只有一个 origin；
- **Cookie 的 `SameSite=Lax` 与 `Secure`** 按常规生效（生产环境 `security.secure_cookies = true`，见 B03 §3.6）。

Nginx 参考片段（按实际路径调整）：

```nginx
server {
    listen 443 ssl;
    server_name pb.internal.example.com;

    root /srv/project-builder/frontend/dist;
    index index.html;

    # API 与健康检查 → 后端进程
    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        # 注意：后端按"连接的来源地址"限流（B03 §3.8），不读 X-Forwarded-For。
        # 反向代理之后所有请求会落到同一个桶，这是刻意的取舍。
    }
    location = /healthz {
        proxy_pass http://127.0.0.1:8000;
    }

    # SPA 路由回落
    location / {
        try_files $uri $uri/ /index.html;
    }

    # index.html 不进长缓存；assets 带 hash 可长缓存（Vite 默认）
    location = /index.html {
        add_header Cache-Control "no-cache";
    }
    location /assets/ {
        add_header Cache-Control "public, max-age=31536000, immutable";
    }
}
```

**四点必须知道**：

1. **限流按来源地址分桶**（B03 §3.8）。反向代理之后所有请求会落到同一桶（等价于"全局一个桶"）。这是后端**刻意**的取舍，不是缺陷；如果将来确实需要按真实客户端 IP 计数，要先在反向代理层配置可信代理再改后端。
2. **不要配置 CORS 的 `*`**。同源部署下根本不需要 CORS；生产环境（`APP_ENV=production`）后端启动时也会拒绝 `cors_allowed_origins` 含 `*`（B03 §4.1）。
3. **字体已经在构建产物里**（§5.3），部署时不需要额外配 `fonts.gstatic.com` 的代理；`index.html` 里也不应该再有指向外网的 `<link>`。上线前用浏览器 Network 面板确认一次"首屏无外网请求"。
4. **静态资源的缓存**：`index.html` 应设 `Cache-Control: no-cache`；`assets/*.[hash].*` 可设长缓存（Vite 默认带 hash）。
5. **必须开启 gzip / brotli**：产物按路由拆成多个 chunk（登录页首屏约 244 kB、项目页约 444 kB 是**压缩后**的传输量），
   原始 JS 合计约 1.7 MB。不压缩会让内网首屏多下载数倍数据：

   ```nginx
   gzip on;
   gzip_comp_level 5;
   gzip_min_length 1024;
   gzip_types application/javascript text/css application/json image/svg+xml;
   ```
