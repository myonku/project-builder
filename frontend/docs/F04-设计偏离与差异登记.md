# 设计偏离与差异登记

## 1. 文档定位

本文档登记**前端工程在实现过程中对 `F01` / `F02` / `F03` 的偏离**，以及对官方模板文件的改造清单。

它记录的是"**为什么实际做法与文档写的不一样**"：

- 技术选型、目录结构、Hook 约定的**权威来源**仍是《F01》；
- TypeScript 类型与契约映射的**权威来源**仍是《F02》；
- 环境、代理、构建、部署的**权威来源**仍是《F03》；
- 本文档只做**偏离登记**；被采纳的偏离会**同步回写到上面三份文档**，因此这里保留的是
  "当时为什么这么定"的历史，而不是一份与主线脱节的另一套设计。

进度与验证证据在 [F05-进度与验证记录](./F05-进度与验证记录.md)；共用契约（`S02`、`api/`）的偏离
**不在这里登记**——那些属于契约本身，要按 `docs/README.md` 的顺序先改 `S02`、再改 `api/`。

## 2. 登记口径

什么算"偏离"，需要登记：

1. **与 F01/F02/F03 的明文描述不一致**（例如文档说 React Router 7，实际用 8）；
2. **对官方模板做了结构性改造**（例如把模板的哈希路由换成浏览器路由）；
3. **文档里没有、但实现必须补的东西**（例如 `utils/pagination.ts`）；
4. **契约里读出来、与文档表述不同的观察**（例如 `fields` 明细的实际语言）。

什么**不**登记：纯粹的 bug 修复、格式调整、数值微调——那些直接改文档即可。

编号 `D1`、`D2`……**只增不改**：后来被推翻的条目保留原文，并在"后续"列写明被哪一条取代。

## 3. 骨架期偏离与修订

骨架期的范围是"能跑起来"：工程配置、主题层、`api/` + `types/`、状态与守卫、布局、登录页、
各域占位页。功能实现（列表、表单、甘特图、上传下载）**不在**骨架期。

## 5. 与契约相关的观察

这些不是前端的选择，而是**实测到的契约行为**，记录下来避免后续误判：

| 编号 | 观察 | 出处 |
| --- | --- | --- |
| C1 | 错误信封的 `message` 是英文，但 `fields` 里的**明细文案是中文**（例如 `sort` 报"不支持的排序字段 …，可用字段：…"） | 实测 `POST /projects/query`、`GET /plan-views/personal?bogus=1`；因此 `applyApiFieldErrors` 可以把 `fields` 直接回填到表单，不需要再翻译 |
| C2 | `fields` 里会给出**可用值清单**（排序字段、查询参数名），前端白名单按《F02》§6 硬编码即可，但报错时可以直接展示服务端的清单 | 同上 |
| C3 | 未登录时 `POST /projects/query` 返回的是 `401 authentication_required`（会话网关先于端点），因此**前端不要把 401 当成"这个接口不存在"** | 实测；与《S02》§2.2 的两层校验一致 |
| C4 | 审计 `changes` 里的自由文本字段（如工作组的 `description`、项目的 `color`）值可能是固定的 `<由请求提供>`，不是请求正文；这是服务端为避免把描述类长文本写进记录而留的占位 | 实测 `PATCH /groups/{id}` 后 `GET /audit`；《A09》只写了"敏感键脱敏 / 单值截断 200"，未列出这个占位。前端原样展示，并在详情抽屉里解释，见 F05 §5.15 |
| C5 | `PATCH /groups/{id}` 的普通更新响应**不带调用者的成员关系投影**（`membership_role/status` 为 `null`）；携带 `owner_id` 的转移响应带的是**新所有者**的投影，不是调用者的 | 《A03》§4 备注已写明；前端若直接用响应覆盖本地组对象，系统管理员会被误显示成"非成员"（实测）。编辑/转移成功后必须再 `GET /groups/{id}`，见 F05 §5.17 |
| C6（2026-10-22 已修复） | 非项目可见者上传**项目附件**：`POST /projects/{id}/attachments` 实际返回 `404 attachment_not_found`；《A07》§端点 1 写的是 `404 project_not_found`，且上传处理顺序应"容器可见性（404）→ 写权限（403）" | 权限回归实测（`step9_join_user`）；前端把两种 404 都映射成"对象不存在或你没有访问权限"，用户界面无差异。属于后端错误码口径偏差，修复前不要依赖具体 code；见 F05 §5.20、§7.3 第 20 条 |

## 6. 变更规则

1. 出现偏离**先登记本文档**，再把被采纳的部分回写到 `F01`/`F02`/`F03` 对应章节；
2. 编号只增不改；被推翻的条目写"由 Dn 取代"而不是删除；
3. 涉及**契约字段或错误码**的偏离不在这里处理——那要先改 `docs/S02`，再改 `docs/api/`；
4. 新增第三方依赖必须同时更新《F01》§2.1 与《F03》§5.1，并写明"不用它会怎样"。

## D39：附件本地预览范围（2026-10-23）

采用 PDF.js（Apache-2.0）、Mammoth（BSD-2-Clause）、read-excel-file（MIT）及 fflate（MIT）。不采用依赖公网可访问文档 URL 的 Microsoft/Google iframe 预览；内部附件没有公开地址，现有授权下载可直接供浏览器解析。自建 LibreOffice 转换服务可以提供更完整 Office 排版，但需要额外运行服务、字体和转换队列，本轮不引入。

DOCX 首版只预览文字，XLSX 只预览保存的单元格值及工作表，不承诺 Office 排版、图片、图表、宏或公式重算。旧 DOC/XLS、PPT/PPTX、HTML/SVG 保留下载。PDF 采取 canvas，所有辅助资源本地托管；解析失败不影响下载。资源/时间/展示限制见 F01 文末及 S01 §4 附件要求；构建与复验见 F03 文末。
